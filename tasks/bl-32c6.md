release-plz pushes a NEW timestamped `release-plz-*` branch every time it
refreshes the release PR, and it pushes that branch BEFORE opening the PR. So
superseded branches pile up one per push to main, and if PR creation fails the
branch is stranded with no PR at all. brazen accumulated 25 orphaned
`release-plz-*` branches against a single ever-created PR for exactly this
reason. Those were deleted by hand and "Automatically delete head branches" is
now enabled on all five repos — but that setting only fires on MERGE, so it
covers the happy path and nothing else.

Add a `prune-release-branches` job to `.github/workflows/release-plz.yml` that
`needs: release-plz-pr` and deletes every `release-plz-*` branch with no open
PR. Because it runs right after the PR job, the current release PR is already
open, which makes "has no open PR" an exact test for "superseded or orphaned".
