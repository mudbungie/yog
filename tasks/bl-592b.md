CI run 29618275736 (first macos-14 job) failed 'make test' with 9 failures; linux green. Evidence from the job log:

1) git_tree::fd_probe::tests::detects_a_writer_holding_the_path and git_tree::lock_probe::tests::detects_a_holder_of_the_inbox_dir fail on macOS: the fake-/proc fixtures create fd symlinks pointing at the raw tempdir path, while the probes canonicalize their target before comparing. On macOS /tmp is a symlink to /private/tmp, so canonicalized target != raw symlink destination. Fix: canonicalize consistently on both sides (fixture and/or probe read_link comparison). Audit production comparisons for the same trap (fd_probe compares canonicalized target vs read_link of proc fd symlinks — on real macOS there is no /proc at all; a macOS probe backend is a separate design-epic concern, but the comparison discipline should be canonicalize-both).

2) Seven fs_watcher tests fail on macOS (coalesces_atomic_rename_to_destination, coalesces_rapid_writes_to_one_event, detects_goal_md_update_in_an_agent_worktree, detects_inbox_deposits_at_workspace_root, detects_removal_under_summary, detects_step_request_creation_at_conv_repo_root, detects_subagent_step_record_at_conv_repo_root): events never arrive within the test's wait budget, or arrive with /private-prefixed paths that fail equality against the /tmp-prefixed expectation. notify's macOS backend is FSEvents (higher latency, canonicalized paths). Fix shape: canonicalize the watch root at Watcher::new so emitted Change.path values and is_watched comparisons are stable across platforms, and give event-wait loops a platform-appropriate deadline (or poll-loop until deadline rather than fixed sleeps).

Acceptance: make test green on macos-14 in CI (the macos job), still green on linux, 100% coverage maintained. The runtime macOS lock/writer probe backends (no /proc on macOS) are OUT of scope here — this ball is about making the existing suite and path discipline portable.
