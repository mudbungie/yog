REMOTE §8.2 (bl-aaec) defines the client-side workspace: a directory
`<yog-data-root>/wire/workspaces/<leaf>/` holding `ca.pem`, `client.pem`,
`client.key`, `address`, and an OPTIONAL `workspace` file naming what the
workspace is called on its host (absent = the leaf). This ball lands the
reader and nothing else — no caller changes behavior yet.

What to build:

- `src/wire/entries.rs` (new module, wired in `src/wire.rs` beside
  `material`), tests in `src/wire/entries/tests.rs` following the tree's
  module-with-sibling-dir layout.
- Consts: `ENTRIES: &str = "workspaces"` (the subdir leaf under
  `material::DIR`) and `WORKSPACE: &str = "workspace"` (the name file).
- `pub(crate) struct Entry { pub leaf: String, pub workspace: String,
  pub channel: Result<Material, String> }` — owned, concrete (rule 2).
  `channel` carries the per-entry refusal so a half-provisioned entry is
  paintable by ITS consumers rather than failing the whole set (REMOTE
  §8.2: per-entry refusal, never the whole shell).
- `pub(crate) fn entries(world: &Env) -> Vec<Entry>`: readdir
  `material::dir(world).join(ENTRIES)`; a missing or unreadable dir is an
  empty vec (the general path with zero entries — this IS the migration
  story, REMOTE §8.2 'Migration: none'); sort by leaf for determinism.
  Per entry: `material::read_dir(dir, Role::Client)` — the entry's file
  shape IS the flat client shape, reuse it verbatim. `Ok(None)` (nothing
  provisioned) is a refusal HERE, not silence: an entry directory that
  exists names an intent. The `workspace` file is read trimmed; empty or
  absent means the leaf is the name.
- Amend `src/wire/material.rs`'s module doc (its 'address is one fact with
  one home' paragraph) to the §8.2 spelling: one address per relationship.

Non-goals: no consumer changes (`yog seat`, the window) — those are the
follow-on balls. Nothing writes an entry; provisioning is the operator's
out-of-channel act (§1.4).

Line cap: entries.rs projects well under 200 with tests in the sibling dir.
