Found by the §16.7 W14 clean-room drive (docs/drive-logs/2026-07-27-w14-cleanroom.md). This is the epic's one real hole and it is a DESIGN contradiction, not a bug in a line of code.

The empty balls section renders, verbatim (screenshot s0-04-transcript.png of the clean-room run):

    No projects yet — add one with: yog exec bl prime

STORIES S3-T5 / S8-3 call that the paved way to enter a project. But the embedded bl arm refuses it — `src/multiplex.rs` `bl::OUT_OF_SURFACE = ["prime", "sync", "install"]` (the W9 ruling) — with:

    yog bl: `prime` is outside the embedded balls surface — yog ships no
    bl-delivery/tracker sibling binaries beside itself, so it would run
    plugin-free (DESIGN §16.7 W9). Run a host bl inside the world instead,
    naming it by path so the world's own shim cannot shadow it:
        yog exec --cwd <project> /path/to/bl prime

exit 91; the next `yog exec bl create` then dies `bl: no balls checkout here — run \`bl prime\` first` (exit 1).

**The remediation is the premise S9/W14 deletes.** On a machine with only yog and git there is no host bl to name by path, so NO project can ever be primed into yog's world — which makes the whole S3 ball rung (claim, close, the balls section, S4's by-ball views) unreachable in the batteries world. Every prior green drive of that rung only worked because the un-seeded world/tools dir let PATH fall through to the operator's own `~/.local/bin/bl` (see bl-44a5): the paved path has never actually been walked by the batteries.

Root cause as the code states it: balls binds its sibling plugin binaries (`bl-delivery`, `tracker`) from `Edge::exe_dir` — under the multiplex that is yog's own dir, and yog ships no siblings — so a multiplexed `prime` would found a checkout with every default plugin pruned. 'Refusing is the honest surface until a plugin-binary seam exists.' W14 says the seam now has to exist.

Candidate shapes (pick by attacking them, do not just implement the first):
1. Multiplex the plugin binaries too: `yog bl-delivery …` / `yog tracker …` namespaces calling the balls crate's plugin entrypoints, with `world/tools/{bl-delivery,tracker}` shims seeded beside the other three, so `prime` binds absolute paths that are yog. Needs balls to expose those entrypoints as lib functions (check the pinned rev; may be an upstream ask).
2. Have yog found/converge the checkout itself through the balls library rather than through the `prime` verb — only if balls exposes a plugin-binding seam that takes paths.
3. Rule that projects enter by a different gesture entirely and retire the rendered `yog exec bl prime` string plus S3-T5/S8-3's wording.

Deliverables either way: the balls-section empty-state string must name a gesture that WORKS with only yog on PATH, DESIGN §16.4/§16.7 W9's ruling amended (its remediation sentence is now falsified by W14), STORIES S9 amended, and the clean-room `run-s3s4s6` green — that is the acceptance test: `scripts/drive/cleanroom.sh target/release/yog /tmp/w14 /tmp/out run-s3s4s6`.
