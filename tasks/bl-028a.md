REMOTE §8.2 (bl-aaec): the window's roster is the union of its channels'
workspaces. This ball lands the composition with N=1 (the loopback channel
only) so nothing repaints differently yet — the general path with one input.
The threads that make N>1 real are the next ball.

Needs bl-4e31 (the `with_workspace` rewrite lands there; this ball spends
it — same boundary surface, serialized on purpose).

What to build:

- `src/wire/channel.rs` (new): a `Channel` = a `Seat`, the leaf-to-host-
  name mapping, and the slice it feeds. The mapping is spent here in BOTH
  directions — questions encoded with the host's name, landed rows labelled
  with the leaf — §8.2's one-place rule (the `Snapshot::ws_name` discipline
  one layer down).
- **The slice.** Today `Engine::asker` feeds one `SnapshotCell`
  (`src/state.rs`). The per-channel cell map is a `state.rs` type — rule 7:
  Mutex/RwLock only there; append at the end of the file (CLAUDE.md rule 7
  records the llvm-cov phantom-line hazard around its impl headers).
- **The union.** The frame reads a composed view; workspace rows carry
  their channel origin (the entry leaf, or local). Name resolution over the
  union refuses a collision naming the token — REMOTE §8.2, the same
  sentence shape as §8's two-roots-one-leaf refusal — and the click-glue
  inverse (`Snapshot::ws_name`) resolves over the same union. Two
  directions, one mapping, nothing stored.
- The frame's standing set (`src/wire/link.rs`) becomes per-channel: same
  questions; which channel asks them is the channel's own fact. With one
  channel this is a refactor with byte-identical paint.

Tests: composition over a fake second slice (slices are values — no second
engine needed here); collision refusal; origin labelling. Any paint
assertion goes through `crate::paint_probe` (rules-audit: no hand-rolled
paint walk).

Line cap: pre-split `src/wire/channels.rs` (the set + union) from
`channel.rs` (the one channel) at design time.
