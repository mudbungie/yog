Premise verified against HEAD and it is DEAD — this was delivered in full by
bl-ebef (the litany =0.0.11 / brazen =0.0.17 pin), which landed the read, the
row, the wire and the edition together because the pin is what made the field
readable. Nothing is left to build. Evidence, all present on main at b35cfd83:

- `src/transcript/mod.rs` — `EntryKind::Delivered` carries
  `sender_name: Option<String>` BESIDE `sender`; the doc comment states the
  reason the id is not replaced (the id is the durable handle once the agent
  is deleted and the name recycled, and it is the only one of the two the
  filename can re-assert).
- `src/transcript/read.rs::classify` — `sender_name: deposit.from_name`, with
  `from_name:` named as the SECOND exception to the dropped-asserted-fields
  rule on `epitaph:`'s own reasoning.
- `src/inboxview/mod.rs` — `Deposit.from_name`, parsed by the one envelope
  parser; `src/inboxview/wire.rs` carries it on `reply/inbox`'s deposit too.
- Wire: `src/transcript/wire.rs` writes `sender_name` only when `Some`
  (absent, not null — `reply/enroll`'s `address` precedent);
  `src/transcript/wire/decode.rs` reads it with `opt_str_of`.
- Edition, not a bump: `corpus/shapes.json` stamps
  `/rows/[]/sender_name:string` and `/rows/[]/deposit/from_name:string` at
  edition 17, and the ledger paragraph is in
  `src/wire/hello/version/exact.rs`.
- Tests: `src/transcript/tests/vm.rs::a_delivered_row_carries_the_senders_name_beside_its_id`
  (present and absent), and the strict round trip at
  `src/boundary/reply/tests/roundtrip/surface/inspector.rs` carries a named
  child's row and a `user` row with no name. All green.
