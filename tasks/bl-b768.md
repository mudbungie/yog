Operator ask, verbatim: *"I want to have the logo in the top right of the app,
and while you have any conversation open, the main circle/eye will change
colors depending on what the agent is doing: green is nothing, blue is
inference, red is tool calls, purple is thinking, orange is waiting for the API
(nothing coming back yet). If the agent has subagents, I want each of their
statuses represented in the other balls, same color coding."*

The mark stops being decoration and becomes the fleet's telemetry: **one circle
per agent, hue = what that agent is doing right now.** The eye is the open
conversation's root; the nine node circles are its subagents in §2.3 descent
order.

## 1. The fact: per-agent `Doing` (§5.1 #28b)

A total five-variant enum, pure over one `Agent` snapshot row — no new disk
read, no stored flag:

| `Doing` | when | hue |
|---|---|---|
| `Inference` | state `InFlight` (#9) and the live `response.json`'s last content delta was a `text_delta` | SPECTRE (blue) |
| `Thinking` | state `InFlight` and the last content delta was a `thinking_delta` | GATE (violet/purple) |
| `Waiting` | state `InFlight` and **no** content delta has landed yet | BRAZEN (orange) |
| `Tools` | a running member holds a tool call whose `output.json` is absent (#10) | ICHOR (red) |
| `Idle` | everything else | HYDRA (green) |

**Priority is not re-decided here.** §5.1 #28's ruling stands — inference
before tools — so `Doing` resolves the `InFlight` substates first, then tools,
then idle. `Doing` *refines* #28: `Flight::Inference` ≡ any member in
{`Waiting`, `Thinking`, `Inference`}, `Flight::Tools` ≡ any member `Tools`.
`nav::convs::flight` is therefore rewritten as a **fold over `Doing`**, not a
second derivation — one authority for "is a model call streaming".

**Green is the mark at rest.** Hydra green is already the mark's own conductor
hue, so an idle fleet paints exactly today's logo. An *unfilled* seat (fewer
than nine subagents) is the same green — an absent agent and an idle one both
say "nothing happening", so the empty case is the general path, not a branch.

## 2. The new snapshot fact: the last content delta

`Agent` gains one field, filled at enumerate time like every other disk fact
(bl-cad5's rule — the render path never reads disk):

    /// The kind of the last content delta in the latest step's live
    /// `response.json`. `None` = the stream has opened but nothing has come
    /// back yet, which is exactly `Doing::Waiting`.
    pub last_delta: Option<Delta>   // Delta::{Text, Thinking}

`streaming.rs` already reads those bytes for `streaming_text`. It must not read
them twice: `streaming_text_from_disk` becomes **one fold yielding both**
(`Stream { text, last_delta }`), so the two facts cannot skew across a
mid-write file and the per-agent per-tick syscall count is unchanged.

Consulted only under state `InFlight`; a settled step's trailing delta is never
read, so no expiry rule is needed.

## 3. The mark: a third emission of the one `Shape` walk

`theme::icon` today emits its `Shape` list two ways (raster for the window
icon, SVG for `assets/yog.svg`) and DESIGN §11 is explicit that they are *the
same picture, not two approximations*. This adds a third — an egui painter
walk — under that same rule:

- `icon::mark()` becomes `icon::mark_with(&Tints)`, with `mark()` =
  `mark_with(&Tints::rest())`. The knowledge of **which disc is which** stays
  inside the one walk; nothing outside indexes the shape list.
- `Tints { eye: Color32, nodes: [Color32; 9] }` — nine because `ARMS * CIRCLES`
  is nine, derived, not restated.
- `icon/paint.rs` walks `mark_with` onto an `egui::Painter` in a rect. Flat
  fills only, so the painted mark and the rasterized icon stay one picture.
- The `mark_texture` cache is **deleted**: the painter is the one in-app
  rendering, and a vector walk at ~28 pt is crisper than a downscaled 64 px
  texture. `icon::rgba` stays — the window icon still needs it.

The traces keep the conductor hue always; only the ten discs take a tint.

## 4. Seat, and the words the colours owe

Top right, at the far edge, with the workspace tab bar shifting left of it
(§11 altitude 0 amended). The top-left keeps the attention strip + `⏭ next`.

**A hue may not be a fact's only carrier** (§11 glyph doctrine). The mark
hovers a worded roster — one line per lit seat: the agent's §3.3 display name
and what it is doing, from a `theme::doing_badge` mapping total over the enum
(hue + words in one home, like every other badge). The roster is also where
overflow is stated outright rather than silently dropped: with more than nine
subagents the hover says *"9 of N subagents shown"*.

## 5. Repaint

No pulse — solid hues; the ask was colour, not animation. The mark requests a
repaint only while some seat is off-rest, so an idle window still schedules
nothing (§7.2).
