Operator rulings from the 2026-08-02 multi-agent UX discussion:

1. **Two-edge taxonomy.** An agent's graph edges are two distinct facts, never conflated:
   - *Context edge* (what the child inherited) = git ancestry. Render **solid**.
   - *Provenance edge* (who dispatched it) = the descent id + the parent-transcript notch where the dispatch landed. Render **dashed**, drawn from the dispatch notch.
   A clean child (dispatch --from config/<name>, shipped in lernie bl-a693) has provenance only — no ancestry edge to its parent. "Clean vs fork" is one spawn gesture with one parameter (the fork point), per lernie ARCHITECTURE §2.3 "Any ref is a legal fork point"; V1 must render both edge kinds, not just ancestry.

2. **Child card at the dispatch notch.** V1.3 ("Descent edges render on the rail: a notch where a dispatch landed links to the child's branch") grows a live inline card: name, fork-point label ("from here" / "from config/default" / "from <Name>@<notch>"), state chip, spend figure, and a **streaming tail** — the last line or two of the child's in-flight inference text. Grounding is VISION §4.9 verbatim: "lernie streams every model event into the step record as it arrives … watching an agent is reading files yog already derives from (the in-flight strip, bl-905f)." The tail is a second consumer of that same derivation pointed at the child's agent id. Moving text = active; still = tool-wait or quiescent. Operator: "Show the user that the agent is active, not idle."

3. **Derive, never push.** The card updates via fs_watcher on the workspace repo + off-thread snapshot read, like every other I1 derivation. Frame renders snapshots only (UI/backend isolation). No new verb, no new transport — this all stays inside V1.4's "pure read of the lernie workspace repo … derivation and rendering only."

4. **Fan group anchor.** V2.3's sibling group renders anchored at the birth notch (one card, N columns) — note this in V1's rail spec so the anchor exists when V2 lands.

5. **Spend on the card** is the per-agent fold of steps/<id> (workspace-root, id-namespaced — no double counting; a fork's shared prefix cost stays with the ancestor). Subtree rollup is a descent-id prefix match, no registry.
