Round 1, lane comparator.

What the suite already has, and it is the best of the four. Verified against a
live engine: `/steps` returns `tokens{cache_read, cache_write, input, output,
total}` per STEP; `/agent` returns the same rolled up per conversation with an
`attribution` count; `/rail` carries a `budget` per operable commit;
`/workspace-balls` is documented as "the balls one workspace holds, with what
each has cost"; `/science` is "every delivery attempt of this workspace, with
what it cost and how it ended". Nothing else on this matrix can attribute spend
to a TASK rather than to a session — codex and Claude Code both answer only per
session, and hermes only per session plus a kanban `task_runs` row.

What is missing is the last multiplication. Every one of those numbers is a
token count. The unit the operator manages is money, and the suite never names
it.

The comparators:

- Claude Code: `--max-budget-usd <amount>` — "Maximum dollar amount to spend on
  API calls (only works with --print)". A hard ceiling, not a report.
- hermes: `estimated_cost_usd` and `actual_cost_usd` are DB columns per session,
  carried with `cost_status` ∈ {actual, estimated, included, unknown} and
  `cost_source` ∈ {provider_cost_api, provider_generation_api,
  provider_models_api, official_docs_snapshot, user_override, custom_contract,
  none}. The honesty of that pair is the interesting part: it never claims a
  figure is real when it was derived from a docs snapshot.
- codex: `/usage` reads account usage; no per-run figure.

Proposed shape, and the layer law decides where it goes. litany "computes,
scales, and estimates nothing — only provider-reported counters are recorded"
(litany ARCH §2.3 *Recorded, never computed*), and that is right: a price table
is not the engine`s fact. But it is not nothing`s fact either, and the one
component that already holds a per-workspace provider table with each row`s
credential state is the WALL — i.e. brazen config, read by yog. So: a price per
(provider row, model id) as wall config, a fold in yog that multiplies the
counters it already displays, and a cost column beside the token column in
`/workspace-balls` and `/science`. Nothing new is measured; one existing number
is multiplied by one configured number.

Carry hermes` honesty with it. A figure derived from a hand-maintained price
table is `estimated`, and the row should say so rather than printing a
confident number — the same posture yog`s own docs take about the leak gate
being "prevention is local and bypassable".

A ceiling is the second rung and should wait for the first: once a cost exists,
`/fan` and `/fleet` are the two gestures that want one, and litany`s whole-tree
budget mechanism (`max_total_tokens`) is already the enforcement point — see the
sibling ball filed against litany about nothing shipping bounded.

Filed p4: a comparator gap on the surface the suite is otherwise strongest at.
