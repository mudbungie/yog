`Query::Workspaces` answers a `pinned` rank per row (§4.1, bl-296f) and
`boundary/reply/ws_row.rs` states in as many words that a pin is durable
operator state rather than a viewport fold. Nothing writes it.

The only writer was `AppModel::toggle_pin`, an in-process method the window's
tab strip called, which resolved the §3.1 name to a path and flipped
membership in `ui.json`'s `pinned` list. bl-7942 removed it with the window.
The read half is untouched, so a seat can render a pin rank forever and no seat
can create one.

This was already a REMOTE §1.2 violation before the severance — a remote seat
had no way to pin either, because the act never crossed the boundary — so the
severance exposed it rather than causing it. The seen watermark is the shape to
copy: `Action::MarkSeen` writes `ui.json` through the dispatch chokepoint, and
the pin wants the same arm.

What the act has to carry, and the one decision in it: pins are keyed by
**path** in the document and addressed by **name** on the wire, so the
name→path resolution (`Snapshot::ws_path`) belongs at the chokepoint, once, the
way `toggle_pin` did it at the click. A toggle or an explicit set is the other
question — a toggle is one word and races two seats, a set is idempotent and
says what it means.

Witness that it is unreachable: `tests/integration/stories_s4_t7.rs` now writes
`ui.json` by hand and boots a second model to read the pin back, because there
is no gesture to fire.
