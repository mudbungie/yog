Three tests bind `wire::provision::PORT` — the one compiled-in default — rather than an ephemeral port, so they fail with `Address already in use` on any box where a `yog` window (or `yog serve`) is up. That is the normal state of a development box, and it reddens the close gate for every unrelated ball: the failures name the wire even when the change is nowhere near it.

The three, all fresh-world tests that found their own world under a tempdir and then reach for the ONE port anyway:

- `wire::tests::an_unprovisioned_box_founds_its_own_loopback_wire`
- `engine::tests::a_booted_engine_hands_its_window_a_seat_on_its_own_wire`
- `engine::tests::a_window_takes_both_halves_of_the_wire_once`

Seen while closing bl-a33d, which touched nothing wire-shaped: 2414 of 2417 passed, and the three failures were these. The speculative build on the runner passes them because a runner has no window up — so the defect is invisible exactly where the gate is green, and blocking exactly where an operator works.

The fix is a testability one, not a product one: a test world already isolates every other durable (`LERNIE_HOME`, `XDG_STATE_HOME`, the names root), and the listen address is the one fact it does not isolate. Either let the world carry the address the way it carries every other root — port 0 in a test world, resolved back off `listener.address()`, which two of the three already read — or have `listen` take the address from the world rather than from a const. Prefer the first: the const stays the deployed default and the world stays the one place a test says "not the real one". Do not fix it by serializing the suite on a lock, and do not fix it by skipping the tests when the port is busy — a test that passes by not running is the shape `beat-audit` exists to refuse.

Verify against the tree; this body cites what was true when it was filed.
