The provider catalog offers `claude-code`, and `/model worker claude-code sonnet` succeeds. The next worker start fails before any network call.

`/steps` reports `framing:"failed"`. The step error is:

`{"type":"error","kind":"parse_input","message":"claude_code carries no tool declarations; use the \`anthropic\` row for tools","provider_detail":null}`

Yog always supplies its worker tool declarations, so this accepted provider-role mapping cannot produce a worker turn. Retrying or changing credentials cannot alter the request-shape mismatch.

Expected: capability validation rejects this mapping when `/model` is set, with the structural reason, or the provider is omitted from roles whose requests require tools. A successful configuration command must not select a deterministically unusable execution path.
