## What yog does today

`Write::Pick` / `Write::Tune` (`src/boundary/config/write.rs`) → `boundary::config::pick_model` / `tune` → `commit(… BRANCH="default" …)` → `litany config <ws> default`, advancing `providers.yaml` on the lineage every chat follows. `/model <role> <provider> <model>` (`src/boundary/line/config.rs`) and the `model`/`effort`/`priority` envelopes (`src/boundary/codec/config.rs`) carry only a workspace. `roles` (`boundary::config::roles`) reads `config/default`'s tip. The §11 model row (`model_pick/header.rs`) shows the tip's pair, with a clause only when the chat does not resolve the workspace lineage.

## The change

1. **Wire (REMOTE §9.4/§9.13 amended first).** `model`, `effort`, `priority` and `roles` gain an optional `agent`. Absent = today's meaning, the workspace default — so this is an **edition**, not a major (§3.2: an absent post-floor key reads as the fact before it existed). Corpus regenerates with the new path stamped.
2. **Carrier.** `Write::Pick` and `Tuning::{Effort,Priority}` gain `agent: Option<String>`; `Read` for `roles` likewise. Codec decodes `agent` with `str_of`-optional; the line reader gives `/model` the seat's selected conversation when there is one (as `/retarget` and `/seen` take theirs from `Context`) — decide whether the slash spelling needs an explicit `--workspace` escape, or whether a conversation-less seat is how one says "the default".
3. **Executor.** `pick_model`/`tune` with an agent drive `litany model <ws> <agent> …` via `actions::verbs` (piped like `retarget`, for the same reason: refusals come back in litany's words). Without an agent, unchanged. The brazen provider-row gate (`model_pick::plan`) still runs in both cases — a dead row is a dead row whichever scope writes it.
4. **Read-back.** `roles` with `agent` reports the overlaid assignment and *where it came from* (mark vs lineage), so a seat can paint "this chat: X (pinned)" against "workspace: Y". The §11 model row shows the chat's binding and gains the apart clause when a mark is standing, with the clear as its exit (the shape `RETARGET_EXIT` already has).
5. **Help/notes.** `WRITE_NOTE` and the §9.4 scope sentence ("this moves the workspace default too") split into the two scopes.
