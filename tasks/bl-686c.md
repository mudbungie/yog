`yog wire-certs WIRE_LEAF=<name>` closes by telling the operator where the
material goes. `src/wire/provision/verb.rs`:

    "  carry those and {} to that box by hand, into its {DIR}/{ENTRIES}/<leaf>/ as \
     {client}.pem, {client}.key and {ANCHORS}, beside an {ADDRESS} you state; the common \
     name inside, not the basename, is the identity",

so an operator is told to file it under `wire/workspaces/<leaf>/`.
`src/wire/material.rs:48` carries the same claim in prose: *"`wire/workspaces/<leaf>/`
(REMOTE §8.2)"*.

**The consumer keys that directory on the WORKSPACE, not the leaf.** The seat
holds one channel per directory under `wire/workspaces/`, and a gesture is
routed by the workspace it names — `lernie conversations <workspace>` looks for
a directory of that name. So a directory named for the leaf is a channel no
gesture can ever address.

Followed literally with a leaf issued under one name, for an engine holding a
workspace under another, the seat reports:

    (this box's own engine)
        nothing provisioned at …/lernie/wire
    <leaf-name>
        <the address that was stated>

— the material is listed, under a name nothing routes to — and the gesture for
the workspace that does exist then fails:

    no wire provisioned at …/lernie/wire: the pair is minted on the host that
    issued it (`yog wire-certs WIRE_LEAF=<name>` there) and carried here by
    hand; the seat mints nothing

**The second half is the worse half.** The material is present, valid and
correctly permissioned; the only thing wrong is the directory's name. The
refusal instead says nothing is provisioned and tells the operator to go mint
another pair — sending them back to the CA to re-issue a leaf that was never
the problem. An operator who follows the mint's instruction is then told by
the seat to do the one thing that cannot help.

The same material moved to a directory named for the workspace works on the
first try, unchanged.

Two fixes, and both are wanted:

- **The instruction should say `<workspace>`**, in the printed sentence and in
  `material.rs`'s doc line. The comment above the `println!` says it is
  *"spelled from the reader's own constants, so the instruction and the
  directory a client files it into cannot drift"* — but `<leaf>` is a literal
  in the format string, and it is exactly the token that drifted. If the
  intent is that the constants carry it, the placeholder belongs in a constant
  too.
- **The seat's refusal should distinguish "no material here" from "material
  filed under a name I do not route to."** It has the entry list in hand — it
  printed it — so a channel present under an unrouted name is a fact it can
  state, with the rename as the remedy, instead of naming the mint.

Found by following the mint's own closing sentence literally while
provisioning a new device.

---

The seat-side half — a refusal that names the mint when the real fault is a directory name — is filed in lernie's store as bl-d574. This ball's own scope is the printed instruction and material.rs's doc line.
