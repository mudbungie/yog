OPERATOR RULING (2026-09-03): release PRs auto-merge on green CI. Two facts shape the mechanism, both verified on lernie 2026-09-02 and to be re-verified here: (1) a PR opened by the Actions bot token triggers no pull_request workflows, so the release PR itself never carries checks — native GitHub auto-merge has nothing to wait on and branch protection on main would break bl close's direct pushes, so both are the wrong tools; (2) the Release-plz workflow already gates the release job on the CI job POST-merge — a red CI on the merge commit skips the publish (observed live: lernie run 33611717922), so merging the bot PR is safe: the version bump lands but nothing ships unless CI is green.

Mechanism: a small workflow (or a job in release-plz.yml) that, when a release-plz PR exists, merges it — e.g. triggered on the Release-plz workflow's completion, finding open PRs from release-plz-* head branches and merging via gh with the repo GITHUB_TOKEN (confirm the token may merge; if not, the remedy is a named operator act, recorded). Guard: merge only PRs whose head branch matches the release-plz pattern and whose author is the Actions bot — never a human's PR. Note the standing ban: nothing this workflow writes into PR bodies or comments may carry a session URL.

Verify against this repo's actual workflow topology first — yog's ci.yml is a separate workflow from release-plz.yml (unlike lernie, where CI is a job inside the Release-plz workflow); the release gating relationship must be confirmed here, not assumed from lernie.
