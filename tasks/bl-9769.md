## words.txt is already curated and landed (bl-ccf7) — do not regenerate it

`src/names/words.txt` ships from bl-ccf7. Source + license + curation recipe are
in its 27-line `#` header (the header IS the CC BY 4.0 attribution and must ride
into the binary via include_str!, so do not strip it).

Constraints mod.rs may rely on and MUST NOT weaken:

1. **Parse rule.** Skip lines that are empty or start with `#`. Everything else
   is one word. (This is the only parsing mod.rs needs.)
2. **Charset.** Every word matches `^[a-z]{3,9}$`. Therefore `<word>-<word>` is
   path-safe on every supported filesystem, shell-safe unquoted, and
   case-unambiguous — which matters because the name is BOTH the workspace dir
   leaf and the `bl claim --as` value (§3.2).
3. **No human-identity collision.** No word is a given name, a surname, or the
   literal `unknown`. bl performs ZERO validation on `--as` (verified, bl-ccf7),
   and its identity fallbacks are `$USER` then literal `unknown`, so this
   property is yogs to hold, not bls.
4. **Pool size.** 7395 words => 54,678,630 ordered pairs. The pool-exhaustion
   error path is therefore unreachable in practice but still must exist and be
   tested — inject a tiny wordlist in the test, do not gate it on the real file.
5. **Ordered pairs, two distinct words.** `a-b` != `b-a`; forbid `a-a` (a name
   like `gecko-gecko` reads as a bug). Pool math above assumes both.

Assert 1-3 in a test over the real embedded file (cheap, and it pins the
artifact against a careless future edit).
