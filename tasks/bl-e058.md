## Symptom

A yog booted on a box it provisioned itself listens on a port **nobody can
learn**, so no seat can dial it and no device can be enrolled onto it.

Walked on a fresh scratch world:

1. Bare `yog` boots. `<data-root>/wire/address` reads `127.0.0.1:0`, which
   `provision::ensure` minted (correct — bl-dc14's ruling: an implicit mint
   must not take a process-global number).
2. The listener binds the kernel's answer. `ss` shows it on an ephemeral port.
3. **stdout and stderr are empty.** The boot says nothing on success; the only
   line it ever prints about the wire is the `yog: wire: bind …` *failure*.
4. `address` still reads `127.0.0.1:0`. Nothing writes the bound answer back,
   and `Listener::address()` — which exists and returns exactly it — has no
   consumer outside tests.
5. `/enroll <name>` refuses, correctly and in its own words:

   > `127.0.0.1:0` names no port a device can dial: a `:0` is a request the
   > listener answers in RAM, and its answer changes at every boot.

## The consumer that was told in RAM has left

REMOTE §8 is explicit about who the answer was for:

> The `:0` in the file is a **request** … what it *became* is runtime, held by
> the listener and handed to the one seat that needs it — the window, in RAM.

and, on the same page:

> A seat is a separate program now and reads the address the way every other
> seat does — the operator states it, or a local one is told the bound port by
> the operator.

bl-7942 deleted the window. The in-process consumer that made a `:0` workable
is gone, and the sentence that replaced it — *"a local one is told the bound
port by the operator"* — has no mechanism behind it: the operator is told
nothing. On a self-provisioned box the bound port is knowable only by asking
the kernel about the process (`ss`, `lsof`), which is not an interface.

## What an operator actually has to do

State an address and reboot the engine: write `<host>:<port>` into
`<data-root>/wire/address` by hand, or mint with
`WIRE_HOST=… WIRE_PORT=… yog wire-certs` on a directory with no material yet.
Neither is discoverable from anything the engine says, and the second refuses
on a box the boot already provisioned (rotation guard, correctly).

## Repro

    XDG_DATA_HOME=<scratch> yog &          # bare boot, fresh world
    cat <scratch>/yog/wire/address         # 127.0.0.1:0
    # engine stdout+stderr: empty
    yog gesture --ws <ws> '/enroll laptop' # refuses: ":0 names no port…"

Then, having stated a port in `address` and rebooted, `/enroll` answers in full
— anchors, leaf, key, grade and the address — so nothing downstream is broken;
the missing fact is only the port.

## The choice to make

Three shapes, all cheap, and this ball is filed for the ruling rather than
carrying one:

- **Say it.** One line on boot naming the bound address. An engine is a server
  and a server announcing its endpoint is ordinary; it costs one `eprintln` on
  the success arm the failure arm already has.
- **Write it.** A runtime file beside the material (never `address`, which is
  the *request* and the operator's) that the boot writes and a local seat reads.
  Single source of truth argues against a second address file.
- **Change the default.** Let the boot's own mint state a port. bl-dc14 rejected
  this for two engines contending on one box, and that reason still stands.
