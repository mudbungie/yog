Implementation of the bl-df65 design ruling (DESIGN §3.3 as amended —
"The workspace never enters the prompt" / "A conversation bears its own
minted name"). Docs are amended on main; this ball makes the code agree.
Read DESIGN §3.3 and §8.1 first. This body REPLACES the superseded bl-68d9
scope that previously lived here (that scope implemented
`Your workspace is <name>.`, which bl-df65 overturned).

## The ruling being implemented

DESIGN §3.3 (as amended at bl-df65):

> The preamble is therefore **one line and no instruction** — and the name
> in it is the **conversation's own**:
>
>     You are <name>.

where `<name>` is a **minted conversation name**: two words from the
embedded wordlist, hyphenated — `src/names`'s existing mint re-aimed one
altitude down. The workspace name leaves the prompt entirely: it stays
operative only in the harness channel (`YOG_NAME` env, the shim's `--as`
default, spawn `current_dir`) — an agent that needs its sphere reads
`$YOG_NAME`.

DESIGN §3.3, the mint:

> the stamped names of the target workspace's current roots [are the
> occupied set], read back from the goals the §11 conversation list already
> parses. No cross-workspace enumeration.

DESIGN §8.1 step 2:

> On confirm: the conversation name mints (§3.3 — a pure in-process step;
> exhaustion is a `["yog-step","mint"]` row, §4.2), the identity line stamps
> the goal, and `lernie prompt <root>/<name> <composed-goal>` — spawned
> detached …

Also from §3.3 (survives from the bl-68d9 wave, still unimplemented):
"**every prefill yog composes leads with its headline** — the ball rung's
first line is `Ball <id>: <title>`, the path rung's is
`Working directory: <dir>` (reworded from a sentence that buried the path
on line two)".

## Changes

1. `src/start/goal.rs` — the preamble fn returns
   `format!("You are {name}.")` where `name` is the minted conversation
   name (not `$YOG_NAME`); name it for what it is (e.g.
   `identity_preamble(conversation_name)`). Stamp shape unchanged:
   preamble + blank line + payload.
2. Mint at fire: `start::plan`/exec mints via `src/names` with the
   per-workspace occupied set = stamped names parsed from the workspace's
   root goals (the same parse the §11 list uses — one module owns compose
   and strip, see bl-1b5a). Pool exhaustion logs a `["yog-step","mint"]`
   ops row (§4.2). The composer's grey preview shows the pre-minted name
   (pure read: parsed root goals + injected RNG); fire re-mints on the
   lost race — preview is a prediction, the stamp is the truth.
3. `YOG_NAME`, the shim `--as` default, and every `bl` rider are
   UNTOUCHED — they carry the workspace name (§3.2), which no longer
   appears in the goal text.
4. `src/start/goal.rs` `path_preamble` becomes headline-first: first line
   `Working directory: <dir>`, then the existing work-there-by-absolute-path
   sentence.
5. Doc-comments and tests asserting the old preamble strings
   (`You are <ws>.` phase-1 / `Your workspace is <ws>.` never landed):
   `src/start/goal.rs`, `src/start/mod.rs`, `src/shell/workspace.rs`,
   `src/shell/mod.rs`, `src/start/tests/*`, `tests/stories_s0_t1.rs`
   (docs/STORIES.md S0/S0-T1 already quote the new strings, incl.
   `lernie new <names-root>/home` — but the `home` bootstrap default and
   New-workspace typed name are a SEPARATE ball; do not implement §3.1
   here unless that ball is this one's blocker).

  the wordlist, unique among the workspace's live roots' stamped names;
  blank line; payload exactly as composed. No workspace name anywhere in
  the goal text.
- The pre-submit view-model carries the same `You are <a-b>.` preview.
- `path_preamble`'s first line is `Working directory: <dir>`.
- `make check` green (100% coverage, 300-line cap).
