REMOTE 5.7 already rules that a credential living on a machine is reached through that machine's foot, with no second way. The server still folds provider rows of its own and calls a model with credentials it holds itself, which is the second way.

Operator ruling: remove it, but only once a far sign-in can be finished from any seat (bl-0127), because until then a far browser-only row cannot be kept signed in.

Open questions for the design, before code: what a server with no registered machine does (most likely: it has no models, and says so); whether the keyless local row moves to a foot like any other; what the seat's machine menu shows when the server entry is gone.

Tested by: no code path in the server spawns the provider binary except through a registered machine's entry.
