Consumer contract: an external client harness (the seat's snapshot harness, the android emulator loop) needs to boot a yog serving a NAMED, deterministic world state and get back a dialable address — so rendered snapshots are reproducible and comparable across runs.

Deliverable: one entry point (prefer an existing signal over a new flag — the suite already fabricates substrate in tests via test_support fake scripts and FakeClock; this is packaging those into named states, not inventing a mechanism). Something shaped like a test-support binary or make target: given a state name, boot yog against fixture substrate, print the address, tear down cleanly.

States worth naming (minimum set): empty first-run; busy wall with several speaking loops; wounded loop inside wound_grace; orphaned-chat banner; a long transcript (elision-relevant); a state with settings-relevant config present.

Constraints:
- Deterministic: FakeClock or pinned timing wherever a snapshot would otherwise race.
- Never touches the operator's ambient world — the nested-world XDG override (DESIGN sec 16) is the mechanism; self-repair style operations must gate on the yog data root per the standing rule.
- Verify premises against the tree before building; this body was written from docs and memory, not a fresh read.

Consumed by the seat-side kittest harness ball (lernie store) and the android screencap ball (yog-android store) — cross-repo, so no edge here; the contract above IS the coordination.
