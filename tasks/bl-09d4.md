`scripts/image-scan.sh`'s `config_text` reads the third surface — every `Env`,
every `Label`, and every `history` entry — with ONE `$ENGINE image inspect
--format` template. That template names `.History`, and **docker's image
inspect has no top-level `History` field** (podman's does). Under docker the
template fails execution: it writes a single newline to stdout, prints
`template parsing error: ... map has no entry for key "Labels"` to stderr, and
exits non-zero.

`scan_image` ignores that exit status and guards only with `[ -s
"$work/image-config.txt" ]` — and one newline is not empty. So the config
surface is scanned as a blank file, and an `ENV` shipped to everyone who pulls
is read by nothing.

The gate fails CLOSED rather than open, which is why this is not a disclosure:
`--self-test` plants a fabricated token in an `ENV`, misses it under docker,
and the build is refused. Measured both ways:

- docker (both builders, legacy and BuildKit, on two boxes): `self-test: MISSED
  a fabricated token planted in ENV — no finding matching '<image config>'`,
  `make image` exits 2.
- podman, same tree, same runner: all five planted findings caught, real image
  scanned clean.

So the standing cost is that `make image ENGINE=docker` — which the Makefile
advertises and README documents — cannot build an image at all, and the ghcr
release job (bl-6b96) names `ENGINE=podman` for this reason.

The fix is a portable read of the same three surfaces, not an engine
requirement. Both engines carry `image inspect --format '{{json .Config}}'`
(Env, Labels, Entrypoint, Cmd, WorkingDir, User in one field) and both carry
`history --no-trunc`, which is where docker keeps what podman puts in
`.History`. Whatever shape it takes, the guard has to become one that a
one-byte answer cannot pass — the enumeration checks in that file are there
because a scan that reads nothing passes everything forever, and this is that
failure wearing a newline.

Found while wiring the ghcr push job (bl-6b96), by a runner verdict.

---

Verified on a box with both engines. Premises hold exactly: docker's image inspect has no top-level History (template parsing error, one newline, exit 1), and [ -s ] passed it. Both engines answer identically to 'image inspect --format {{json .Config}}' and 'history --no-trunc --format {{.CreatedBy}} {{.Comment}}'. After the fix, make image ENGINE=podman and make image ENGINE=docker both exit 0 with the same verdict line (603 authored paths, 601 distro floor, 1 declared binary, 2 scanned) and both catch all five planted self-test findings. The new guard was driven the other way through a stub engine reproducing the old failure: a one-newline answer with exit 0 dies naming the missing Env, a failing read dies naming the command. Note for the next author: scripts/image-scan.sh is 294 lines against the 300 cap and was 276 before this change. It was not split because the file states its own reason not to be (it is a near-byte-identical port of thrall's and litany's copies, and a short diff against a sibling is the only defence against the three drifting). The next edit to it has to split along a real seam rather than shave.
