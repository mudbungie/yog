World C lays a pending inbox deposit for a ROOT agent (`<ws>/inbox/<root>/<child>-001.md`, §2.11's own naming) to fire §6 rule 5 (mail nobody is driving). yog's Flush — the composer's Scan, `lernie scan <ws>` (§8.2) — dispatches correctly and the ops row carries the child's failure verbatim:

    lernie scan: git ls-tree messages: git ["ls-tree", "-r", "--name-only",
    "agents/20260727T031141Z", "--", "messages"] exited with exit status: 128:
    fatal: Not a valid object name agents/20260727T031141Z

The ref it asks for is the recipient id truncated at its FIRST hyphen — i.e. scan derives a parent branch for every inbox-bearing agent and a ROOT has no parent, so the derived name is garbage and the sweep aborts. Reproduced with two different sender names, so it is the recipient side.

Consequence for the drive: the S7-T4 beat asserts the verb was DISPATCHED (`lernie scan` row present), not exit 0, because exit 0 is not yog's to give. Once lernie handles root recipients, tighten that beat to `row_ok '"lernie","scan"'` in scripts/drive/beats_s7.sh.
