**Resolved upstream — and the diagnosis in the original filing was wrong.**

## Fixed

lernie `c816ee8` on `main` (lernie task bl-025b), delivered with unit coverage
and an ARCH §8 amendment. `lernie scan` on this drive's exact world-C fixture
now exits 0.

## The title's claim does not hold

A ROOT agent with pending mail scans clean and always did. Verified against a
real workspace built with the shipped binary:

```
$ lernie new $W
$ git -C $W/repo.git branch agents/<agent-id> <tip>
$ mkdir -p $W/inbox/<agent-id>
$ printf -- '---\nfrom: user\n---\nhello\n' > $W/inbox/.../user-001.md
$ lernie scan $W
silent deaths: 0; died deposits swept: 0; drivers launched: 1; inboxes with no agent branch: 0
$ echo $?
0
```

The exit 1 came from a *different* branch the same fixture lays, in
`lay_forensics()` (`scripts/drive/beats_s7.sh`):

```sh
  git --git-dir="$g" branch "agents/$ag-c0ffee" "$tip"
```

lernie's sweep derived that branch's parent address by token arithmetic over the
hyphenated descent — a segment is `<ts>-<short>`, exactly two hyphen-free tokens
(lernie ARCH §2.3) — so the one-token `-c0ffee` suffix made three tokens, the
last two were stripped, and the sweep asked git for `agents/20260727T031141Z`.
Git's 128 aborted the whole pass **before the flush ran**. Not the recipient, not
the sender, not the mail: the mail was a bystander, and the failing branch needed
none of its own.

Adding the recipient-side hypothesis's counter-evidence for the record: adding a
*well-formed* child (`<root>-<ts>-<short>`) reproduced the same error, and
removing the mail entirely still reproduced it.

## The fix

lernie now intersects the derived parent address with the `agents/*` registry —
the same intersection its flush already applied to the inbox listing (lernie ARCH
§2.11). A branch whose derived parent holds no ref is nobody's child: treated as
a root, nothing deposited, nothing asked of git. Exit semantics are unchanged and
were never mail-dependent: `lernie scan` is documented as *"an operator verb is
loud, not best-effort: errors propagate to a non-zero exit rather than being
swallowed"* — the defect was a genuine error path reached on a non-error state.
