Filed by Alkaloid 2026-08-11, from bl-bc06's second finding (Ferrule).

## The finding that makes this necessary

`egui::Galley::text()` returns the text that went **in**, not what was laid out. A galley egui truncated to a bare `…` still reported the whole string. So every assertion ever made through `paint_probe` was **blind to elision** — the one class of defect the paint layer is the only witness for. bl-bc06 changes `paint_probe::collect` to read the laid-out **glyphs** row by row.

## Why a follow-up ball

On that change, **all 1815 existing tests still passed.** That is the alarming part, not the reassuring part. It proves two things at once:

1. No test was depending on the invisible text (good — the probe swap is safe).
2. **No test anywhere was covering truncation at all.** Every elision defect in the tree has been invisible to the suite by construction, not by luck.

bl-bc06 fixes the probe and covers two rows (the Login row and the ball row). It does not and should not sweep the rest.

## Scope

Re-audit the paint-layer assertions across the suite against the glyph-reading probe, and find the defects that were unobservable until now:

- Any assertion that checks a row's text and would pass identically if the row painted `…` — those are vacuous and should assert on painted glyphs.
- Sweep the surfaces bl-bc06 did not: activity rows, inbox rows, conversation rows, config form fields, inspector tabs, status bar, masthead.
- Related open balls whose evidence is now suspect or newly testable: bl-3aa1 (rows keep the invariant prefix, elide the informative tail), bl-b531 (text hard-cut mid-glyph with no ellipsis at 420x320), bl-76f8 (config fields truncate mid-token while 1700px sits empty).

Expect this to surface real elision defects that have always been present. File them separately rather than growing this ball.

## Do not

Do not re-land bl-bc06's probe change or its DESIGN §11 rule 1b ("the control wins the row", `src/shell/row.rs::control_last`) — claim this only after bl-bc06 is on main, and build on it.

Verify all cited paths against HEAD first; ball bodies drift.

## How this audit must proceed (Ferrule, via Alkaloid)

**A green suite after the probe change is the null result, not the pass.**

The probe swap was only *safe* because nothing covered truncation. The corollary is that this audit **cannot** proceed by "did any test change colour" — the tests that should have failed do not exist yet. Waiting to see what breaks will find nothing and conclude the tree is clean.

It has to go **surface by surface**, asking of each: *can this surface elide at all at a bounded width?* Where the answer is yes, write the assertion that does not exist.

## The two predicates are different, and neither subsumes the other

`paint_probe::collect` returns `(String, Rect)` per galley, and after bl-bc06 the string is the **painted glyphs** — what the operator actually sees. That supports two distinct assertions:

1. **bl-bc06's** (a control's label survives whole): the painted glyphs contain the label intact, and the sacrificial text is absent, proving the row really was over-full.
2. **bl-b531's** (a cut label is *marked* as cut): the painted glyph string is shorter than the input **and ends in something other than `…`**.

A surface can pass 1 and fail 2. Audit for both.

## The standard for every assertion added here

Revert the layout, run the dump, and confirm it prints the literal defect. bl-bc06 did this and got `claude-session-direct / auth oaut… / …`. An assertion that has not been shown to fail against the broken layout is not evidence.

## A third flavour of vacuity: assertions that pin content but not position (Ferrule, via Alkaloid)

Found while scoping bl-71fc. `src/inboxview/tests.rs:140-141` assert the empty-state **string** but not its **position**. The defect in bl-71fc is positional — `(no deposits)` is bottom-anchored by `tail::scroll`'s `anchored = true`. So:

**The fix could land and those two assertions would keep passing on the unfixed layout.** They cannot distinguish the broken frame from the correct one.

That makes three distinct vacuity shapes now catalogued, and the audit should look for all three:

1. **Wrong source** — asserting on input text rather than painted glyphs (the `Galley::text()` defect this ball exists for).
2. **Wrong predicate** — a check satisfied by something other than the behaviour (empty-variable and generic-key greps; bl-f16e).
3. **Wrong axis** — pinning *what* is painted while the defect is *where* it is painted. Position, order, anchoring and alignment are all unasserted today.

`paint_probe::collect` returns `(String, Rect)`, so the rect has always been available — shape 3 is unasserted by habit, not by limitation. bl-fb1c's alignment evidence (x-coordinates of wordmark vs tagline) needs no new machinery either.

When rewriting an assertion under this ball, state which of the three shapes it was, and prove it bites.

## A fourth shape, and the reason none of these are caught today (Ember, via Alkaloid)

**4. Deleted or truncated assertions.** While editing, Ember's sloppy `str.index` boundary silently truncated the pre-existing `a_raw_editor_takes_the_pane_width` test. Clippy's `unused_import` caught it by luck; nothing else would have.

**The reason that is not caught, and it generalizes to this whole ball:**

> **100% line coverage does not detect a deleted assertion.** Coverage measures lines *executed*, not lines *asserted*.

A truncated test body still executes the code — often the same lines another test also covers — so the gate stays green at 100%. The repo's strongest quality guarantee is structurally blind to the exact defect this ball exists to find. That is why the audit cannot be driven by the coverage report or by 'did anything go red'.

Practical checks for shape 4 while sweeping:
- Compare test **counts and names** before/after, not just the coverage number.
- Any hunk that *removes* assertion lines while claiming to fix something deserves a second read.
- `a_raw_editor_takes_the_pane_width` was restored verbatim; confirm it is intact at HEAD.

## Related: a probe that lies for a second reason (bl-76f8)

Ember also found that measuring a `TextEdit`'s **galley** says nothing about what the operator sees — a `TextEdit` lays its text out **unwrapped whatever the box width**, so the galley size is constant while the visible run is cut. The assertion had to measure the *visible* run instead.

That is the same family as this ball's founding defect: the obvious handle on 'what is painted' reports something other than what is painted. Add it to the sweep — anywhere a test measures a galley of an editable field, it is measuring the wrong thing.

Ember's before/after is the standard to hold: **281 pt at 700 and 281 pt at 2560, identical — the defect as a number** — then cut at 700 and whole at 2560 after, with the narrow case still genuinely failing.

## A fifth shape, and a pairing rule (Ferrule, via Alkaloid)

**5. A test that CONSTRUCTS the precondition the code depends on, instead of proving the code does not need it.**

Ferrule's rule 1b pinned a trailing control right and relied on the **ambient** wrap mode to truncate the text beside it. True in the side panel (rule 1 sets `Truncate` at the root); **false in the centre, where egui defaults to `Extend`** — and the Login rows paint there too, because the auth-failed banner renders `login_section` inline in the conversation. Pinned right with text free to extend, the text stopped running off the edge and instead ran **through the control**: an elision defect converted into an overlap, which is strictly worse.

**Both of its own new tests passed.** Both constructed a `Truncate`-rooted panel — they *assumed* the condition the helper depended on rather than guaranteeing it. A test that builds the happy precondition cannot discover that the code requires it.

Sweep heuristic: for any assertion, ask **what ambient state does this test set up that production does not guarantee?** Then write the version that omits it. Ferrule's fix made `control_last` set `TextWrapMode::Truncate` on the text side itself so the rule depends on no ambient state, and added `the_row_truncates_itself_in_a_seat_that_declares_no_wrap_mode` — driven on the blocked branch, verified to bite by deleting the one line and watching it fail with the literal overlapping text.

## Pairing rule: run BOTH predicates over the same dump

The bug was caught by **another ball's** test (bl-9551's `overlap` walk), not by this ball's. The two predicates are complementary and neither subsumes the other:

- **survival** — does the label that matters remain whole? (bl-bc06)
- **disjointness** — do any two painted runs share pixels? (bl-9551)

A surface can pass either and fail the other; converting an elision bug into an overlap bug passes survival and fails disjointness. **The re-audit must run both over every surface**, plus the position/anchoring predicate from bl-71fc and the marked-as-cut predicate from bl-b531.

That now makes four predicates and five vacuity shapes catalogued on this ball. They are cheap to run together and expensive to discover one at a time.
