## The defect (operator ruling: a bug)

A foot that is restarted — its tool document edited or not — is refused by the server for up to a hold's width, and in practice longer: the unit crash-loops or one channel of several stays dead.

Mechanism, read off the code and not the docs:

- `Mailbox::take` (src/registry/mailbox/slots/read.rs) holds the one-reader claim for the whole thirty-second hold, asleep between looks, and nothing tells it the peer's socket closed. A killed process leaves its claim standing.
- `advertise` refuses a CHANGED set while that claim stands (`superseding`, src/boundary/dispatch/advertise.rs), and the foot reads a refused advertisement as terminal — so the new process exits, the supervisor restarts it, and it is refused again.
- An UNCHANGED set is accepted and then the new process's own `invocations` is refused by the dead claim; the foot waits a hold's width and more before asking again.

## The ruling

A restart is an activation, and an activation says so. The same certificate must be serving again within a second or two.

## The rule to land

`advertise` is the gesture a process makes when it takes a channel up, so it is the existing signal of a new activation:

- An accepted advertisement ENDS whatever read its certificate holds. The set comes into force and the next `invocations` from that certificate is the reader.
- The read that was ended is answered, not dropped: `reply/invocations` with no rows and `superseded: true` (an optional key — an edition, no PROTOCOL bump). A process that is still alive learns it lost the queue.
- A bare `invocations` still never takes a queue from the read that holds it.
- Work handed to the ended read follows REMOTE 5.6/5.7 unchanged: redelivered while unacknowledged, in doubt once a post has landed.
- The guard that refused a changed set under a parked read goes: it protected a serving machine from a silent disarming, and the ended read now says it out loud.

Considered and not taken here: the server probing a parked connection for EOF. The answer path holds no socket, so it is a seam through the listener, the intake and the dispatch for a case the supersession already covers; a clean TLS close also leaves bytes ahead of the FIN that a peek cannot tell from a request.

## Done when

- restart with a changed set and with the same set are both serving at once (test)
- a live duplicate's parked read is answered superseded (test)
- a bare redial does not take the queue (test)
- in-flight work of the superseded activation ends as 5.6/5.7 say (test)
- REMOTE 5.1 says the rule as landed; the corpus carries the key
- thrall reads the key and stops that channel naming why (thrall ball)
