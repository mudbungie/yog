## What the operator sees

A conversation answers normally, then the model calls a tool and the chat goes
silent. Every message sent afterwards produces nothing. The conversation is dead
and no gesture in yog revives it.

inside the tool window, before the executor was entered.

## Why it is invisible and why it is permanent

Both halves are pinned-lernie defects, both fixed upstream after 0.0.6:

1. **Invisible** — lernie 0.0.6 `AdvanceLauncher::launch` binds the detached
   driver's stderr to `Stdio::null()`, so whatever killed it printed to
   /dev/null. Fixed by lernie bl-55f9 (0.0.7): stderr now lands in
   `steps/<agent>/driver.log`.
2. **Permanent** — lernie 0.0.6 `tool_step::run_tool_calls` returns
   `ToolWindow::Stopped` without settling, leaving the `tool_use` unanswered.
   Fixed by lernie bl-b98d (0.0.7): the stopped exit now commits one in-band
   `is_error` tool_result per unanswered id, so the tail is resumable.

## The fix

Bump `Cargo.toml` `lernie = "=0.0.6"` to `"=0.0.8"` (published; it links
`brazen =0.0.5`, the same exact version yog pins, so the §16.7 parity note
holds). Fix any `cmd::Fx` / `Command` API fallout, run the suite, merge.

Three balls are already blocked on this publish and unblock with it: bl-cd38
(the mint), bl-6654 (cwd binding, lernie bl-d0b4), bl-2d19 (retarget, lernie
bl-22a5). bl-bb09 (AGENTS.md rule 6 cites a stale pin) is the same edit's
neighbourhood.
