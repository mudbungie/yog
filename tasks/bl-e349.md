## Observed, live

Operator focuses a remote workspace (in the roster since bl-028a), opens the
start pane, types a goal, hits Enter — and is immediately dropped back at home.
No conversation, no refusal, no reason painted anywhere.

## The mechanism

`src/shell/start_pane.rs::send_pending`:

    let ws = model.snap.ws_path(&p.workspace).unwrap_or_default();
    ...
    super::acting::start::prompt(model, state, &ws, &p, &p.goal);

`Snapshot::ws_path(name)` answers `Err` for a remote name (bl-028a, recorded in
its landing: path-needing surfaces paint empty, rung 2/3 fill them). Here that
`Err` is flattened by `unwrap_or_default()` into `PathBuf::new()` and the act
is FIRED anyway, aimed at an empty path. Whatever the engine does with that,
the operator sees only the bounce.

Two defects, one site:

1. **`unwrap_or_default()` on a path that gates an act.** An empty path is not
   a workspace; firing at it is a silent wrong act for EVERY `Err` case, not
   just the remote one. The pattern to follow is the pane's own doc: "a failed
   launch keeps the composer open with the edited goal" — an unresolvable
   workspace must refuse before posting, in the pane, with the composer and
   goal intact.
2. **The refusal discipline is violated.** bl-dc14's rule: a refusal is said
   where the operator is. Nothing said anything.

## Sequencing — gated on bl-670c, on purpose

bl-670c (in flight) is the real remote fix: the poster routes acts by the
workspace they NAME, so a start on a remote workspace should route over the
entry channel rather than resolve to a local path at all. This ball is
therefore claimed AFTER 670c lands, and its job is:

- reconcile `send_pending` with whatever 670c built (the act should carry the
  name and route; if a path is still needed for the local arm, the remote arm
  must not go through `ws_path`),
- kill the `unwrap_or_default()` so no arm can ever fire at an empty path,
- make the failure legible: if any workspace still cannot accept a start, the
  composer stays open and the reason paints in the pane,
- acceptance coverage for: start on a remote workspace (routes, post-670c),
  and start on an unresolvable name (refuses in place, composer intact).

Verify the mechanism against the tree at claim time — 670c may have already
moved this exact line.
