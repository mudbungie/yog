## Symptom — one noun short of bl-6c9e's ruling

A project primed into the world is refused by every ball gesture until the
worker's next sweep, and the refusal is indistinguishable from a typo:

```
$ yog bl prime --as <name>                 # in the project, inside the world
$ yog gesture --ws <ws> --project proj --as <ws> '/create a tiny task'
{"error":"unknown project \"proj\"","ok":false}

… one full sweep later, byte-identical command …
{"exit":0,"kind":"outcome","ok":true,"stdout":"bl-8694\n"}
```

## Cause

`app::snapshot::names::addressable` — the fix bl-6c9e landed — folds exactly
one set:

```rust
pub(crate) fn addressable(published: Arc<Snapshot>, live: Vec<Workspace>) -> Arc<Snapshot> {
    if live == published.workspaces { return published; }
    Arc::new(Snapshot { workspaces: live, ..(*published).clone() })
}
```

`projects` is left as the derivation published it, so `Action::project()` /
`naming::resolve` answer over a cached set. bl-6c9e's own ruling is stated as a
rule about existence, not about one noun:

> **Birth is a barrier because existence is a query** — and no claim is held
> anywhere to make it one…

and REMOTE §8's summary of it says the intake builds the environment "with the
§3.1 enumeration as disk holds it". A project is enumerated the same way, off
the balls clones directory; it simply was not included.

## The second half: nothing answers "what projects are there?"

`--project` takes the §5.1 #1 derived name (the shortest unique trailing run of
path components). No gesture answers that set. `/balls` and `/board` carry a
`project` field only for balls that already exist, so on a world with a primed
project and no balls — exactly the state after `bl prime` — the operator cannot
learn the word `--project` wants. The refusal names the token they typed and
offers no way to find the right one.

Compare `/workspaces`, which exists for precisely this and answers names.

## Repro

    # in a git repo inside the world
    yog bl prime --as <name>
    yog gesture --ws <ws> --project <leaf> --as <ws> '/create x'   # unknown project
    # wait one full sweep; the same line succeeds

## Shape of the fix

- `addressable` folds the live project enumeration beside the live workspace
  one — the same readdir-over-cache shape, and it runs backwards for free the
  same way (a project removed stops resolving at once).
- A `/projects` read answering the names `--project` takes, beside
  `/workspaces`. Small, and it is the discoverability half: an address you
  cannot enumerate is an address only the seat that already knows it can use.
