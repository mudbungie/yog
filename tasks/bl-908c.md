Reproduced and fixed: the whole app/watch-side flake class is ONE mechanism — the per-user inotify instance budget.

MECHANISM. `WatchSet::reconcile` armed a separate `notify::RecommendedWatcher` per watched root, i.e. one inotify instance per root (5 enumeration roots + 1 per workspace). `fs.inotify.max_user_instances` is 128 PER USER, shared with every other process on the box. A failed arm is silent by design (reconcile skips the key and retries), so exhaustion never surfaced as an error — it surfaced as watches that were simply never armed:
- app::tests::drift::construction_arms_the_watch_before_taking_the_first_snapshot and app::tests::construction_arms_the_workspace_and_enum_watchers assert `WatchSet::watches(...)` directly -> false.
- app::tests::drift::a_workspace_{appearing,vanishing}_between_sweeps assert Unenumerated drift, which `Deriver::announceable()` gates on `set.watches(root, kind)` -> the finding is filtered out, 0 rows.
- fs_watcher::tests / watch::tests fail at construction with EMFILE ("Too many open files" from inotify_init1).
The suite was self-poisoning: ~3 instances per booted AppModel x N test threads. At 32-64 threads it blew the budget on its own; at 16 it needed only one other agent gate running. NOT a timing bug — no sleep, no wall-clock race; the FakeClock seam was already correct.

NOT REPRODUCED: start::tests::run::prepare_*. ~20 full-suite runs across CPU saturation (24 spinners on 16 cores), fd starvation (ulimit -n 96/256), total inotify starvation, and 6 concurrent suites x 32 threads — the prepare_* group never failed once. Statically they hold SPAWN_LOCK across write+exec, spawn no watchers, read no clock, and log ops synchronously; I found no load-sensitive path. Either it was collateral of a different run, or the trigger is outside what I could provoke. Left unchanged rather than papered over.

FIX (mechanism, not symptom). `src/fs_watcher/hub.rs`: the process owns ONE notify instance, and each `Watcher` is a subscription fanned out by root prefix. `Watcher::tick`, the RootKind allowlists, coalescing, staleness and `WatchSet` are unchanged — every existing watcher test passes untouched. Two documented consequences: a backend error has no root attribution once instances are one, so it desyncs every live root (a superset, which is what Desynced already means); and because notify unwatches a whole subtree, `disarm` re-arms every overlapping live root instead of leaving a nested one deaf (both proved by new tests). This is also a production fix — yog past ~120 roots would have silently lost watches, and it drops one thread per root to one per process.

Rule 7 carve-out: the two `OnceLock` singletons keep their `Mutex` in hub.rs, declared in rules/locks-outside-state.yml alongside probe_cache. Folding them into state.rs measurably costs the chokepoint its 100% floor (llvm-cov mis-attributes phantom uncovered regions onto its impl headers and type aliases when the file byte-shifts) — same reason, recorded verbatim. DESIGN 7.1 and AGENTS rule 7 amended.

VALIDATION. Before: 32/64-thread runs failed every time; 5 concurrent suites x 16 threads failed in all 5. After: 9 consecutive full-suite runs at 64 threads and 6 concurrent suites x 32 threads, all 1096 green, with only 43 inotify instances free on the box. make check green (fmt, clippy+ast-grep+deny, 100.00% coverage 6063/6063).

RESIDUAL (not fixable in code): with the budget at literally zero free instances, watcher tests still fail — nothing can watch without an instance. The suite now needs 1 instead of ~100.
