Round-1 multitenant lane. Reproduced on two independent fresh workspaces on one
engine. Neighbours: bl-8523 and bl-21e9 are about what the refusal SAYS; this
is about the refusal not firing at all.

## Gesture and replies

A wall carrying exactly one operator-written provider row,
`claude-session-direct`, whose credential is ambient and readable
(`yog bz --list-models --provider claude-session-direct` answers a model list).
The workspace's roles are the defaults, which name `anthropic`:

    $ lernie roles beta
    worker     anthropic  claude-sonnet-5
    compactor  anthropic  claude-haiku-4-5
    reviewer   anthropic  claude-haiku-4-5

The §9.19 door lets the start through:

    $ lernie start beta "Create a file … Then stop."
    {"kind":"prepared","ok":true,…}
    {"conversation":"ChipmunkMango","kind":"started","ok":true}

and the conversation is dead on arrival:

    $ lernie conversations beta
    ChipmunkMango  stopped  tone=bad
      failure: "no credential for this provider: set BRAZEN_API_KEY (or the
                provider API-key env var / --api-key) o"

## Two defects

**1. The door asks the wrong question.** Its own sentence is *"no provider in
this workspace's wall holds a credential"* — ANY provider. What the fire needs
is a credential for the provider the governing lineage's **roles** name. One
credentialed row the roles do not name satisfies the gate and readies nothing.
Before the row was laid the same start was refused correctly, so the gate works
— it is just not asking about the role.

**2. The failure string is cut off mid-token.** The row's `failure` field ends
`… --api-key) o` — truncated at ~120 characters inside the word `or`. The
remedy the sentence was about to name is the half that got cut.

## Expected

The `prompt` door reads the roles the fire will actually resolve and refuses
naming the role and its provider — e.g. "worker resolves `anthropic`, which
holds no credential in this wall". And a `failure` that is truncated says so
(an ellipsis), or is not truncated.

## Severity

p2. Every workspace born on this engine — including the very first one on a
fresh box — spends a conversation and a model call to discover a fact the
engine already held before it fired. In a multi-seat workspace the operator who
finds the corpse is not the one who started it.
