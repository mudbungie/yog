Operator report 2026-08-21: a benign lernie driver notice ("compaction landing
[...] superseded — ... the branch continues", lernie child_result.rs:280-296,
printed on an Ok(()) path) paints in ichor at the originating surface as the
§7.3 failure banner — argv line + stderr tail — and reddens the ops row/chip.
Doing nobody any good.

## Verified root cause

`src/opslog/exit.rs:110-118`: `ExitKind::Detached => !self.stderr.is_empty()`
— for detached (-2) rows yog substitutes "said anything on stderr" for
"failed". lernie's pinned contract says the driver's stderr is an OPERATOR
NOTICE channel (lernie ARCHITECTURE.md:565: declines, superseded compaction
landings, budget stops, accepted-crash notes — "addressed to an operator").
The exit code is right and yog never observes it (the -2 sentinel row is
written at handoff, `src/start/prompt.rs:150-158`; sink fold at read time,
`src/opslog/detached.rs:72-88`). Because the fold re-reads the sink TAIL every
sweep and the sink is append-only for the driver's life, one benign notice
keeps the newest row of its origin red until the operator acks
(`src/app/balls.rs:65-72` last_failure; painted `src/shell/banner.rs:44-55`;
chip/ops row via `src/opslog/live.rs:143-160` + `theme/badges.rs:266`).

The benign class is broad and enumerated: lernie child_result.rs:282/:289,
advance.rs:136, advance/crash.rs:68, terminal.rs:130/:190/:214,
driver.rs:151/:162.

## The change (the bl-8433 move, repeated, plus the sibling classifier)

1. **`OpOutcome::Notice`** — a fifth outcome beside Clean/Failed/Detached/…
   (`src/opslog/live.rs:50-58` is the precedent: Detached was added exactly
   because a fact was neither clean nor failed). `failed()` false; own badge
   in `theme::op_badge` (ash/brazen glyph, NOT ichor); still expandable in
   the ops pane; retires like Clean/Detached. The §7.3 banner never paints a
   notice row.
2. **`opslog::notice` classifier** — sibling of the two existing text-keyed
   classifiers over the same folded tail (`config_edit::fault::looks_config`,
   `src/config_edit/fault.rs:43-121`; `login::auth::looks_auth`,
   `src/login/auth.rs:31-53`), deliberately narrow, case-insensitive markers
   for the enumerated lernie notice lines. A tail that mixes a notice with
   unrecognized lines stays a failure — fail toward alarming, never toward
   silence. Record the fragility note the fault classifier already carries;
   an upstream lernie ball asks for a stable "lernie: notice:" prefix that
   will replace the phrase list when it lands.
3. **Sibling fix:** `src/shell/activity.rs:186-189` paints the `stderr:`
   label ichor on ANY row with captured stderr, exit-0 piped verbs included —
   use a neutral hue unless the row itself is failed.

Out of scope (filed separately as the architectural follow-on): deriving a
detached row's failure from STATE (driver lost the lock, no reply) with sink
content as diagnosis only, per DESIGN:9296's own "content is never the
trigger" rule — that ball subsumes the marker list.
