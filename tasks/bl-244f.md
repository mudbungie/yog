Operator ruling on bl-fd5a's open decision 1. The carve-out read:

  "`docs/drive-logs/` is exempt from the operator-home rule only (every other
   rule still applies there) because those files are append-only evidence of
   runs on a real box and the path IS the evidence."

Ruled: burn them. 11 files, 2595 lines, 176K — every one an operator-home
carrier (62 occurrences of the real home path).

## Scope

1. `git rm docs/drive-logs/` — the whole directory.
2. Drop `SKIP[operator-home]` from `scripts/leak-scan.sh`. That was the ONLY
   user of the per-rule path-exemption mechanism, so the mechanism goes with
   it: the `SKIP` array and `scan`'s filtering branch are now dead code, and
   dead code is context nobody asked to carry.
3. `scripts/drive/logskel.sh` folds `$HOME` to `~` in every path it emits.
   Without this, burning the logs and dropping the exemption sets a trap: the
   next drive run generates a skeleton full of real home paths, and the gate
   refuses the commit that files it. The generator is where the redaction
   belongs — one place, before the operator ever sees the text.
4. Repoint every dangling citation: `docs/STORIES.md` (7), `docs/DESIGN.md`
   (1), `docs/QUALITY.md` step 6, `AGENTS.md`'s carve-out paragraph. The
   historical CLAIMS stay — a passing run on a date is still a fact — they
   just name the run instead of a deleted file.

## What this does NOT do, stated plainly

Deletion at HEAD is not unpublication. The logs remain in git history and on
GitHub, and `target/package/yog-0.0.1/docs/drive-logs/` confirms they shipped
inside the crates.io tarball for 0.0.1. Actually erasing them means a history
rewrite plus a force-push plus a crates.io yank — a separate, much larger
decision, not taken here. What this ball buys is that the tree stops carrying
them and the gate stops making an exception for them.

DELIVERED. 11 files, 2595 lines removed; 17 files touched, 2625 deletions.

The exemption mechanism went with the logs, not just the entry: `SKIP` was the
only per-rule path escape in `scripts/leak-scan.sh` and `docs/drive-logs/` its

whoever hand-finishes it. That took `set -o pipefail`: the emission now ENDS
in a pipe, and without it a python3 dying mid-table would exit 0 through sed
and hand back a truncated skeleton as a whole one. Verified both ways — a
skeleton generated from home-rooted verdict rows emits `~/.local/bin/yog` and
passes `leak-scan`, and a corrupted `verdicts.jsonl` exits 1.

Seven dangling citations repointed to name the RUN rather than the deleted
file (`the 2026-07-26 W14 clean-room drive`), across `docs/STORIES.md` (6) and
`docs/DESIGN.md` (1). Every historical claim stands; none now cites a path
that resolves to nothing.

`docs/drive-logs/`, now with "Quote the evidence, not the operator. ... an
absolute path was never the evidence, the verdict was." Burning the logs and

drive generates a skeleton full of real home paths and the gate refuses the
