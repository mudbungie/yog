## Mechanism (composition fault, in lernie)

NOT a goal-copy bug: every child's goal.md and deposited dispatch message carried the dispatch call's goal argument verbatim (proven from the dispatch commits and inbox deposits). The children re-dispatched because lernie's child fork inherited the parent's transcript as the child's own opening context:

- The fork is off the parent's tip; the dispatch commit's trim (lernie src/prompt/dispatch/step_commit.rs, trim_to_context, then line ~182) removed control files, ungranted descriptors, the UNSETTLED tool tail, and settled the name - but left the parent's messages/** in the child's tree. Assembly is a pure function of the tree (ARCH 5.1) and the transcript composes unconditionally (5.2), so gen 1's step-1 request (steps/<gen1>/001/request.json) literally contains energize's messages 001-007 as its own conversation, ending in the user-role "spawn a subagent to analyze..." followed by the goal message from the parent agent.
- The unsettled-tail prune (lernie bl-4231, step_commit/unsettled.rs) deletes the parent's model-output entry carrying the dispatch tool_use - i.e. exactly the evidence that the spawn had already happened. So each child saw an apparently UNANSWERED user instruction "spawn a subagent...", outranking the parent-sent goal message, and obeyed it: gen 1's very first model output is a dispatch tool_use (transcript entry 009). Recursion by construction, one generation per ~3s.

## Fix (lernie bl-5a36, commit feeb127)

New src/prompt/dispatch/step_commit/inherited.rs (prune_inherited_dialog), called from subagent::spawn_subagent_branch: every child's dispatch commit now deletes the fork point's branch-scoped dialog - messages/**, summary/**, skills/** (ARCH 2.2: written per-branch, never another branch's tree; the transfer already excluded them child-to-parent). Two principled keepers: the compactor (the dialog IS its subject, 2.7) and fork-back-in roots via lernie prompt --from (they resume the very conversation - which is why the prune lives in the child spawn, not trim_to_context). Tests reproduce the runaway shape over real git (a_child_never_opens_on_its_dispatchers_dialog: parent tail = "spawn a subagent...", child tree carries none of it, only the deposited goal; a_compactor_keeps_the_dialog_it_exists_to_compact).
