Found while splitting the ≥295 band (bl-b278) and left standing there on purpose: this file is 297 lines because ~200 of them already exist next door, and splitting a duplicate is the wrong repair.

`src/boundary/reply/tests/mod.rs` and `src/boundary/reply/tests/rows.rs`
both define:

    join_rows_encode_the_binding_facts                              IDENTICAL
    ops_rows_encode_the_durable_line_fields                         IDENTICAL
    the_agent_state_and_flight_tokens_are_total                     differs by one inline `use` line
    workspace_rows_carry_the_classification_and_rollups             rows.rs is a strict superset
    conversation_rows_encode_their_optional_facts_only_when_present rows.rs is a strict superset

Rust allows it — they are different module paths — so nothing complains and
both run. `rows.rs`'s module doc already claims the subject outright: *"The
row encoders' tables: every field a workspace, conversation, join or ops row
carries, and the two token mappings that must stay total."* Its own copies are
the better ones: the two that differ cover fields `mod.rs`'s leave at `None`,
and `rows.rs` carries a sixth beat `mod.rs` has never had
(`a_display_only_name_is_withheld_from_the_boundary_as_a_message_target`).

Both files predate the squashed public root, so there is no split commit to
read the intent off; the duplication is simply old.

**The fix:** delete the five from `mod.rs`, keeping `rows.rs`'s copies, after
confirming per-beat that each surviving copy asserts everything its twin did —
the two supersets need reading, not assuming. That leaves `mod.rs` holding
what it is actually about: the reply envelope (outcome, prepared, cleared,
refusal, help), around 95 lines, and no split is needed at all.

Coverage is the check that the deletion cost nothing: the gate's 100% floor
fails if any line only the deleted copies reached goes uncovered.
