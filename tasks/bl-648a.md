QUALITY.md §1 criterion **H2** ('Absence is named. An empty region says what it is and names the paved path in full; it is never a bare blank or an unlabeled box' — precedent bl-b491, bl-b2ed). Audited sha 4b0e75c, run /home/u/.cache/yog-drive/quality-20260807T214407Z/out.

SYMPTOM. Ctrl+F, a needle, Enter. If the needle matches, the answer pane appears under the composer. If it matches nothing, **the pane does not appear** — no 'no matches for …', no count, no trace that a search ran at all. The operator cannot tell a search that found nothing from a gesture that never fired.

MECHANISM (read, not guessed) — `src/shell/search_pane.rs`:

    if !searching && found.hits.is_empty() && found.unreadable.is_empty() {
        return;
    }

The early return is unconditional on whether a search was ever published, so 'zero hits' and 'no search' render identically.

WITNESS: `Q-S4b-default.png` shows the populated answer for the needle 'inspector' (two ball rows). `Q-S4b-empty.png` / crop `crop-s4b-empty.png` is the very next frame after searching 'zzzznotathing' — the region is empty; only the composer and its verb rows remain.

REPRODUCTION:
  1. launch on a seeded world with at least one ball
  2. key ctrl+f ; type 'inspector' ; Return   -> answer pane appears (control)
  3. key ctrl+f ; type 'zzzznotathing' ; Return -> nothing renders
The headless twin `yog gesture '/search zzzznotathing'` returns an empty answer normally, so the derivation is fine; this is the pane's rendering of it.

BALL BODY HAS DRIFTED FROM THE TREE (verified 2026-08-11, Ferrule, read-only groundwork while gated on bl-bc06 — NOT claimed, NOT worked).

The cited mechanism no longer exists. `src/shell/search_pane.rs` carries no early return at all today; the whole file is 60 lines and `pane()` unconditionally paints `searching…`, then the hits, then the unreadable notes. bl-1ca2 moved the answer out of a 220pt scroller under the composer and made it a §11 CENTER TAB, and the defect moved with it.

The defect now lives one level up, in `src/shell/center.rs::render`:

    let answer = model.found();
    let searching = model.searching();
    let offered = searching || !answer.is_empty();
    if state.center == CenterTab::Search && !offered {
        super::focus::center(state, CenterTab::Conversation);
    }
    strip(ui, model, state, offered);

and in `strip`, which skips the tab entirely when `!search`:

    if tab == CenterTab::Search && !search { continue; }

So a zero-hit answer does not render an empty pane — it UN-OFFERS the tab and reseats the operator on Conversation. The symptom the ball describes is intact and if anything worse than filed: not merely 'nothing renders' but 'the tab the operator was on disappears from under them'.

`Found::is_empty()` (`src/search/mod.rs:123`) is `hits.is_empty() && unreadable.is_empty()` and its doc says it is deliberately shared by both seats — the strip deciding whether to offer, and the pane deciding what to paint. That sharing is exactly what makes zero-hits and no-search indistinguishable: emptiness is being used as a proxy for intent.

SUGGESTED SHAPE (single source of truth, not a flag): the answer should carry the needle it answers — `Found { needle, hits, unreadable }`, set by `search::run`. Then the offer condition becomes 'a search was asked' (`searching || !answer.needle.is_empty()`) rather than 'there were hits', and the pane names the absence with the needle in it. This preserves the existing 'a /search with no text clears it' rule for free — an empty query yields an empty needle, so the tab vanishes exactly as it does now, with no special case. The caller stops re-deriving intent from emptiness; the answer knows what question it answers.

Note for whoever takes it: after bl-bc06 the paint-layer probe reads laid-out GLYPHS, so an assertion here can name the literal on-screen text of the empty state rather than the string that was handed in.
