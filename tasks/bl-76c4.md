Scenario: lane KNOWLEDGE, round 1. First act on a brand-new workspace: add a provider row so a role can be pointed at a model.

GESTURE

    $ yog gesture --ws notes "/prepare dir <some path>"
    {"kind":"prepared","ok":true,...}
    $ yog gesture --ws notes "/config brazen # hello"
    {"error":"No such file or directory (os error 2)","ok":false}

Reproduced on a second, independently created workspace. The read direction works and answers empty:

    $ yog gesture --ws notes "/config brazen"
    {"kind":"config","ok":true,"settings":[],"text":""}

CAUSE AND WORKAROUND

`<yog-data-root>/world/walls/` did not exist at all — a wall is born empty (DESIGN §16.2, README "The world": "A wall is born empty ... custom rows and sign-ins are per-workspace acts you perform after birth"), and the directory is not created by the write path. After

    mkdir -p <yog-data-root>/world/walls/<workspace>/brazen

the identical gesture answers `{"kind":"applied","ok":true}` and `/providers` then shows the new rows.

EXPECTED

Either the write creates the wall on the way (it is the documented first act on a newborn workspace, so it is the ordinary path, not an edge case), or the refusal names the wall path and says it must exist. A bare errno with no path is unactionable: nothing in `--help /config`, `/providers` or `/lineages` mentions a wall directory, and the README documents walls as a place that resolves rather than a place you create.

SEVERITY

p2: it is not a corner — every newborn workspace is in this state, and adding a provider is the first thing a user does. It only reads as p2 rather than p1 because the shipped keyless rows (`claude-code`, `ollama`) work without it, so a user who never adds a row never hits it.
