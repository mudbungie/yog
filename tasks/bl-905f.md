## Operator complaint (2026-08-01, verbatim)

'the inference status at the top is good, but I want to see in-flight call characteristics at the bottom of the screen while it's going. something so that if I'm looking down at the chat, I'll see that it's working.'

The chat is tail-anchored now (bl-5cdb), so the operator's eyes live at the BOTTOM. The top status is out of their field of view while reading the tail. While anything is in flight for the focused conversation, a strip at the bottom of the screen must say so, with live characteristics — so a glance down-screen answers 'is it working?'

- The live tail is on disk (streaming JSONL, read via git_tree streaming machinery); the running tool's records carry its name. The bottom of the screen holds the activity accessory (src/shell/activity.rs) and the input bar.

## Design

A one-line strip, rendered only while `flight` is Some for the focused conversation, placed at the bottom edge (adjacent to the input bar / activity chip — pick the §11-consistent seat and record it). Content = the flight class plus the live characteristics honestly derivable from the snapshot, e.g.:
- Inference: `⋯ inference · <agent display name> · <N chars streamed> · <elapsed>` — chars from the live tail's current size; elapsed from the tail file's age if that is honestly derivable (creation/mtime facts only — if elapsed is not derivable without a stored start time, DROP it rather than store a flag; §5.1: yog never observes a start, only the disk at this tick).
- Tools: `⚙ <tool name> · <agent> · …` (name from the step's tool records).
- Subagents: `↳ <n> children running`.
Pulse it with the existing pulse convention (theme::pulse + request_repaint_after, as the transcript InFlight tone does); an idle window renders nothing and schedules no repaint (§7.2 — None means no strip, no cost).

Everything derives per-frame from the snapshot the frame already holds — no new stored state, no second flight derivation, no per-frame disk stats outside what the snapshot/enumerate already reads (if a live counter needs a fresh stat, gather it where the snapshot is built, like bl-cad5 is doing for recency mtimes).
