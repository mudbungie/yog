Operator instruction 2026-08-01, verbatim: *"the entire config pane needs a ui overhaul. it should not just be blind editing a config file. Actually take all the settings and internalize them to appropriate interface elements."*

## Current state

The §9.1/§9.2 config surfaces are text editors over raw files (`src/config_edit/` — the brazen `config.toml` editor and the lernie-global/workspace editors over `models.yaml`/`providers.yaml`, sharing a `Draft` type since bl-52f8). The operator edits file text and Apply validates after the fact. That is the complaint: the UI knows what these settings ARE and should present each as a typed control, not a text buffer.

## The work

1. **Enumerate every setting** reachable through the config surfaces (brazen config.toml rows; models.yaml models + capabilities; providers.yaml role→provider grants; workflows/*; anything else the editors touch). The enumeration is part of the deliverable — record it in this body or DESIGN.
2. **Give each an appropriate element**: provider references become pickers over brazen's live table (the bl-bd89/bl-c3a9 `unknown_rows` judgement machinery exists — validate at input, not after); enumerated values become dropdowns; numerics become bounded fields; booleans become checkboxes; free-text stays text but scoped to the one value, not the file.
3. **Single source of truth stands**: the elements read and write the same underlying files/config commits the editors do today — no second store, no cached copy that can drift. The file remains the fact; the pane becomes a typed view of it.
4. **Raw editing as fallback, if at all**: keep an escape hatch only if some setting genuinely can't be typed; justify each such case in this body.
5. **Amend DESIGN §9.1/§9.2** to describe the pane as controls-over-facts rather than editors-over-files; update §12 rows for touched modules.

## Coordination

- The fleet clock (bl-3381) will add per-role cadence settings to this pane once it lands — design the pane so a new setting is a row, not a rebuild.
- Validation machinery: reuse `src/model_pick` grammar judgements; do not duplicate (the §9.2 Apply gate, birth-template gate, and these controls must never disagree).

## Gate

Usual: 100% coverage, line caps, no behavior change to what the configs MEAN — only how they are edited.
