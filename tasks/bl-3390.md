# Ruling to land in REMOTE §2 (the noun table)

REMOTE §2 says "Multi-server adds no noun … A workspace is one word at both
ends" — yet REMOTE's own prose uses "engine" dozens of times for the yog
program and "wall" four times for a workspace. Both are leaks past the table.

## The ruling

| Noun | Means |
|---|---|
| box | a machine |
| server | the yog process a seat dials; holds workspaces |
| workspace | the unit of conversations, one word at both ends |
| seat | lernie, an operator face |
| foot / tool host | thrall / the role |
| litany | by name only; it is a subprocess yog runs per verb and is not on the wire |
| engine, wall | retired as wire-facing nouns |

Why no role noun for litany: a role noun earns its place when more than one
thing can fill the role (seat: phone, laptop, desk) or a reader needs the
abstraction without the instance (tool host vs thrall). litany has one filler
and no wire presence; its name is clearer than any role word.

Why one word for yog: REMOTE's split is box vs program ("a home server runs
the engine"). "box" already names the machine on every consumer, so "server"
is the program a seat dials — role noun + program name, the same shape as
seat/lernie and foot/thrall.

Wall: yog DESIGN §3 defines it as the workspace's on-disk isolation boundary
(YOG_WALL) — a part of a workspace, server-side. It may keep that meaning in
yog's own DESIGN; it never names a workspace, and never appears in REMOTE.

## Scope

- REMOTE §2: add the rows above; sweep REMOTE's prose engine → server and
  wall → workspace.
- yog DESIGN: engine → server where it means the yog process; leave "wall"
  only where it means the directory.
- Consumers follow after this lands: lernie's sweep is blocked on this ball
  (a seat does not rename ahead of the protocol authority).
