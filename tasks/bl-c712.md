Deliverable: docs/DESIGN.md, a living document tracked like code. yog generalizes the current single-workspace lernie-ui-egui into a session manager: sessions correspond to balls in different repos; starting a session is cheap; every agent and subagent of every session is directly reachable; effectively all on-disk data is exposed. Brazen config (XDG config.toml, operator-owned, yog must write atomically and validate via bz --dump-config) and lernie config/workflows are manageable from the UI. Durability invariant: nothing exists only in RAM except unsubmitted input-box text — two yog instances side-by-side faithfully replicate the same data (all state on disk, fs-watched; selection/session/organization state included). Targets: linux + macos/aarch64 (the /proc probes need a portability story). Simple dependencies. The design must cover: yog's own durable state model and where it lives; the ball<->lernie-workspace binding; enumeration (XDG balls clones, per-project bl list --json); the watch/re-render loop (fs_watcher exists but is unwired); config-editing write paths; process/window model; portability of the probe layer; and the implementation epic decomposition.
