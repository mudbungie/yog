Found while verifying bl-a4e0's "DESIGN is kept in sync with the code" bullet
against the tree. Both halves are the same failure — a doc-to-code drift nothing
machine-checks — and both were left out of bl-a4e0 deliberately: the first is 23
review-worthy rows, the second is an editorial sweep bl-2368 just finished a
pass over.

**1. §12 has no row for 23 tracked non-test source files.** DESIGN §12 is the
module map and the line budgets, and AGENTS.md says "Over the cap? Split along a
real seam and add the row to DESIGN §12" — so a file with no row is a split that
never got recorded. Reproduce by expanding §12's brace spellings and
suffix-matching against `git ls-files src`. Today's list:

    src/app/memo.rs
    src/cli_outbound/{exec,resolve,stream,streamed,sys}.rs
    src/config_edit/{effects,pipeline}.rs
    src/config_edit/branch/edit.rs
    src/git_tree/{descent,detect,enumerate,lock_probe,probe_cache,probe_stack,state,tools}.rs
    src/projects/{join,runner}.rs
    src/shell/{fire,config_marks}.rs
    src/shell/config_edit/status.rs
    src/shell/acceptance/masthead.rs

Note `src/cli_outbound/sys.rs` in particular: AGENTS.md rule 3 pins every
`unsafe` in the crate to that file, and the module map does not list it.

The deliverable is either the 23 rows, or — the more elegant answer, and the one
worth attacking first — a test that makes the map an invariant the way
`tests/design_citations.rs` made citations one: every tracked non-test file
under `src/` resolves to a §12 row, both directions (a row naming a file that no
longer exists fails too). §12's own brace spellings are the parsing problem to
solve; if they cannot be parsed reliably, that is an argument for changing how
§12 spells paths, not for skipping the guard.

**2. "minted" still describes workspace names in src prose.** DESIGN §3.1 is
explicit: "A workspace name is chosen or `home`, never minted" — minting names
conversations (§3.3). The doc comments say otherwise, including in the module
that owns the question:

    src/binding/mod.rs:6,37,48,128,164   (the §3.1 names-root authority)
    src/boundary/answer.rs:237           ("ws's minted name")
    src/actions/verbs/balls.rs:120, src/app/echo.rs:67, src/app/focus.rs:65,
    src/app/derive/sweeps.rs:63, src/shell/delete.rs:186, src/shell/ram.rs:248

All are doc comments and test prose — no behaviour, no coverage impact. bl-a4e0
fixed the same falsehood in README; this is the rest of it.
