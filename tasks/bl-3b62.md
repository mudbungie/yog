DELIVERED (Marlin). The ruling at bl-9b52 Q3 turned out to need **one call site**, exactly as the ball predicted — an existing affordance re-seated, no new verb, no new config, no new flag.

WHAT WAS ACTUALLY WRONG. The §11 Login tab was already reachable from the empty world — the centre strip paints it, the navigator entry names it, Ctrl+Shift+3 presses it. Verified by probe: it painted its own H2 empty-roster sentence and **zero rows**. The cause is one line in `shell::render`: `state.focus_wall(model.focused_workspace())`. A stranger has no focus, so the frame lensed onto no wall, so `BrazenPaths::of` answered `None`, so `RealBzRunner` had no config to read and `credential_presence` had no dir — an empty roster, and the §9.1 editor beside it showing 'focus a workspace to edit its providers'. Sign-in was therefore reachable only as derived agent state after an auth-failed step (§13.3), which is the conversation-and-dead-turn cost the ruling named.

THE FIX. The wall lens now rides §3.4's `start_workspace()` — 'the where axis for a start from this instance: the focused workspace's path verbatim whenever one is focused, else `<names-root>/home`'. It is the same path whenever anything is focused; the two differ only in the empty world. This is not a new fact and not a guess: DESIGN §16.2 already rules that 'a wall is keyed by a *name*, so a hand that knows the name can lay one whenever it likes — and the empty-world start's name is not minted at all: §3.1 fixes it at the constant `home`'. A wall is pure path algebra over a leaf (no IO, nothing stored), so the sphere the next Enter founds has a wall before it has a directory. `start_workspace` was promoted `fn` → `pub fn`; `shell/mod.rs` and `shell/center.rs` are the two call sites.

WHAT THE STRANGER GETS NOW, before any dispatch: the Login tab paints brazen's shipped table (7 rows) with each row's real credential state and its real remedy, and the §9.1 brazen editor beside it is live on the same wall — so a key can be authored and an oauth row signed in, and both land in `<world>/walls/home`, which is the wall the founded `home` reads. Note the shipped table carries **no oauth2 row**, so on a default install every row's honest answer is 'set the key in Config' rather than a Login button; that is §8.3 as amended working correctly, and it is now reachable rather than discovered by dying.

ONE LINE ADDED, and it is required by the re-seat rather than decoration: the Login pane now names the sphere a sign-in lands in — 'these rows and their credentials belong to the workspace <name> — a sign-in here signs in that sphere and no other'. While this surface only ever appeared under a focused workspace, the tab bar and roster column answered 'which sphere'; with nothing focused nothing on screen does, and §16.2's whole ruling is that a credential belongs to one workspace and no other. Derived from the holder's own `workspace`, never a second fact.

F1: the reach is Ctrl+Shift+3 from inside the bootstrap box (the empty world's only keyboard state), asserted in the drive; the navigator entry's hover states the same spelling via `CenterTab::focus_hover`.

DESIGN amended: §16.2 gains 'The lens rides the START's sphere, not the focus's' immediately above the born-empty rule it qualifies; §5.1 row 19's 'no workspace in focus is no path at all' now says the frame never holds a wall-less env; §12 row for the new drive file.

DRIVE: `src/shell/acceptance/first_run.rs` — three beats: the combo from inside the box lands a populated roster with every row's fact on the glass and no empty-roster sentence; the sphere name is *derived* (a focused world names its own leaf, so the first beat cannot pass on a hard-coded 'home'); and the load-bearing one, that the roster's holder workspace and its `YOG_WALL` spawn pair are the sphere the first message founds.
