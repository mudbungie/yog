Round 2, lane swdev. yog main 5cd95986, litany =0.0.10.

## The gesture

    lernie steps <ws> <agent>
      001  complete  1 attempt  16338 tokens  commit 6b6206b0…
      002  complete  1 attempt  18091 tokens  commit e1245e31…
      003  complete  1 attempt  18477 tokens  commit 55bffada…

    lernie --json step <ws> <agent> 3

answers, verbatim:

    {"driver":{...},"kind":"step","meta":{"kind":"absent"},"ok":true,
     "request":{"kind":"absent"},"response":[],"seq":"3",
     "staging":{"kind":"absent"},"tools":[]}

`ok:true`. Every record absent. The same gesture with `003` answers the whole
step — meta.json with its commit/config_commit/workflow_commit, the 31 KB
request.json, the response, and the per-tool input/output pairs.

Confirmed at the engine too, so it is not the seat:

    yog gesture (op step, seq "3")   → every field absent
    yog gesture (op step, seq "003") → the records

## Cause

`steps_view::detail` joins the seq verbatim: `workspace/steps/<agent>/<seq>`.
The directories are `STEP_SEQ_WIDTH`-padded (`001`), so `3` names a directory
that is not there, and `Doc::of_file` on a missing file is `Absent` by
design — the classification that exists to distinguish an empty record from a
malformed one is here reporting a WRONG PATH as an empty record.

## Why it matters

This is the drill-in that round 1 called the suites strongest single
capability — the one thing neither `claude -p` nor `codex exec --json` can
answer a week later. A user who types the number they see in a numbered list
is told, with `ok:true`, that the step recorded nothing. There is no error, no
hint, and the correct answer is one leading zero away.

`lernie steps` prints `001`, so copying from the listing works; typing `3`
does not, and typing `3` is what a numbered list invites.

## Expected

Either normalise the seq to the record width before the join, or refuse a seq
that names no directory — naming the seqs that exist. Never `ok:true` with
every record absent for a path that was never opened.

## Severity

p2. Not a data loss — the records are on disk and intact — but a false
negative on the audit path, and audit is the differentiator.
