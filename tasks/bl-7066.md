Operator ruling 2026-08-13: converge toward a single branch; loose branches
are unwanted.

The tree is already in that state, and that is the problem — it got there by
luck. Right now `git ls-remote origin` is:

    refs/heads/main
    refs/heads/balls/tasks
    refs/heads/release-plz-2026-08-13T23-36-17Z

Nothing else. But twice today an agent pushed a branch to the public remote to
buy a runner verdict — `work/bl-e492` (bl-e492) and `anvil-measure-1015`
(bl-1015, "TEMP: macOS measurement (do not merge)") — and both times the only
reason the remote is clean now is that the author remembered to delete it. A
third agent who forgets leaves a branch there forever, and AGENTS.md says
nothing about it: the word "branch" appears in the publication checklist, in the
speculation-queue notes, and in the balls/tasks description, but there is no
statement anywhere of which refs are ALLOWED to exist.

**Why an agent pushes at all, and why it will keep happening.** A runner verdict
cannot be had without a ref on the remote — `workflow_dispatch` runs against a
ref that must already be there — and some defects are only visible on a runner.
bl-e492 was exactly that: five tests that passed locally 1969/1969 and failed on
CI, so pushing a branch was the only way to prove the fix before landing it. The
rule must therefore permit the probe and bound its life, not forbid it.

**The cost that makes it worth a rule.** Deleting the branch does not undo the
push. `refs/pull/<n>/head` is permanent — the public repo still serves
`refs/pull/1/head` and `refs/pull/4/head` for two branches that no longer exist.
So a pushed probe is a permanent public artifact of whatever was on it, which is
both a reason to push rarely and a reason the tree cannot be tidied later.

Write the model into AGENTS.md as an invariant with a named owner per ref:

- `main` — the trunk, and the ONLY durable line of development. Work lands by
  `bl close` squashing a claim worktree onto it; a pushed branch is never how
  work lands.
- `balls/tasks` — structural, owned by balls, not a line of development.
- `release-plz-*` — machine-owned and machine-pruned (the
  `prune-release-branches` job in release-plz.yml deletes every one with no
  open PR, right after each PR refresh).
- anything else — a PROBE, owned by whoever pushed it, deleted by them the
  moment its verdict is read. State that the verdict is the point: read it,
  land through `bl close`, delete the branch, close any PR.

Done when AGENTS.md carries that list and a reader can tell, from the doc alone,
whether a ref they are looking at is supposed to be there.
