Seen live on the 0.0.3 release (2026-08-15): the release job publishes the crate, then 'failed to create ref refs/tags/v0.0.3' with a 403 'Resource not accessible by integration' — the fresh public repository's default workflow permissions are read-only, the exact fresh-repo gap the publication checklist item 2 predicted for a different job. The v0.0.3 tag was pushed by hand to the release commit as a stopgap; the GitHub Release object was never created. Fix is a repository setting (Workflow permissions: read and write — or a finer-grained permissions: block in release-plz.yml granting contents: write to the release job, which is the narrower and better shape), which is the operator's security-posture call — this ball is the tracked decision. Until it lands every release will publish-then-fail the same way and want a hand-pushed tag.
