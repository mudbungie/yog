Operator, 2026-08-11, verbatim: *"the model selection in the yog conversation window should have both dropdowns: provider and model. … those both show up when the pane is expanded. I mean when it's not; it has model, but not provider."*

## The fact

`src/model_pick/header.rs` composes two collapsed lines from one `ConfigPoint`, and they disagree about the pair:

- `frozen_header` (the conversation's line, §11 bottom settings rows) uses `worker_model()` — the model id alone, in BOTH clauses: `model · gpt-5.4 · frozen at 1a2b3c4d · workspace default is now gpt-5.6-sol at 9f8e7d6c`.
- `birth_header` (the §11 birth block) uses `worker_pair()` — `provider · model`.

`worker_pair`'s own doc states the reason the conversation line needs it too, verbatim: *"The birth line says both, because the birth block's `change…` affordance opens a picker that writes both halves (§9.4 'the pick is a pair'), so the collapsed line has to show what the expanded one would change."* The conversation line's `change…` opens that same picker (`src/shell/model_pick/lines.rs`), scoped to the same branch write. Expanded, both dropdowns are there (bl-bd89); collapsed, half the pair is invisible — so the operator cannot read what a pick would change without opening the pane.

## The fix

One derivation, not two: `frozen_header` reads `worker_pair()` in the freeze clause and in the drift clause. `worker_model` then has no caller and goes.

Amend DESIGN §9.4's sample line (docs/DESIGN.md ~3488) to the pair form — the doc pins the verbatim sentence, so it is part of the change, not a follow-up.

Tests: `src/model_pick/tests/header.rs` asserts the sentences literally (lines 38, 51, 75, 90, 95); update each to the pair, and keep the `(no worker role)` arm as it is — no worker means no pair to name.
