The c0e2 wall exists on disk, but three GUI RAM holders do not obey DESIGN §5.3: `RAM, but per target, not per box; switching the selection switches drafts`.

Code evidence on `96d5f4e`:

- `ConfigState::rebind` replaces `BrazenEditor`; an unsaved draft in workspace A is lost after A → B → A.
- `LoginHolder::rebind` changes its world lens but retains the active `LoginRun`; A authorization output, outcome, and fallback can paint while B is focused.
- `PickerState::rebind` clears only rows and roster. It retains open, role, provider, model, custom text, status, and memo state from A, which can be acted on after switching to B.

That is both data loss and cross-wall capability theater. Add two-workspace acceptance tests that draft/start/select in A, switch to B, then return: A state must be preserved only for A, B must show none of it, and no stale selection can write B. Use one per-workspace RAM map or delete the state where the design does not promise preservation; do not keep one box and relabel it.

---

Premises verified against 86afb0c, all three true and reproduced by mutation drives:

- `ConfigState::rebind` (src/shell/config_edit/mod.rs) did `self.brazen = load_brazen(wall, ...)` — the unsaved draft in A is gone after A -> B -> A.
- `LoginHolder::rebind` (src/shell/ram/login.rs) re-seated bz/wall/creds_dir and never touched `run`, so A's streamed `bz --login` lines, outcome and fallback painted under B.
- `PickerState::rebind` (src/shell/model_pick/ram.rs) cleared only `rows` and `roster`; `open`, `role`, `provider`, `model`, `custom`, `status`, `frozen`, `birth`, `tip_providers`, `models_text` all survived the wall change.

Two corrections to the framing:

1. The lost draft is NOT the composer draft. `crate::actions::Drafts` already keys `DraftKey::NewConversation(Option<PathBuf>)` by workspace (bl-a69a), and `src/shell/acceptance/drafts.rs` already drives it — a composer draft survives a workspace switch today. The draft lost at a wall is brazen's config-editor buffer.
2. `focus_wall` runs per frame from `src/shell/mod.rs` (not only ahead of the Config re-read in `center::focus`), so all three leaks were live on every workspace switch, not just when the Config tab was visited.

One hole the ball did not name, found by attacking the fix and closed with it: the per-wall RAM is keyed by workspace path, so a workspace minted later under the same §3.1 name would have inherited a deleted sphere's box — the exact hand-over §16.2 deletes the wall directory to prevent. `ShellState::forget_wall` now drops it at §3.6's fire, with its own drive.
