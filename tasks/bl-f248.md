Seen live on the 0.0.3 release (2026-08-15): the release job published the crate and then 'failed to create ref refs/tags/v0.0.3' with a 403 'Resource not accessible by integration' — the fresh public repository's default workflow permissions are read-only, the same fresh-repo class the publication checklist item 2 predicted for the PR job. The v0.0.3 tag was pushed by hand at the packaged commit (read from the published crate's own vcs stamp, the authoritative source); no GitHub Release object exists for 0.0.3. Fix is a permissions grant: either the repository-wide workflow setting, or — narrower and better — a permissions block in release-plz.yml granting the release job contents: write. The security-posture pick is the operator's; this ball is the tracked decision. Until it lands, every release publishes then fails the same way and wants a hand-pushed tag.
