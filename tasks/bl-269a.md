## What the face actually did

`yog serve` was, in full:

    fn serve(ambient: &Env, overrides: &[(String, String)]) -> ! {
        seed_world_tools(ambient);
        let _engine = Engine::boot(…, Arc::new(NoRepaint));
        loop {
            std::thread::park();
        }
    }

There was **no signal handler**. A SIGTERM took the default action, so the
process died immediately: no `Drop` ran, the `Engine` was never dropped, its
worker/bridge/consumer/sentry/pilot threads were never stopped or joined, and
`Stream`'s drop — the one thing that would SIGTERM a piped child politely and
wait for it — never executed at all.

The GUI had the same shape and the same defect, for the same reason.

## What a stop turned out to be: the catch, and nothing else

**The change is smaller than this ball assumed, and deliberately so.** The
design question was whether the engine owed a drain of its own. It does not,
for three separate reasons, each of which subtracts a piece of the mechanism a
first design would have built:

1. **The drop already is the drain.** Every thread `Engine::boot` spawns owns
   the §7.2 shutdown shape — stop flag, park loop, a `Drop` that unparks and
   joins — and every piped child sits behind a `Stream` whose drop posts
   SIGTERM, waits a grace and escalates. An engine dropped at the end of a
   consumer pass has therefore finished the deposit it was answering and
   refused the next. Nothing had to orchestrate that; something had to stop
   *preventing* it.
2. **The bound is the unit's.** `TimeoutStopSec=30s` was already there and
   already unused; the kernel's SIGKILL at the end of it is the only bound that
   cannot be out-waited. A second deadline inside yog would be a worse copy of
   one that already exists.
3. **The substrate settles itself.** A turn in flight is a *detached* `lernie`
   driver in its own process group (§8.1) — which yog's exit has never killed
   and must not start killing. Under the unit it takes the cgroup's own SIGTERM
   beside yog's, and the pinned lernie catches that and deposits its branch's
   result with a `stopped` epitaph on the way out (lernie ARCH §2.9). yog
   neither drains nor signals a turn: it stops being in the way of one.

So a stop is: **refuse new work, finish the pass in hand, drop the engine** —
and the whole *new* mechanism is a disposition, a flag and a loop that ends.

## What landed

- `src/cli_outbound/sys.rs` — the third raw process effect, in the one audited
  home rule 3 names: `term_disposition(bool)` (the SIGTERM catch, and its
  reverse), the process-wide flag, and a handler whose entire body is one
  async-signal-safe atomic store. One function with a boolean rather than an
  install/restore pair, because `signal(2)` is idempotent and the reversing
  direction is what keeps the test that installs the real handler hermetic.
- `src/engine/stop.rs` — the mechanism both faces consult: `catch`,
  `requested`, and `Engine::park_until_stopped`, which takes the engine **by
  value** so that returning from the loop and dropping the engine are one act.
  Parking-without-dropping is now unspellable rather than merely discouraged —
  that being the defect, stated as a type.
- `src/engine/serve.rs` — the windowless face, moved whole out of the
  coverage-excluded entry file. What had kept it there was that it never
  returned; a face that parks forever is not a function a test can drive. The
  stop dissolved that, so `main.rs`'s arm is now one call and the headless face
  is under test. `world::tools::seed` went with it, the seed-and-warn policy
  now having one tested home instead of a copy per caller.
- **Both faces** (VISION V5.4). The window consults the same flag from eframe's
  loop and closes its viewport — the close a titlebar click already makes — so
  `App` drops and the engine stops down the path it already had. A drain on one
  face only would have been the second implementation V5.4 refuses. No new
  verb, flag or config key anywhere: the signal is the existing explicit signal.
- Docs: DESIGN §8.5 (the ruling), the §12 map, the signalled-with-work-in-flight
  row in the invariants table (bl-b54e's ruling covered the engine's own state
  and never covered the work), CLAUDE.md rule 3, and the unit's own comment.

## How it is tested

`src/engine/stop/tests.rs` and `src/engine/serve/tests.rs`: the loop's waiting
arm on a flag the test owns; the handler raising the flag; a **real windowless
engine** — every thread a running `yog serve` has — parked, stopped and joined
inside the test; and `Engine::serve` itself driven to completion.

One deliberate limit, recorded rather than papered over: the handler is driven
**as a function**, not by signalling the test binary. This suite runs under
tarpaulin's ptrace, whose signal bookkeeping is the very thing `tarpaulin.toml`
already pins the run serial to work around, and what a delivered SIGTERM would
prove beyond the call is `signal(2)`'s contract rather than yog's. The
end-to-end proof belongs to a drive beat over a real `yog serve`, not to the
unit suite.

## Downstream

The deployment's quiescence deferral is now an **optimisation rather than a
safety requirement** — a restart during a turn costs the turn's remaining
progress, not correctness. Relaxing it is `scripts/deploy/yog-update`'s call and
not this ball's.
