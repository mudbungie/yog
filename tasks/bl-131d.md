Selecting a child conversation (a compactor branch, or any dispatched subagent)
and asking `/agent` answers with its ROOT's token totals, byte for byte, under
an attribution that says one conversation:

    parent  agent=<root-id>          spend.tokens.total = N
                                     spend.attribution = {count: 1, kind: "conversations"}
    child   agent=<root-id>-<child>  spend.tokens.total = N   (identical)
                                     spend.attribution = {count: 1, kind: "conversations"}

The `agent` field on the reply correctly names the child, so the row is about the
child; the spend beside it is about the tree. An operator asking "what did that
subagent cost me" is answered with a number that is not the subagent's, with
nothing in the reply saying so.

Observed twice on this drive, once per conversation that ran a compactor: both
children reported their parent's totals exactly.

If the intended rule is "spend is a property of the conversation tree, and a
child is not a conversation", then the reply is arithmetically right and
editorially wrong — `attribution.count: 1` invites the reading that this is the
one selected thing's cost. The §3.5 spend fold is the single source and should
stay so; what is missing is the reply saying whose fold it is.

## Shape of the repro

    …run any conversation long enough to trigger a compactor…
    yog gesture --ws <ws> --agent <parent> '/agent'
    yog gesture --ws <ws> --agent <child>  '/agent'
    # spend.tokens identical; agent differs

## Candidate answers

- The child's own step tokens, folded over that branch alone.
- The root's fold kept, with the attribution naming the root it is the fold of,
  so the number is not read as the child's.

Either settles it; the present reply settles nothing, and the operator cannot
tell which of the two they are holding.
