## The failure

CI is red on `main` and has been for 4+ consecutive pushes. The `linux` job
passes; the `macos` job (macos-14: `cargo build --locked` then `make test`)
fails:

```
Running tests/stories_s1_t3.rs
test s1_t3_message_stop_scan_argv_and_ops_trail ... FAILED
thread 's1_t3_message_stop_scan_argv_and_ops_trail' panicked at
tests/stories_s1_t3.rs:57:5:
each verb runs cwd = ws
test result: FAILED. 0 passed; 1 failed
make: *** [test] Error 101
```

The assertion at `tests/stories_s1_t3.rs:57` is:

    assert!(inv.iter().all(|i| i.cwd == ws_s), "each verb runs cwd = ws");

where `ws_s` is `tempdir()`'s path as a string and `i.cwd` is what the fake
recorder script (`tests/support/mod.rs`) captured via `$(pwd)` in the spawned
child.

## Why it blocks everything

`.github/workflows/release-plz.yml` (bl-e2b5) gates its release job on the `CI`
workflow concluding `success` on `main`. While macOS CI is red, yog can never
cut a release. Release PR #1 ("chore: release v0.0.1") is open and waiting.

## Hypothesis to verify (do not assume)

macOS-only path canonicalization: `tempfile`'s dir lives under
`/var/folders/...`, and `/var` is a symlink to `/private/var`. The child's
`pwd` reports the physical path; the test's expected string is the logical one.
Two strings, one directory, string compare fails.

## Required shape of the fix

Canonicalize BOTH sides of the comparison rather than `cfg!(target_os)`
branching or weakening the assertion ("a special case is usually a missing
reframe"). Do NOT delete or `#[ignore]` the test. Audit sibling story tests for
the same recorder-cwd comparison (`tests/stories_s2_t1.rs` also compares
`inv[0].cwd`), since the run aborts at the first failing binary and later ones
never executed.
