Round 1, devadmin lane, hit at step 0 of every scenario.

GESTURE

    lernie start ops "say hello"
    {"error":"sign in first: no provider in this workspace's wall holds a
     credential, so a conversation begun here would reach no model —
     /login <provider> (rows: anthropic, openai, ..., claude-code,
     openai-chatgpt)","ok":false}

Good refusal. So write the workspace a brazen config, which is the door
`/config brazen` exists for:

    lernie ask '{"op":"config","target":{"file":"brazen","workspace":"ops"},
                 "text":"<a valid brazen config.toml>"}'
    {"error":"No such file or directory (os error 2)","ok":false}

That is the whole message. No path, no file, no hint which of the several
files in the act it means. The same sentence comes back from `yog gesture --ws
ops "/config brazen <text>"` on the box itself.

CAUSE

`BrazenPaths::in_wall` puts the file at `<wall>/brazen/config.toml`, and
`config_edit::draft::Draft::stage` writes a temp file beside it.
`<world>/walls/<name>/brazen/` is never created — on a world where no
conversation has ever run, `<world>/walls` does not exist at all. The io error
is surfaced through `Applied::Io { error: e.to_string() }`, which is the bare
`std::io::Error` display and carries no path.

    $ mkdir -p <world>/walls/ops/brazen
    $ lernie ask '{"op":"config","target":{"file":"brazen",...},"text":"..."}'
    {"kind":"applied","ok":true}

One `mkdir -p` and it works.

WHY p1

It is a hard wedge on a fresh install with no way out from any interface a
person is offered. The provider door refuses the start, `/config brazen` is
the act that lifts it, and the act cannot run until a conversation has run.
`/login` does not lift it either: the wall`s row set is whatever brazen`s own
default table has, which on this box did not include the provider the operator
actually has a credential for. The only escape found was to reach into the
engine`s private data root with `mkdir` — which no operator should be asked to
do and which is not documented anywhere.

Two defects, and both are worth fixing:
1. the write must create its parents (or the wall must be made when the
   workspace is);
2. `Applied::Io` must name the path it failed on. `No such file or directory
   (os error 2)` with no subject is the least actionable sentence in the tree,
   and it is the one an operator meets first.
