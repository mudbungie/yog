An auth-shaped step failure offers Login without saying **which provider row** to log in to, so the one-click remedy is a guess against brazen's whole table.

## Evidence (conversation `ladies`, dev workspace, 2026-08-07)

`steps/<agent-id>/{009,010}/response.json`:

    {"type":"error","kind":"auth","message":"borrowed OAuth credential is expired; refresh it with the tool that owns it","provider_detail":null}

`login::auth::AUTH_MARKERS` contains `"credential"`, so `is_auth_failure` fires and the affordance paints (§8.3, "also offered beside an auth-failed step"). But brazen's line carries no row (`provider_detail` is null), and `StepsView`'s flag is a bare `auth_failed: bool` (`src/steps_view/mod.rs:72`), so nothing downstream can name the row or preselect it.

The remedy here was exact and permanent: `bz --login --provider claude-session-direct` mints an **owned** credential, and owned beats ambient (`brazen/src/auth/mod.rs:149-163` — store first, `discover` only as fallback), which retires the whole borrowed-expiry class for that row. The operator could not tell that from the banner.

## The derivation (no new stored fact)

The row is already on disk twice over:

- the failing step's `request.json` carries `model`;
- `fork::roles_at(workspace, refspec)` (`src/fork/mod.rs:266`) reads the governing config commit's `providers.yaml` `roles:` block as `Vec<RoleModel>` — role, provider row, model id — through §9.4's own grammar reader.

Match the request's model id against the governing roles; the matching role's `provider:` is the row. One file read on the failing step only (framing == Failed), never per frame. No match (a drifted or custom id) yields no row and the banner keeps today's generic wording — absent data is a value, never a branch.

## Deliverable

- `StepsView`'s login flag carries the row instead of a bool.
- The inline banner and the Steps row name it: "claude-session-direct's credential expired" + a Login that runs that row directly, no pane, no picking.
- The Login pane, opened from that affordance, opens scrolled to that row.
- DESIGN §8.3 amended: the affordance beside an auth-failed step is row-named, and where the row comes from.
