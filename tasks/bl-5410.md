Found by Larkspur while sweeping bl-36c3 (re-audit of paint-layer assertions). **Measured, not read** — the evidence is `src/shell/acceptance/legible.rs`'s predicate run over the shipped frame.

## The predicate that found it

`paint_probe::seen_of` now hands back, per galley, the laid-out glyphs, the rect they were laid into, and the part of that rect the clip let through. A run whose **shown width is narrower than its laid width** is one the operator reads the front of and no more — and because the galley was never *truncated*, egui never added the `…` that would say so. That is QUALITY §1 **G1**'s defect exactly: not that text is cut, but that it is cut **silently**.

## Root cause, one line

DESIGN §11 rule 1 (`TextWrapMode::Truncate`) is set at the **side panel's** root (`src/shell/navigator.rs:33`), the flight strip (`flight_strip.rs:47`), the inbox queue (`inbox_queue.rs:130`) and inside `row::control_last`. **Nothing sets it on the centre**, the top bar or the activity panel — egui's default there is `Extend`. So every horizontal label in those seats is laid at its natural width and sliced at the container's edge, mid-glyph, with no marker. Rule 1 is a side-panel rule that reads like a window rule.

## What bl-b531 does NOT cover

bl-b531 is scoped to the documented 420x320 minimum. These are at **800x500** — an ordinary half-screen, the audit's own default capture size:

```
"Declare" laid 43 pt, 26 pt shown                                  (Config tab)
"bearer-token provider — set the token in Config" laid 268, 210    (Config tab)
"built-in provider rows are compiled into bz and are not shown in
 this file (the Login provider list shows them)" laid 565, 524     (Config tab)
```

`Declare` is a **control** (`src/shell/config_edit/lernie_pane.rs:145`), cut to its first three letters' worth of pixels. §11 rule 1b keeps a control from being *elided* by the greedy text beside it; nothing keeps it from being *clipped away* by its seat, and the two are the same loss to the operator.

`built-in provider rows …` is `crate::config_edit::brazen::BUILT_IN_ROWS_HINT` (`src/config_edit/brazen/mod.rs:100`).

## And the shape that is strictly worse than an unmarked cut

At 420x320, Login tab:

```
"auth none…" laid 68 pt, 36 pt shown
```

The galley **was** truncated — egui added the `…` to say the row was cut — and then the clip cut the ellipsis off too. The marker that exists to prove elision is itself elided. Everything a G1 assertion could look for is gone.

## The assertion that is already landed

`src/shell/acceptance/legible.rs::nothing_is_cut_without_an_ellipsis_at_any_window_size` sweeps the whole window at four sizes × trail open/closed × four centre tabs, and its sibling does the six inspector tabs. It is **one-directional**: no run may be cut that is not on a `KNOWN` list naming the ball that owns it. Every entry in that list carries either `bl-b531` or **this ball's id** — so closing this one means deleting its entries, and the list stays honest by construction.

Both were proved to bite: a planted wide label in the top bar reported

    "MUTANT a planted run far wider than the top bar can show at a small window"
    laid 428 pt, 412 pt shown — at 420x320

and **no other test in the tree noticed** (1874 of 1876 green).

## Fix shape (not prescriptive)

The severable answer is to state rule 1 where it is true rather than where it happens to be inherited — the same move `row::control_last` already made for rule 1b (bl-bc06's second shape: *"the helper states the whole rule itself and depends on no ambient state"*). Attack it first: a blanket `Truncate` on the centre would also truncate every **control** there, which is the defect rule 1b exists to stop, so it is not one line.
