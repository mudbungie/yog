Found during UX testing, 2026-07-27 (the operator), on his live instance.

## Observed

Five detached prompts fired in one short session; five zombies, all parented to
the live yog:

    $ ps -o pid,ppid,stat,comm -p 4083036,4084632,4084686,4089731,4090427
        PID    PPID STAT COMMAND
    4083036 4082900 Z    yog
    4084632 4082900 Z    yog
    4084686 4082900 Z    yog
    4089731 4082900 Z    yog
    4090427 4082900 Z    yog

One per `lernie prompt`, exactly. They stay until yog exits.

## Why

`src/cli_outbound/detach.rs:62`:

    // `child` is dropped here WITHOUT wait or kill: a bare
    // `std::process::Child` drop orphans, it does not signal. The
    // process survives us — that is the whole point.
    Ok(child.id())

The comment is right about signalling and wrong about orphaning. Dropping a
`Child` does not detach it from the process table — yog remains its parent, so
when the driver exits it becomes a zombie yog never reaps. It only reparents to
init if *yog* dies first. Detachment (`process_group(0)`, null stdio, no
retained pipe) is what makes the driver survive yog's exit, and that part
works; reaping is a separate obligation nobody discharges.

A long UX session or a busy operator accumulates one PID per fire indefinitely.

## Fix direction

Two shapes, pick the elegant one:

1. **Double fork** — the child forks its own grandchild and exits immediately;
   yog reaps the short-lived intermediate, init adopts the driver. Real
   detachment, but it costs the returned pid (`spawn_detached` returns
   `child.id()`, and the grandchild's pid is not it) — check who consumes that
   pid before choosing this.
2. **Ignore `SIGCHLD`** (`SA_NOCLDWAIT`) — the kernel reaps automatically, one
   line, no fork dance. But it is process-global and would also change how the
   *piped* `Cli::run` path's children behave, so it must be proven against
   `run`/`Streamed` (`src/cli_outbound/mod.rs`) before adoption.

Whichever lands: the `unsafe` location rule pins every `unsafe` to
`src/cli_outbound/sys.rs` (`rules/no-unsafe-outside-sys.yml`, AGENTS.md rule 3),
so any raw syscall goes THERE, not in `detach.rs`.

Also fix the misleading comment at `detach.rs:62-64` — it currently asserts the
bug is the intended behaviour, which is how it survived review.

## Acceptance

A test that fires a detached spawn, waits for the child to exit, and asserts no
zombie remains parented to the test process.
