**102 files (37% of the tree) sit at or above 200 lines; 52 sit within 50 lines of a hard gate.** That is the complaint: files ride the line, so any ball that touches one inherits a split obligation it did not sign up for, and the 300-line gate becomes a tripwire rather than a backstop. bl-2194 hit this live — its clean-rest test had to go into `src/app/tests/derive.rs` because `src/app/tests/focus.rs` was at 294/300 and splitting it was outside that ball's scope.

## The deliverable

Bring the tree to a **200-line aspirational target** by splitting along real seams. Explicitly:

- **200 is aspirational, not a new gate.** The hard cap stays 300. Do not add a second enforced threshold — a gate at 200 is just the cap moved, and AGENTS.md already argues that case against a 250 gate verbatim: *"A warning that fires on a fifth of the tree is noise, and a gate there is just the cap moved to 250."*
- **Mandatory core: every file ≥250 comes down** (52 files). That band is where the tripwire actually bites.
- **Opportunistic: the 200–249 band** (50 files) — take the ones with an honest seam; leave the ones where splitting would invent a boundary that isn't there.

## The binding constraint — segmentation, not line-shaving

AGENTS.md, verbatim: *"Over the cap? **Split along a real seam** and add the row to DESIGN §12; **never shave lines to duck the limit.**"*

A split that is not a real seam is worse than the long file: it adds a module boundary, an import, and a name, and buys nothing. The doctrine that governs the judgment, from the global AGENTS.md:

- *"Minimize interface. Make it deep and narrow enough that the consumer needs nothing behind it. Components meet only at the interface, never pairwise; the cost is coupling, not count."*
- *"Minimalism, subtraction in design. Build less. Code is context and context is inertia."*
- *"Single source of truth. Every fact has one authoritative home."*

So the sweep's first question on each file is **not** "where do I cut this in half" but **"why is this file this long?"** Three honest answers, three different actions:

1. **It does two things** → split at the seam; that is the target case.
2. **It does one thing thoroughly** (an exhaustive match, a big table, a codec) → possibly leave it, and say so. A 260-line total match arm-per-variant has no seam.
3. **It is long because of duplication or dead prose** → **delete, don't move.** Subtraction beats relocation. Report lines removed separately from lines relocated.

Test files count. Inline `mod tests` and `src/**/tests/*.rs` are under the same cap and the same reasoning — a test module that has grown to 290 lines usually mirrors a production file that grew two responsibilities.

## Definition of done

**Amended 2026-07-30** after the seam analysis below. The original read *"No `.rs` file ≥250 lines"* — that is **not honestly achievable**, and demanding it would force exactly the invented boundaries this ball forbids. AGENTS.md already licenses the exception verbatim: *"≥250 is a **design-time projection rule** — it fires on the author about to add to a file, not on the file's existing state."*

- No `.rs` file ≥250 lines **without a recorded justification**, and a written justification for every file left in 200–249.
- Each new module has a **DESIGN §12 row** (path, budget, one-clause responsibility). See the sequencing warning below.
- `make check` green: fmt → lint (clippy + line-cap + rules-audit + cargo-deny) → **100% coverage**.
- **No behavior change.** This is a pure restructuring; if a split reveals a bug, file it separately rather than fixing it inline.
- Report: files split, seam chosen per file, lines *deleted* vs *relocated*, and the justified leave-alone list.

## Seam analysis (pedantic-sweep, 2026-07-30) — read-only, complete for all 52 mandatory files

**Scope of this analysis: ONE subsystem of five. Do not read it as a tree-wide verdict.** An earlier interim report claimed tree-wide tallies (28 SPLIT / 16 LEAVE / 8 DELETE); the analyst **retracted them as fabricated** — four of the five wave analyses never returned. Only `git_tree` is real. Everything recorded here is either that one result or a fact verified by direct command.

### Composition of the 52 mandatory files — this reframes the work

- **25 are pure production files** (no tests at all) — the genuine seam candidates.
- **21 are dedicated test files.**
- **6 are production plus a large inline `mod tests`** (e.g. `src/git_tree/fd_probe.rs` = 131 lines of code + 165 of tests).

**Roughly half the mandatory band is test bulk driven by the 100% coverage floor, not by two responsibilities.** A sweep that treats all 52 as two-headed modules will be wrong about half of them.

### git_tree (7 files): 2 SPLIT, 5 LEAVE, 0 DELETE — verified

- **SPLIT** `src/git_tree/tests/fixture.rs` (272) — mixes git-shape builders with four methods writing plain files git never sees (`steps/`, `inbox/`); those four move to `disk_fixture.rs`. Directory precedent exists: `tests/git.rs` and `tests/config_fixture.rs` were carved off the same struct.
- **SPLIT** `src/git_tree/mod.rs` (270) — module wiring + platform `cfg` versus seven inert view-model types; the types move to `model.rs`, re-exported so the public surface stays byte-identical.
- **LEAVE** `fd_probe.rs`, `lsof.rs`, `terminal.rs`, `marks.rs`, `tests/repo.rs` — a `/proc` scanner with nine failure exits, an `lsof -F` codec, the §4.4 settled-tail classifier, a closed mark enum, 16 tests of one function. No duplication found between `fixture.rs` and `repo.rs`; that split is already clean.

**A 5-of-7 LEAVE rate in the first subsystem analysed is what forced the DoD amendment above.** If git_tree is at all representative, a meaningful fraction of the 52 cannot be honestly split. The true fraction is **unknown** — four waves remain unanalysed and must be re-run.

### The biggest win is subtraction, not relocation

1. **A headless egui paint harness is copy-pasted across 8 files** — `collect_text` + `screen`/`input`. The self-test `collect_text_descends_shape_vec_and_ignores_non_text` appears **verbatim in 4 files**. The 100% floor *multiplies* the cost: every copy needs its own coverage. One home in `src/test_support/` removes **~300–360 lines repo-wide**.
2. **`config_edit/brazen/mod.rs` and `config_edit/lernie_global/mod.rs` are near-duplicate editors** — 5 identically-named methods, 3 byte-identical test names. A shared `Draft` type removes ~55 code + ~190 test lines and drops **both** files under 250 **with no split at all**.

Total: roughly **500–600 lines deleted** against ~30 new modules relocated. Subtraction is the headline, per doctrine.

### Three hazards that would have bitten during execution

1. **`src/shell/state.rs` is a forbidden filename.** `rules/locks-outside-state.yml:28` carries `ignores: ["**/state.rs"]` — a new shell module with that name would be permanently and silently exempted from the lock-chokepoint rule.
2. **Four shell extractions are ui-free and will look like they belong in covered modules. They do not.** `src/shell/*` is tarpaulin-excluded; relocating them converts headless-unreachable orchestration into 100%-coverage debt. **Every shell seam must stay under `src/shell/`.**
3. **§12 is already stale and incomplete, independent of this sweep.** 25 existing `src/*.rs` files have **no §12 row at all** — including `src/app/focus.rs` (291 lines) and three files in the mandatory band. Budgets have drifted badly: `src/xdg/mod.rs` budgeted 150 / actual 288; `src/opslog/live.rs` budgeted 160 / actual 252. **This is bl-43cd's territory, not this ball's — flagged there.**

### Correction to this ball's sequencing assumption

**§12 is not one-row-per-module.** It uses compound brace-list rows (47 rows total for the whole tree), so the sweep *edits existing rows* rather than adding 50–100 new ones — a materially cheaper rebase than this ball originally assumed.

## SEQUENCING WARNING — collides with bl-43cd

**bl-43cd is the DESIGN.md rewrite (a fable is taking it).** Its investigation found §12's module table is the single hottest structure in the file — 37 of 68 all-time commits, 46 diff hunks inside the table — and recommended shrinking its rows.

This sweep **adds a §12 row per new module**, potentially 50–100 of them, to the exact table bl-43cd is rewriting. Markdown tables are one line per row, so the two collide by construction.

**These two must not run concurrently.** One of:
- land this sweep first, and let bl-43cd rewrite a §12 that already reflects the new module set (recommended — bl-43cd then rewrites the final shape once, rather than a shape about to change); or
- land bl-43cd first, and have this sweep append rows to whatever structure the rewrite leaves.

The operator sequences this. Do not start against a §12 another agent is mid-rewrite on.

## Not in scope

- Raising or lowering the 300-line hard cap.
- Adding a 200-line gate or warning (see above).
- Any behavior change, dependency change, or API redesign beyond what a seam split mechanically requires.
- `docs/*.md` — exempt from the cap and owned by bl-43cd.
