REMOTE §8.2 (bl-aaec): the host half of provisioning an entry is minting a
client leaf for the visiting box under a stated common name. Today
`src/wire/provision.rs` mints exactly the three `LEAVES` roles
(server/client/window) with fixed common names; there is no way to issue a
fourth leaf without raw openssl.

What to build:

- `src/wire/provision/openssl.rs`: the leaf recipe derives basename+CN from
  a `Role`; add the spelling that takes a stated CN outright and writes
  `<cn>.pem`/`<cn>.key` (basename = CN). Refuse a CN that is not a single
  path component, and refuse the reserved identities the registry refuses
  (`local`, `.`, `..` — REMOTE §4.1's rule, one rule not three cases).
- `src/wire/provision.rs`: `pub(crate) fn issue(dir: &Path, cn: &str) ->
  Result<(), String>` — refuses when `ca.key` is absent (a client box
  cannot issue; REMOTE §8: the mint never replaces an operator's trust
  root) and refuses to overwrite an existing pair (re-issuing distrusts
  nothing, so a fresh CN is the remedy; rotation stays the verb's FORCE
  over the whole dir).
- `src/wire/provision/verb.rs` + Makefile: `yog wire-certs` gains
  `WIRE_LEAF=<cn>` — when set, issue ONLY that leaf and print its two
  artifact paths; no CA creation, no address write, no other leaves. Keep
  the client-leaf recipe identical to `Role::Client`'s (the client leaf
  carries no host SAN; check openssl.rs, only the server leaf does).
- Docs: REMOTE §8.2 already cites this ('the one recipe, one more artifact
  it can be asked for'); amend REMOTE §8's mint-interface list
  (WIRE_DIR/WIRE_HOST/WIRE_PORT/FORCE) to include WIRE_LEAF. Note in the
  verb's help: on the client box the pair is placed into
  `wire/workspaces/<leaf>/` under the basenames `client.pem`/`client.key`
  — the CN inside, not the basename, is the identity.

Tests: provision/tests.rs pattern (real openssl at test runtime; a
certificate fixture is never committed): refusal without ca.key, refusal on
an existing pair, CN validation, issue-then-read via `material::read_dir`
against a scratch dir laid out as an entry.

Independent of the entries reader (bl-5b68); an operator can run it before
any code reads entries.
