RULING (Marlin): **the §11 altitude-1 header's chip is the one seat for the class in words; the in-flight strip keeps only the characteristics and hovers the sentence.**

The premise held — both seats still painted `theme::flight_badge`'s whole sentence, in the same hue, in the same frame, on the one conversation surface. Two facts decided which seat keeps the words, and neither is a preference:

1. **The header is unconditional; the strip is not.** `shell/pane.rs` gates the strip on a §11 rule 5 share (`layout::share(pane, …).is_some()`) and `flight_strip::render` returns early on `None` — its own documented rule is 'the panel itself is conditional, not its content'. A fact seated only there disappears at the documented 420x320 minimum. The header row has no such gate.
2. **The strip's line is width-bound and truncates** (`wrap_mode = Truncate`, its own §11 rule 1 comment), and its unique payload sits at the *tail*. So the duplicated 40-character prefix was pushing 'N chars streamed · 5s' — the only thing bl-905f built this seat for — off the right-hand edge. Removing the prefix buys back exactly the payload.

Supporting: bl-905f's own ruling says 'the inference status at the top is right as far as it goes' and adds the strip *for the characteristics*; and the §11 badge-seat pattern already has an answer for a width-bound seat — the conversation list row states the glyph and hovers the words. The glyph is not left as the class's only carrier: the characteristics beside it are the class stated concretely ('320 chars streamed' IS a model call streaming, 'Read' IS a tool executing, '2 children running' IS a descent working), the hue is the class's own, and the sentence is now the first clause of the strip's hover.

SECOND DUPLICATION, also fixed: the strip's `<who>` segment named the member doing the work — which for a root-only conversation is the conversation itself, whose §3.3 display name is the pane heading two lines above. `<who>` is now painted only for a member that is **not** the conversation root, which is the case the segment was added for (a dispatched child streaming under a quiescent root) and the only case the heading cannot cover.

MECHANISM: `Facts.says` became a `Vec<String>` of segments joined once at the end. Every segment here was already independently omittable (unparsable tool name, unstattable record, and now `<who>`), and a joined string forced each omission to be spelled as a branch that also knew about the separator — the list dissolves that. It also makes the empty case expressible: a class contributing no segment at all (a tool call this snapshot can neither name nor time, on the root) yields no strip, which is the seat's existing 'the panel is conditional' rule read one level in, not a new case.

DESIGN amended: §11's 'A third seat' passage (the state-outright claim, the three per-class line shapes, the `<who>` rule, the hover, the new no-segments clause) and §5.1 #28 (which seat states the class in words).
