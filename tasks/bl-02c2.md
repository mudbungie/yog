bl-8da1 landed the VISION §4.9 monitor's **tier 0** whole: arming as a `cadence.yaml` `monitor:` entry (`/arm <model>` / `/disarm`), the bounded tool-less check through the embedded brazen adapter, the level trigger off the step spine (its own thread, one check per tick, only when a branch tip moved), the one `ops.jsonl` row per check, the standing verdict rendered per conversation, and `Flag` as a boundary Action variant. Ships **flag-only by default** and, deliberately, **fires nothing automatically**: a verdict today is a rendered fact and a trail row, nothing more.

This ball is the ladder — the verdict→response tie-point (§5 logic board) VISION §4.9 rules is config, never code. Do not start it before the calibration the design close-out asks for: measure verdict quality against operator judgement using the `yog-monitor` ops rows already accumulating. A false `diverged` that fires visibly is the thing that teaches an operator to distrust the monitor.

Scope, per VISION §4.9's two shapes:

1. **DIRECT wiring** — a `cadence.yaml` row mapping a verdict to one existing verb, fired mechanically. `flag` (write the attention row from the verdict), `notice` (`lernie message` — OFF by default; it reveals the monitor to the agent, inviting the obfuscation result), `stop` (the existing verb). yog executes a config row and decides nothing.
2. **HOOKED wiring** — a verdict dispatches a **responder**: an ordinary lernie worker on an operator-named workflow, its goal carrying the flagged window, its granted tools yog's boundary verbs through the world tool shims. Tool selection IS ladder selection; no rung executor in yog. **Floor grant is `flag` alone** (bl-7aef) — every grant beyond it is the operator's deliberate wiring, because a responder reads attacker-influenced content while holding real verbs.
3. **The shim gap, verified at bl-8da1's implementation:** `world/tools/` seeds `bl`, `lernie`, `bz`, `bl-delivery`, `bl-tracker` — **there is no `yog` shim**, so a responder cannot call `yog gesture` today. The floor grant needs one (`world::tools::ROSTER` + `Binary::Yog`), and that is the first rung of this ball, not an afterthought.
4. **The attention hook.** DESIGN §6 records the seam and why it is not yet a sixth rule (calibration). Wiring the standing verdict into the attention predicate — seen-gated on the checked sha, exactly as rules 1–4 are seen-gated on their oids — belongs here, after the measurement.
5. **The spend fold.** VISION §4.9 says §4.5's join folds monitor ops-row usage into the watched conversation's cost. The rows carry `model` and both token counters already; the join does not read them yet.

Explicitly NOT here: revoke-auto-approval. That waits on bl-0cea's capability ruling — when it lands, an alignment verdict becomes one input to the capability policy.

Also decide explicitly (the recorded concern): whether armed monitoring covers responders themselves. They are ordinary agents in the workspace, so the uniform answer is yes, and today's implementation already gives that for free — the level trigger checks every agent in an armed workspace's tree, responders included. Keep it uniform.
