Rule 4 says that assert!, assert_eq!, and assert_ne! are banned in production while debug_assert! is fine. rules/no-assert-outside-tests.yml contradicts that authority: its regex also matches debug_assert!, debug_assert_eq!, and debug_assert_ne!, and its commentary calls all six macros test-only. The source tree currently has no debug assertions, so rules-audit cannot expose the conflict.

Resolve toward the documented standard. Narrow the rule and commentary to the three unconditional assert macros. Add rule fixtures proving that all three unconditional forms still fail in production and all three debug forms pass there while test carve-outs remain intact.

Debug assertions run only when cfg(debug_assertions) is enabled. They preserve cheap development-time invariant checks without adding release-build panic paths.

Acceptance: make rules-audit and make check pass.
