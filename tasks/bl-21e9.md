Round-1 daily lane. yog 0.0.38 (main c7916da1), seat lernie 0.1.30.

The second workspace of the day cannot start a conversation, and the remedy it is given does not name the row the operator is actually using.

Gesture — `prepare` into a workspace that does not exist yet, then `prompt`:

    {"kind":"prepared","ok":true,"prepared":{"binding":"<repo>",...,"workspace":"proj"}}
    {"error":"sign in first: no provider in this workspace's wall holds a credential, so a conversation
      begun here would reach no model — /login <provider> (rows: anthropic, openai, mistral,
      openai-responses, google, ollama, claude-code, openai-chatgpt)","ok":false}

The refusal itself is very good: it fires BEFORE the conversation is minted, it names the cause, and it names the verb. Two things sit behind it.

1. **The list is brazen's built-in floor only.** This box's operator row is `claude-session-direct`, defined in the user's own `brazen/config.toml`. `lernie providers home` — a workspace whose wall has that config — lists it, "auth oauth2 · signed in". `lernie providers proj` — a newborn wall — does not list it at all. So the row the workspace's own `providers.yaml` names for `worker` is missing from the list of rows the refusal offers, and `/login claude-session-direct` would be a login for a row the wall cannot resolve. The operator is offered eight rows, none of which is the one their config uses.

2. **The per-workspace cost is paid per workspace, forever.** §16.2's blast-radius ruling is the reason and it is a good reason; what it does not come with is a way to say "this workspace signs in the way that one does". Every new workspace is a fresh sign-in, and this lane's workaround was to copy `config.toml` and the credentials directory into `<world>/walls/<name>/brazen/` by hand — which is what `scripts/drive/wall.sh` does for the drive harness, and which no operator-facing surface offers.

The costliest shape is the config half: a wall with no `config.toml` cannot even OFFER the row, so no amount of signing in from the seat reaches it. The row table has to arrive by a file copy, which is out of channel, undocumented outside the drive harness, and not something the refusal above hints at.

Expected: at minimum the refusal distinguishes "no credential for a row that exists here" from "the row your roles name is not declared in this wall at all", because the remedies are different and only one of them is `/login`. Better: a seat gesture that seeds a new wall's row table from an existing workspace's — the one act every second workspace needs.

Severity p3: it is a wall, not a defect; it is hit by everyone on their second workspace, and the sentence they are given points somewhere that will not help.
