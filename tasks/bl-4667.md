The top-level help promises: `Every command answers --help.` The shipped command matrix disagrees.

`serve`, `seat`, `wire-certs`, `env`, `exec`, `gesture`, `lernie`, `bl`, and `bz` all answer `--help` with exit 0. `yog tool-host --help` instead exits 2 and says it takes no arguments. `yog help tool-host` is the workaround.

This regresses bl-52ed, whose governing text is: `bl-0ec2 required help to be higher-order and world-free: every command must answer --help in place.` It also required: `Add per-namespace zero-side-effect tests.` The later-added `tool-host` was absent from that roster, so the invariant regressed without a failing matrix.

Expected: exit 0 with a short tool-host usage page, matching `serve` and the declared every-command discovery invariant. Extend the roster test from a fixed historical list to the authoritative current command definitions so a new command cannot fall outside it silently.

Diagnosis from a parallel claim attempt (Help4667, refused seconds after your claim) — offered so the work is not redone.

WHY tool-host is the odd one out: src/multiplex/help.rs answer() intercepts help above the router but bails for any word in the router table (Namespace::from_arg(word).is_some() -> return None, 'the arm answers'). tool-host sits in NAMESPACES (src/multiplex.rs, (wire::HOST_SUBCMD, Namespace::ToolHost)) purely for routing — it owns no argv grammar. Its arm (src/wire/host.rs) rejects ANY first arg with usage exit 2, so the pass-through hands --help to a command that accepts no arguments. Every other namespace really owns its argv (bl/bz/lernie via their clap surfaces; gesture/seat via boundary::sugar::argv::read_gesture, which rewrites --help into Gesture::Ask(Query::Help)). A page already exists and is unreachable at the command: HelpRow { verb: HOST_SUBCMD, usage: 'yog tool-host', … } in src/multiplex/help.rs, reachable only via 'yog help tool-host'.

WHY bl-52ed's tests missed it — sampling, two places in src/multiplex/help/tests.rs: every_yog_subcommand_answers_at_the_command iterates a hardcoded four (SERVE/ENV/EXEC/control) and also misses wire-certs; a_namespace_help_is_the_tools_own_and_falls_through iterates a hardcoded six — seat and tool-host postdate both lists.

SUGGESTED SHAPE: (1) give Namespace an exhaustive-match predicate owns_argv(self) -> bool (ToolHost => false, rest true) so an added variant cannot compile unclassified; help::answer bails only on is_some_and(Namespace::owns_argv), so tool-host --help falls to page(word), exit 0 above the router, no world, no dial. (2) Replace both sampled loops with enumerations over COMMANDS and NAMESPACES — that combination fails on tool-host today and picks up seat/wire-certs for free. Regression home: tests/multiplex_seat.rs already pins dispatch(['yog','tool-host','--follow']) == Some(2); the --help -> Some(0) case belongs beside it. Checked non-issue: world::compose is pure env folding, so the seat/tool-host arms composing a world on the help path write nothing — the defect is only the argument rejection.
