Upstream lernie **bl-79a2** (delivered `9d0c0ea`) changed the agent-name mint from one lowercase word to two words in PascalCase — `PeachHollow` — drawn from a widened index space of 541 x 540 = 292,140 ordered distinct pairs. One RNG draw per mint, same pure scan, same exhaustion bound.

yog links `lernie::mint::mint` directly (`src/start/identity.rs`) and draws it at both preview and fire, so it inherits the new shape with no code change. Verified at filing time: **no yog test pins a literal minted word** anywhere in `src/` or `tests/`.

The work is therefore: bump the `lernie = "=x.y.z"` pin in `Cargo.toml` (the pin authority — no version is restated here, per CLAUDE.md rule 6) to the release carrying bl-79a2, refresh `Cargo.lock`, and run the gate.

**Blocked until that release exists.** lernie 0.0.10 is the current pin and bl-79a2 sits on lernie `main` unreleased. Do not take an interim git/rev pin for this — CLAUDE.md rule 6 permits it only as a last resort with a named exit, and it re-blocks `make publish` because crates.io refuses git deps. Wait for the registry version.

Check on bump, since the brazen parity constraint is real: `Cargo.toml` documents the lockfile as the parity check that yog and lernie resolve ONE brazen ("skew death"). A lernie bump that moves brazen must keep that single resolution.
