From the 2026-07-27 UX-testing session (the operator), verbatim:

> everything that is currently a one-key alphanumeric command should have a
> paired combo. We want to preserve standard combos as much as possible
> (ctrl+w to close something, ctrl+n for a new something, etc)

## Why it matters

DESIGN §11 already explains why bare letters are lawful here: bindings are
"suppressed while a text box holds the keyboard … so typing never steals them",
and `Escape` then `i` is "the one deterministic put-the-cursor-in-the-composer
idiom from any state." That works, but it makes the muscle memory yog-specific.
An operator arriving from any other app reaches for Ctrl and gets nothing.
Both hands should work.

## The current table (DESIGN §11, ~line 1190)

    ↑ / ↓  step the focus         1–5  inspector tab
    i  composer focus             n  ＋ conversation
    w  ＋ workspace               s  ▶ Start (top ready row)
    x  Stop                       f  Flush (lernie scan)
    c  Close ball                 r  Release ball
    b  balls fold                 g  recent ⇄ by ball
    a  activity                   Enter  send goal      Esc  cancel goal

## The hard part — read this before assigning combos

the operator pushed back on the first draft of this section, and he was right. It
listed `Ctrl+R` = reload as a "collision" without checking whether yog has a
reload at all. **It does not**, and the reason matters:

> we are instrumented to be very hostile to any potential ui drift (everything
> loads file descriptors directly, etc) so what are we _loading_?

Correct. DESIGN §7.2 / §7.1: an inotify watcher marks roots dirty, a 100 ms
debounce coalesces the storm, a 2 s cheap sweep reconciles and re-probes
liveness, and a 15 s full sweep re-derives everything — `src/app/derive.rs:121`
states the guarantee outright: *"so a dropped inotify event costs ≤15 s of
latency, never divergence."* The ops tail is re-read on the same cadence and
detached stderr sinks are folded in at read time. There is no cached view to
refresh. A reload verb would have nothing to do.

**So the method for this ball is: for each conventional combo, first ask
whether yog has that concept at all.** Only then ask what it should bind to.
The three cases:

1. **yog has the concept and a letter for it.** Give the combo the conventional
   meaning. `Ctrl+N` = new is the clear one — though note `n` is ＋conversation
   and `w` is ＋workspace, so decide which one earns `Ctrl+N` and give the other
   something that is *not* `Ctrl+W`. `Ctrl+W` is close in every browser and
   editor alive; binding it to "new workspace" because the letter matches would
   be hostile.

2. **yog lacks the concept.** Then the question is not "what do we bind" but
   **"is a reflexive press harmless?"** This is where the real hazard lives:

   - `Ctrl+R` (reload) — nothing to reload. But an operator WILL press it out of
     habit expecting a harmless refresh, and yog's `r` is **Release — unclaim
     the ball**. A destructive verb behind a reflex keystroke is the worst
     possible outcome. `Ctrl+R` must not be Release.
   - `Ctrl+S` (save) — nothing to save; drafts are RAM until sent (§5.3) and
     config edits land through an explicit Apply. yog's `s` is **▶ Start**, which
     fires a conversation. Same hazard, same conclusion.
   - `Ctrl+F` (find) — yog has no search. `f` is **Flush** (`lernie scan`), a
     mutation. Less destructive than the two above, still a surprise.
   - `Ctrl+A` (select all) — inside a text box this is egui's and must stay so.
     `a` is the activity accessory.

   **Leaving a combo deliberately unbound is a valid, probably correct answer
   here** — and the absence should be documented in §11 as a decision, not left
   as an omission. AGENTS.md: "Fill the holes with a default or a principle, not
   a feature." Do not invent a "force refresh" verb so that `Ctrl+R` has
   something to do; that is a new mechanism for a problem that does not exist.

3. **No convention exists** (flush, activity, balls fold, organizing view).
   Pick something defensible and say plainly that you invented it rather than
   dressing it as a standard.

Also verify empirically that each candidate combo actually reaches the app —
egui and the window manager consume some before yog sees them.

## Deliverable

1. **docs/DESIGN.md §11 is the authority** — the table above gains a combo
   column, and the prose gains the rationale for every place convention and
   letter part ways. AGENTS.md: "don't implement a deviation: fix the doc."
   Do the table first and treat it as the design artifact.
2. `src/keymap` (the pure table) and `src/shell/keys.rs` (the egui lift — see
   its `LETTER_KEYS` / `DIGIT_KEYS` consts and the `ctx.wants_keyboard_input()`
   suppression) implement it. `keymap` is pure and fully tested; the combo
   dimension belongs there, not in the shell lift.
3. The suppression rule needs a decision: a bare letter is suppressed while a
   text box holds the keyboard. **Should a combo be?** Ctrl+N while typing in
   the composer is exactly when you most want it to work — that is the whole
   ergonomic argument for combos. Getting this right is most of the value of
   the ball. Whatever you decide, write it into §11.
4. `scripts/drive/stories.sh` documents the binding table in its STEERING RULE
   header and steers by it. Keep it truthful.

## Not this ball

Do not remove or renumber any existing bare-letter binding. This is additive.
