Measured 2026-09-22. bl-6a84 (balls main, unpublished) changed the gate fingerprint; a box that installed bl-speculate from that tree computes key 0bbd4178… for a tree the crates.io 0.5.11 the workflow installs computes 314f3b41… for (the runner's key is what a hand reconstruction of 0.5.11's algorithm — rustc -V plus the four gate files — gives on the same tree). scripts/speculate-gate then finds no PASS under the local key, exits non-zero, and balls stores pass = false for a tree the runner passed — a FAIL that stops every chain behind it and cannot be dislodged without a new commit. One such false verdict was already written and hand-deleted during the 2026-09-22 wave.

Exit: when balls publishes bl-6a84 (0.5.12 or later), bump the `balls =` pin in Cargo.toml so speculate.yml installs the same algorithm the box runs, and note in CLAUDE.md's merge-queue section that the local bl-speculate must be the pinned crates.io version, not a source build. Until then: do not run `bl-speculate run` on this box; close on the local gate, which is honest. The residual bl-673a names — a gate exit code meaning no verdict — now exists upstream (balls bl-1643, exit 75) and rides the same pin bump, so scripts/speculate-gate should start answering 75 for a fingerprint miss instead of FAIL in the same ball.
