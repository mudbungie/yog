## What the operator saw

> the new workspace is <workspace>, but the prompt includes <workspace>? is
> that the name of the workspace or the specific conversation? it should be the
> conversation. workspaces are supposed to be rarely minted, large-scope,
> effectively collision boundary constructs that let you have, like,
> personal/work, or client/client noninteractive spaces.

He is describing §3.1 back to us. §3.1 already says exactly that:

> **A workspace is long-lived and low-volume** — a sphere of work (personal,
> corporate, a client) whose wall is lernie's isolation boundary; conversations
> are root agents *inside* it (lernie §7.3) … further workspaces are minted
> only to wall spheres off from each other.

## The contradiction

The name is minted **per workspace** (§3.1: "The name is minted at creation:
two words from an embedded wordlist"), and then `src/start/goal.rs:39` stamps
that same workspace name as every conversation's identity:

    pub fn identity_preamble(name: &str) -> String {
        format!("You are {name}.")
    }

So every root agent in `<workspace>` is told "You are <workspace>." Ten
conversations in one sphere, ten agents all asserting the same identity. The
sphere wall — a *boundary* — is being used as a *name*. Those are different
kinds of thing, and §3.1 says so in its own words while the code does the
opposite.

## Why this is not a one-line fix — read before proposing one

The workspace name is **load-bearing for the ball join**. §3.2:

> The ball↔workspace association is **metadata on the ball**: a ball is bound
> to a workspace iff its claimant equals the workspace's name.

and §16.7 W9 removed the "stamp every bl verb with --as <name>" instruction
from the preamble precisely because yog's `bl` shim now defaults `--as` to
`$YOG_NAME` — the workspace name — automatically (`src/world/tools`). So:

- give conversations their own names and `--as` changes meaning, and §3.2's
  join key changes with it;
- §3.2 itself argues that a ball's assignment must be **late-mutable** and that
  "agents author balls mid-flight and pick up several." An *agent* picking up a
  ball is a conversation-scoped act, not a sphere-scoped one — which is an
  argument that the join was always pointed at the wrong noun;
- but a per-conversation claimant multiplies claimant identities, and §3.1
  mints workspace names against an occupied set that includes "every claimant
  visible in `bl list --json` across enumerated projects." That set changes
  shape.

Also in scope: §3.3 (the composer's greyed identity preview), §3.4 (the rungs),
§8.1 step 1-2 (mint + preamble at fire), §11 (the conversation list renders
`row.preview` or the raw `root_id` — a timestamp-hash like
`<agent-id>` — because there is no name to render), and §16.7 W9
(`YOG_NAME`).

## What the design must answer

1. Does a conversation get a minted name of its own? From the same wordlist?
   How does it avoid colliding with workspace names and with bl claimants?
2. What does `You are <x>.` say, and what does `YOG_NAME` carry?
3. What is the ball's claimant after this — the workspace, the conversation, or
   something derived? §3.2's "binding is the ball's claimant" is the invariant
   under pressure; if it changes, say what replaces it and why the new one is
   also a single source of truth.
4. What does the §11 conversation list show as a row title, and what does the
   composer say it is messaging? (bl-2f30 is blocked on this answer.)
5. Attack it before committing, per AGENTS.md: what does the proposal NOT
   solve? Is a per-conversation name a new mechanism where a reframe would do —
   e.g. is the conversation's name simply its first-line intent, already
   present as `ConvRow::preview`, and the real bug is only that the *preamble*
   and the *ball claimant* conflate sphere with speaker?

Prefer subtraction. A design that removes the conflation without minting a
second name namespace is better than one that adds one, if it holds up.
