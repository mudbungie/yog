Twice in one day, for two different closes, the echo-window beat asserting a second Enter is held and delivered when the start resolves failed with the recording litany shim's log empty — only under gate contention (long parallel runs, 600s+), passing 2764/2765 in ~31s isolation on the same trees both times. The shape matches the write-then-exec class the spawn-boundary discipline exists for, but the spawn lock did not save it, so the window is elsewhere — likely a sleep-calibrated wait inside the beat that a loaded box outruns. Find the beat's timing assumption and replace it with an event the harness can wait on (the shim writing its first line, the start resolving as a state predicate) rather than widening a sleep; a beat that needs an idle box is a beat that lies on CI.
