bl-ae05 opened the window's READ path over loopback mTLS (REMOTE 1.2, 9.7): the window carries its own leaf, is scoped by its registrations, and an off-frame asker lands decoded replies the frame paints. Its acts did not move.

Every gesture the window sends still goes through AppModel::dispatch — the in-process boundary::dispatch::dispatch over this instance's ui.json. That is the second execution path 1.2 exists to refuse, and it is the larger half of the residual by volume.

Why it cannot simply be re-pointed at the seat. The click-glue reads each act's Reply SYNCHRONOUSLY and branches on it in the same frame (the stop/scan/message/nudge arms, the config-mark write, the model picker's write, the slash line's answer, the fork). A frame may never wait on a socket — that is the invariant the read path was built to keep — so every act becomes a declaration whose receipt lands later. The asker's shape applied to writes: send, get a handle, paint 'in flight', paint the receipt when it arrives.

What needs designing before it is built:

1. The receipt's identity. An act is not idempotent, so a resend is not free and a handle cannot be the encoded envelope the way a standing question's key is. Something has to mint one, and it must survive a frame that repaints between the send and the answer.
2. What a surface paints while an act is in flight, and what it paints when the receipt never comes. Today a failed act is a status string set in the same frame; the boundary already answers refusals in band, so this is a rendering question rather than a new error class.
3. The ui.json write. dispatch takes &mut self.ui — the window's in-memory document — while the engine's own answer opens the file fresh per gesture. Over the wire the engine writes and the window adopts (the existing external-change adopt path, keyed on the content hash), so the model's copy stops being authoritative. Check that ordering: an act's own write must not read back as an external change the window fights.
4. Whether the fire-and-hold flows (the start claim, the pending echo) survive unchanged. They already hold state across frames waiting for a conversation to appear, so they may be the shape the rest converges on rather than a special case.

Deliverable: the design recorded in REMOTE (a subsection under 9, citing this ball), then the cutover. Honest increments are allowed on the same terms bl-ae05 took: never leave the window half-broken, and record what is left.

Inputs already ruled and not to be relitigated: one boundary, everything through the front door (operator ruling 2026-08-14, bl-ae05); connection-per-gesture stands until a seat's ask rate exceeds human cadence (REMOTE 10); the wire adds no verb (REMOTE 3).
