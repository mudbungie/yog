Both failed once in one close gate on a box running roughly thirteen concurrent tarpaulin suites (load ~18-20), and both passed on the immediate re-run with no code change. Recorded by the agent closing bl-6a6a.

- `boundary::login::…::a_lane_ends_when_the_run_it_was_reading_is_gone` — landed with bl-c285 (the sign-in act); the lane/holder pair rendezvous on a run's settlement, and the beat's wait is the suspect.
- `boundary::consumer::…::the_boot_answers_a_dead_claimants_gesture_in_doubt` — the consumer's boot-time doubt arm.

Same class as bl-b8c8 and the sibling it fixed (`registry::mailbox::slots::tests::work_landing_mid_hold_ends_it`): a wall-clock wait standing in for a cross-thread rendezvous. The fix is the same shape — hand off on something both sides observe (the published state, a channel, the claim the read takes on its way into the hold), with an escape deadline that fails instead of hangs. Do not widen a sleep.

Verify the failure first: run each test alone under `stress`-like load (or several concurrent `cargo test` invocations) and confirm the shape before editing.

---

Reproduced one of the two, and its cause is not the one filed.

**`boundary::login::…::a_lane_ends_when_the_run_it_was_reading_is_gone` has no
wall-clock wait.** Every look it takes is `Lane::poll`, driven by hand with
`Duration::ZERO` between them, and the sweep it asserts on is keyed off the
stamp the test passes in (`"4000"` against a slot seated at `0`, against a
3600-second TTL) — deterministic end to end. Its one non-deterministic act is
that it execs a shell script the test itself had just written, and that is what
fails: reproduced at 16 workers x 70 iterations,

    panicked at src/boundary/login/tests.rs:226:
    started: "failed to spawn …/bz-quiet: Text file busy (os error 26)"

which is `.expect("started")` on `Runs::start`. ETXTBSY, not a rendezvous.

Fixed by taking the fixture away: the sweep is the beat's subject and the child
is incidental — nothing reads what `bz` said — so `bz` is now `/bin/sh`, a
binary this process never opened for writing. Re-run at the same volume: gone,
while ten other victims still fell in the same run, so the stress was still
live.

The class behind it is filed as bl-6bf5: `multiplex`'s in-process `balls`/
`litany` arms fork outside yog's spawn lock, so any peer thread's write fd on a
fixture script is copied into a child, and the exec that follows is Text file
busy. Same filter with `multiplex` left out, same volume: zero. Fourteen
distinct tests carry the exposure; this ball fixed one of them.

**`boundary::consumer::…::the_boot_answers_a_dead_claimants_gesture_in_doubt`
could not be made to fail, and its wait is already the prescribed shape.** It
polls for the reply file — a fact the sweeping thread and the test both observe
— behind a 10-second escape deadline that asserts rather than hangs, which is
exactly what bl-b8c8's sibling was rewritten INTO. Twenty concurrent full-suite
runs under load ~20 plus a targeted stress at 16 workers: green every time,
while three unrelated flakes fell out of the same runs. Left alone; widening
the deadline would be widening a sleep. If it recurs, the suspect is thread
creation or scheduling under a tarpaulin herd, not the fold, and nothing in the
test can answer that.
