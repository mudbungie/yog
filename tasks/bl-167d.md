Source: publication audit follow-up 2026-08-13 (item 5), snapshot yog
`e758814`. `scripts/leak-scan.sh` landed under bl-fd5a; these defects remain.

The gate is not a sufficient regression barrier:

- It claims "Reading the INDEX", but `git ls-files` supplies only path NAMES
  and `grep ... "$@"` opens WORKTREE files. A staged leak paired with a clean
  worktree copy passes.
- `grep -I` skips binary content; archives, databases, PDFs, HAR files,
  screenshots and executables are not rejected.
- The home rule is built only from the scanner's current `$HOME`, so CI on
  another account cannot catch `/home/u`, `/Users/u`, or Windows profile
  paths.
- There is no rule for personal email, named private dialogue, or ordinary
  transcript prose.
- Scanner source and fixtures are excluded from the scan.
- The scanner is absent from the speculative verdict fingerprint, and the
  pre-commit hook accepts a cached verdict before running lint.
- A hook scans one tree — not old commits, other refs, PR/release text, Actions
  logs, artifacts, or published crates.

Required tests:

1. staged-index / worktree divergence;
2. Linux, macOS and Windows home paths, independent of runner identity;
3. personal-email and private-dialogue fixtures;
4. binary/archive policy;
5. fixture values that are unmistakably fake;
6. a scanner change invalidating the verdict cache;
7. CI / protected-ref enforcement, not just a local hook.

Scope boundary: keep one-time history and remote-surface scanning as a release
checklist, NOT a commit-hook promise. A hook cannot make that promise.

Verify each defect against the current script before editing.

Verified against the tree at e758814 before editing. Six of the seven listed
defects were exactly as filed. Two corrections:

- **The fingerprint claim is half right.** bl-speculate keys a verdict on
  (tree, gate): the gate half is the fixed file list compiled into the binary
  (scripts/pre-commit, scripts/check-line-lengths.sh, scripts/check-coverage.sh,
  Makefile, `rustc -V`) and the scanner is indeed absent from it — but the tree
  half is `git write-tree` over `add -A`, and the scanner is a TRACKED file, so
  editing a rule DOES invalidate every verdict for a tree containing the edit.
  The live hole is the one the ball names second: the hook consults the cache
  before scanning at all, and a verdict can arrive from elsewhere (the
  speculate workflow uploads a store, scripts/speculate-gate imports it).
  Fixed by ordering rather than by fingerprint — `make leak-scan` runs BEFORE
  the cache check and is never cached — which needs nothing from balls bl-6a84.

- **Required test 7 was already satisfied.** CI enforcement existed:
  .github/workflows/ci.yml runs `make ci` -> `check` -> `lint` -> `leak-scan`,
  and speculate.yml runs scripts/pre-commit. The test landed pins that chain
  against silent removal; it did not add enforcement. Protected-ref
  enforcement proper is a GitHub setting, not a repo artifact, so it stays out
  of scope with the rest of the remote surface.

Two things dissolved rather than patched:

- The `$HOME`-derived home rule was INVERTED instead of extended: any absolute
  path under any home root on any platform, excepting the three house
  synthetic roots. One rule, no per-runner computation, no platform list to
  keep adding to. `(^|[^A-Za-z0-9._/-])` is load-bearing — `<world>/walls/home/
  brazen` is a wall leaf, not a home.
- The two remaining scan exemptions were deleted rather than narrowed. The
  scanner and its table are scanned, under the invariant "no pattern may match
  its own text" (one did: PuTTY's banner, now `Fil[e]`). A fixture is scanned
  by every rule EXCEPT its own — a structural exemption keyed to the file's
  name, so extending it means adding a RULE of that name. tests/leak_gate.rs
  probes with those fixtures rather than restating leaks, so instances of leak
  material live in exactly one directory.

Found in passing: docs/DESIGN.md's sample ui.json carried a real personal
address in `identity_last_used` — the gate's first live catch. bl-2368 landed
the same fix on main concurrently; taken from main in the merge.

Not attempted, per the scope boundary, and recorded as a release checklist in
AGENTS.md ("Before making the repo or a crate version public"): history, other
refs, commit messages predating the hook, PR/issue/release text, Actions logs
and the `verdicts` artifact, and already-published crate versions.
