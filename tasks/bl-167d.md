Source: publication audit follow-up 2026-08-13 (item 5), snapshot yog
`e758814`. `scripts/leak-scan.sh` landed under bl-fd5a; these defects remain.

The gate is not a sufficient regression barrier:

- It claims "Reading the INDEX", but `git ls-files` supplies only path NAMES
  and `grep ... "$@"` opens WORKTREE files. A staged leak paired with a clean
  worktree copy passes.
- `grep -I` skips binary content; archives, databases, PDFs, HAR files,
  screenshots and executables are not rejected.
- The home rule is built only from the scanner's current `$HOME`, so CI on
  another account cannot catch `/home/u`, `/Users/u`, or Windows profile
  paths.
- There is no rule for personal email, named private dialogue, or ordinary
  transcript prose.
- Scanner source and fixtures are excluded from the scan.
- The scanner is absent from the speculative verdict fingerprint, and the
  pre-commit hook accepts a cached verdict before running lint.
- A hook scans one tree — not old commits, other refs, PR/release text, Actions
  logs, artifacts, or published crates.

Required tests:

1. staged-index / worktree divergence;
2. Linux, macOS and Windows home paths, independent of runner identity;
3. personal-email and private-dialogue fixtures;
4. binary/archive policy;
5. fixture values that are unmistakably fake;
6. a scanner change invalidating the verdict cache;
7. CI / protected-ref enforcement, not just a local hook.

Scope boundary: keep one-time history and remote-surface scanning as a release
checklist, NOT a commit-hook promise. A hook cannot make that promise.

Verify each defect against the current script before editing.
