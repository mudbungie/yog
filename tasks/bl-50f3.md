Operator hit it live 2026-08-02: told valid-overcrowd to message shudder-storeroom; the message tool failed twice with no-agent-in-workspace (ops agents/<agent-id>/messages/005-tool.json, is_error). Facts: lernie message resolves agents/* refs only; yog mints display names (DESIGN 3.3 ladder) and stamps them solely as prose ("You are shudder-storeroom.") at fire; no machine-readable name-to-id mapping exists. Operator and every UI surface speak names; agents can only address ids.

RULING (naming-arch, 2026-08-01): (a) — the name becomes a first-class lernie fact. The name is agent identity; agents live in lernie; the fact lives in lernie. yog stays the minter (policy) and becomes a pass-through and reader (mechanism moves to the substrate).

Verified facts grounding it:
- The mint is NOT derivable from the id: src/names/mod.rs `mint(rng, occupied)` is a pure function over an injected RNG plus a per-workspace occupied set, and the composer previews the name BEFORE anything spawns (3.3, I7) — the name exists before the agent id does. No crate can compute name from id; the name is an irreducible fact needing exactly one durable home.
- Messages are sent mid-run by lernie tooling (lernie src/prompt/tool/builtin/message/ via `lernie message`, guarded by workspace::agent_exists, lernie src/workspace/guard.rs). yog is not in that loop, so resolution must live where lernie can reach it — which leaves only (a) and (b).
- yog already consumes lernie on-disk workspace facts (src/git_tree/enumerate.rs reads `<workspace>/agents/<id>/goal.md`), so the (a) read-back adds no new kind of coupling: yog reads a lernie-owned, lernie-documented fact, exactly as it reads goals and refs today.

Why the losers lost:
- (b) workspace registry file yog writes, lernie reads: two representations of the living-agent fact (registry rows vs agents/* refs) that must drift — lernie-dispatched children never appear (yog is not at their compose), retention deletes refs while nobody owns registry cleanup, a yog crash between spawn and write strands an unregistered agent — and the format is an interface neither crate owns or documents. Fails single-source-of-truth and minimal-interface both.
- (c) tool-description mitigation: the description is lernie source (src/prompt/tool/builtin/message/mod.rs), so the cheap candidate still costs a lernie release — the (a) price without the fix. The yog-prose variant (teach agents to git-show peer goal.md files and parse "You are <x>.") couples every model to a yog-private display idiom, burns steps per resolution, and still fails for hand-typed and foreign roots.
- (d1) derive the name from the id: impossible, see the mint facts above.
- (d2) name AS the id: the id is a branch name, a worktree dir, and two namespace keys (lernie ARCH 2.2/2.3); names lawfully recycle after retention while ids must never collide. Freighting the identifier with display semantics is rejected.

Ruled shape (full spec in lernie bl-c8ed): lernie prompt/dispatch grow optional --name; creation refuses a name colliding with a living agent name (uniqueness enforced where the fact lives); the name is committed under the agent beside goal.md so agents/* refs stay the only registry and retention recycles names with zero cleanup; message resolves exact id first, else unique living name, ambiguous/unknown is a loud error; the tool description teaches both. yog then passes --name at fire, ladder rung one reads the fact, and the "You are <name>." line stays as model-facing prose (frozen dispatch content composed from the same string at the same instant — not a second fact home), its parse demoted to a legacy rung until retention ages pre-feature roots out.
