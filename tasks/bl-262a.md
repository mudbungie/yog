Round-1 daily lane. yog 0.0.38 (main c7916da1), litany 0.0.10 pinned, seat lernie 0.1.30, engine on 127.0.0.1:7741 under an isolated `XDG_DATA_HOME`.

Scenario S2/S3: a person tracks a project's tasks with `bl` in their own shell, then aims a conversation at that same directory and asks for a report on it.

Setup: a git checkout at `~/proj/tasks` with four balls filed from the operator's own shell (`bl create ...`, two p1, one p2, one p3).

Gesture:

    lernie ask '{"op":"prepare","workspace":"tasks","payload":{"rung":"path","dir":"<repo>"}}'
    lernie ask '{"op":"prompt","prepared":{...},"goal":"Write a status report of the open balls in this project to STATUS.md. Use the bl command line (bl list, bl show) to read them. Group by priority and say what the board looks like."}'

The conversation ran for four minutes, spent 2,607,869 tokens, dispatched six compactor children, and wrote a 2,133-byte STATUS.md whose first heading is:

    ## What the board looks like

    The board is **empty**. There are no open balls in this project, at any
    priority, in any state.

It then tabulates eight `bl list` variants, all `[]`, and adds a "Tracker health" section arguing the absence can be trusted.

The board is not empty. The same directory, two commands:

    $ bl -C <repo> list
    ready    bl-....  the composer loses focus after a send  p1
    ready    bl-....  stop does not stop  p1
    ready    bl-....  transcript scroll jumps to top on refresh  p2
    ready    bl-....  spend is not shown per conversation  p3

    $ cd <repo> && yog bl list
    (nothing)

Cause: `yog env` folds `XDG_STATE_HOME` to `<yog-data-root>/world/state` and puts `<world>/tools` first on PATH, so the `bl` the agent's `bash` tool reaches keys its store off that state root. balls keys a store on the invocation directory, so the path matches and the store does not — the agent addresses an empty store at the right path and cannot tell.

Comparator, same directory, same goal, same minute:

    claude -p --model sonnet "<the same goal>"     22.6s, found all four, grouped by priority correctly

Expected: a conversation aimed at a directory reads the task store that directory's operator reads — or, if the nested world is the ruling (DESIGN §16), the agent is told which store it is addressing so an empty answer reads as "a different store", not as "no work".

Severity p1: it is silent and it produces confident wrong work. The failure mode is not an error the operator can see; it is a well-written report of a fact that is false. Any workflow that asks an agent about the project's own tasks — which is the paved path S3 describes — is affected.
