Round-2 devadmin lane, the new three-box scenario: a foot killed and restarted
while one of its invocations is in flight (REMOTE 5.6, in-doubt).

## The measurement

A goal whose command has a side effect BEFORE its delay, so the box itself
records how many times it ran:

    On alpha2 with Bash, run exactly this and report the output verbatim:
    echo RUN >> /srv/indoubt2.log; sleep 40; wc -l < /srv/indoubt2.log

Once the side effect had landed on the box, the foot was killed and restarted:

    kill -9 $(pgrep -x thrall)   # inside the container, its own PID namespace
    thrall run &                 # 2 seconds later

Afterwards, on the box:

    $ cat /srv/indoubt2.log
    RUN
    RUN

The command ran **twice**. What the model was handed:

    007-tool.json  result of toolu_01…
    Exit code: 0
    2

    008  The command ran successfully on alpha2. Output verbatim:
         ```
         2
         ```

## What is right

The redelivery itself is REMOTE 5.6 working. A control run without the restart
appended one line and returned `1`; three or more hand-offs still produce 5.6
Ruling 2's engine-written capture ("was handed to … N times and never
answered"), which round 1 measured and which remains the best-behaved corner of
the lane. Nothing hung, nothing was lost, and the channel recovered on its own.

## What is wrong

The capture the model receives is **indistinguishable from a single clean run**.
`Exit code: 0`, no annotation, no field. The engine knows the hand-off count —
it already renders that count in the sentence it writes at the third — and it
spends that knowledge only on the give-up case. At hand-off two, which is the
common case (one restart, one deploy, one blip), it says nothing.

Here the number `2` in the capture IS the evidence that the command ran twice,
and the model read it as the answer and reported it as fact. On a real box the
capture of a double `apt install`, a double log rotation or a double migration
looks exactly like the capture of a single one.

## Ask

A capture posted for an invocation that was handed out more than once carries a
mark saying so — the same sentence 5.6 Ruling 2 already writes, said earlier and
without giving up. The model can then say "this may have run twice" instead of
reporting a doubled side effect as a single one; the operator reading the
transcript afterwards can see it too. Nothing about the delivery policy needs to
change: this is the fact the engine already has, on the frame that already
exists.

p2. The wire behaves as designed; the design under-reports what it knows, and
the under-report reaches the model as a fact.
