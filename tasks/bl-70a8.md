**Symptom (the operator):** "I'm doing make run, and I'm still seeing the default gear
icon."

**Not the icon.** `assets/yog.svg` installs correctly, the desktop entry
validates, and a GTK icon-theme lookup for `yog` resolves straight to it. The
window is a *native Wayland* toplevel (no X11 client exists for it).

**Cause.** Two facts compound:

1. On Wayland there is no protocol for a client to set its own window icon, so
   `ViewportBuilder::with_icon` — and therefore `theme::icon::icon_data()` — is a
   no-op. The icon can ONLY come from the compositor matching the toplevel's
   `app_id` to a desktop entry.
2. `egui-winit` only forwards `app_id` to `WindowAttributesExtWayland::with_name`
   under its own `wayland` feature — and `Cargo.toml` takes eframe with
   `default-features = false, features = ["default_fonts", "glow"]`. winit's own
   wayland backend is on (hence the native window), but egui-winit's is not, so
   `with_app_id("yog")` is compiled out and the toplevel advertises nothing to
   match `yog.desktop` against.

**Fix.** Add `wayland` (and `x11`, its X-session counterpart) to the eframe
features. `wayland = ["winit/wayland", "bytemuck"]` and both are already in the
build, so this must add ZERO crates — verify `Cargo.lock` is untouched before
landing, per the repo's no-new-dependency rule.

**Also fix the doc.** DESIGN §11 currently asserts the StartupWMClass/app_id
binding works; it has never worked on Wayland.
