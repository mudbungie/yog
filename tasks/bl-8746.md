Source: bl-2b8c ruling (VISION §4.10). Upstream mechanism: balls bl-a1a4 (source-owned reconciliation; delivery never merges) then bl-4eac (the policy-blind attempt capability: private source ref/index/worktree + single-writer lease per attempt, opaque target resolution, separated worktree release vs source-ref retention, returned base/source/target/delivered identities). Cross-repo gate: do not claim until a balls release carrying both is published; the first act is the exact pin bump.

## Scope

1. Bump the balls pin to the release carrying bl-a1a4 + bl-4eac.
2. Fan fire over a delivery obligation: pin the target tip once, ask balls for N attempts off that exact commit (namespace distinct from work/*; balls owns names and paths — yog constructs neither), fire N variant agents, each bound (bl-6654's channel) to its own attempt worktree. N=1 stays the ordinary claim/close path — same mechanism, no special candidate path.
3. Cohort and provenance are derived, never stored: siblings = attempts sharing (target, base), joined with the agents bound to them; the accepted candidate is the attempt whose delivery the target's history records (balls' auditable squash identities). No winner field, no cohort store, no yog project index.
4. Rejection changes no target ref. Worktree teardown and source-ref retention are separate balls calls; retention policy is yog world config, severable (deleting it deletes a default, not code).
5. Rework is source-owned: message the bound agent (or fork per V2) to incorporate the current target in its own attempt worktree and redeliver; delivery refuses a stale source by bl-a1a4's law and yog never reconciles.
6. Fan affordances render only when both upstream sides are pinned (no capability theater).

Blocks bl-c2bd (V3): judge/deliver/reject render over this surface.

## Delivered (Strake) — deviations and what the vendored 0.5.10 API actually said

**Scope 1.** `balls = "=0.5.10"` (Cargo.toml + Cargo.lock). One forced yog-side
fix rode with it: `balls::tracker::Env` gained a `depth` field, so the
`bl-tracker` multiplex arm now builds it through balls' own
`Env::resolve(xdg, env::var("BALLS_PLUGIN_DEPTH").ok())` rather than a struct
literal — the depth parse stays upstream's, failing open at 0.

**The API as vendored, vs. the body's second-hand description.**

- *"private source ref/index/worktree"* — confirmed: `Attempt::open(root, xdg,
  &Target)` mints `attempt/<handle>` at the target tip and checks it out at
  `attempt_path(xdg, invocation, handle)`.
- *"single-writer lease per attempt"* — confirmed but **not a lease object**:
  balls adds no lockfile and no liveness probe. The lease is git's own (fresh
  handle off the live set; `worktree add` refuses a ref checked out elsewhere;
  the path is a pure function of the handle). Nothing for yog to acquire or
  release.
- *"opaque target resolution"* — confirmed and stronger than described: `Target`
  has a private field and no accessor, so yog cannot construct or even render
  one. `Project::target(Option<&str>)` and `Project::target_ref(&str)` are the
  only doors.
- *"separated worktree release vs source-ref retention"* — confirmed:
  `Attempt::release()` / `Attempt::discard()`.
- *"returned base/source/target/delivered identities"* — confirmed on the
  **delivery** side (`Delivered { target, base, source, commit }`), which is
  V3's (bl-c2bd). What a *materialization* returns is `handle()` / `worktree()`
  / `base()` / `tip()`, and that is what this ball consumes.

**DEVIATION 1 — "pin the target tip once" is not expressible upstream.**
`Attempt::open` takes a `Target`, which is a **ref name**, re-resolved per call;
balls exposes no "fork at this exact commit" door. yog therefore resolves the
target once and *proves* the shared start instead: `fan::open` refuses a fan
whose members do not all report one `base()`, naming the divergent commits. A
moved target under a fan is a loud refusal, not an incomparable cohort.

**DEVIATION 2 — cleanup has no handle-only door.** `release`/`discard` hang off
a live `Attempt`, so yog's `fan::discard` re-materializes (via `Attempt::resume`)
the worktree it is about to remove. Idempotent, correct, and cheaper than a yog
path formula would be — recorded because it looks wasteful and is deliberate.

**DEVIATION 3 — the cohort join is the ops trail, not `(target, base)` alone.**
Two attempts of two different balls off an unmoved `work/*` share a base, so
`(target, base)` is not discriminating in the general case, and balls' `Target`
is opaque so yog cannot key on it anyway. `fan::cohort` therefore joins the
**fire rows yog itself wrote** (`--cwd` bindings that balls' own `attempt_path`
reproduces) with the workspace they fired in and the claim naming the project.
Explicitly NOT lernie's `refs/lernie/cwd/<agent-id>` mark: that is rewritten by
the agent's own `cd`, so a cohort read from it would be a set the candidates
could edit themselves (the same reason `control::root` refuses it for the
writable root). Still derived, still stored nowhere.

**ADDITION (yog-side premise that had changed) — the writable root.** VISION
§4.11's capability control landed after this body was written, and
`control::root::bound_worktrees` derived the writable root from the `work/<id>`
claim alone. A fanned drone works in an attempt worktree, so every one of its
writes would have classified open-world. `control::root::candidate_worktrees`
now adds the candidates, from the same two yog-owned facts (claim row for the
project, fire rows for the bindings). Without this the fan fires drones that
cannot write.

**Shape as landed.** `Action::Fan { prepared, obligation, n }` answers
`Reply::Fanned(Vec<Prepared>)` — the prepared start rebound once per candidate —
and fires nothing; each element is spent through the ordinary `Prompt` door, so
the §3.5 spend ceiling gates every birth unchanged and the trail keeps N ordinary
fire rows. `n <= 1` materializes nothing and hands back the claim binding, which
is scope 2's "N=1 stays the ordinary claim/close path" made structural.
`Action::Retire { obligation, handle }` releases the worktree and discards the
source ref only when `cadence.yaml`'s new `retention:` block declares a
`keep_min` for that project and the candidate has outlived it — absence is never
discard, the `fleet:` `lease_min` precedent. `fan::Obligation` (project + optional
ball) is new: the pair is one fact and every act re-derives the target from it.
All three serializations landed (RAM variant, JSON envelope, `/fan <n>` and
`/retire <handle>`); DESIGN gained §3.8 and the §12 rows. Scope 5 (rework) needed
**no code**: it is `Message` to the bound agent plus balls' own stale-source
refusal, and the absence of any reconcile path in `crate::fan` is its
implementation. Scope 6 is discharged by scope 1 — the affordances exist because
the capability is pinned.

**Found, not fixed (V3's, bl-c2bd).** No §11 seat picks N or renders the cohort;
judge/deliver/reject render over this surface and are that ball's. Also
unclaimed here: `fan::cohort::members` is consumed today only by the writable
root; the V3 read surface should spend the same fold rather than a second one.
