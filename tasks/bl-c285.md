## What this lands (REMOTE §8.3; DESIGN §8.3 as amended by bl-61bf)

Two boundary verbs, all three serializations, no wire vocabulary (REMOTE §3):

- **`Action::Login { workspace: String, provider: String }`** — starts the sign-in run ON the engine: spawns `bz --login --provider <row> --browser` inside the NAMED workspace's wall, through exactly the seam `boundary::config::providers`/`models` already lens (`wall_env(deps, workspace)`, src/boundary/config.rs — the bl-fcd5 discipline: the gesture's own workspace, never a focus). The act MUST NOT wait for the run: the intake is one thread for the whole world, so it starts and answers at once (REMOTE §3's `invoke` precedent). The receipt is the run's standing, re-read (the Marks discipline), never an echo.
- **A follow-class `Query`** (suggest `Query::LoginTail { workspace, provider }`) — the run's lines from the START (buffered engine-side; a sign-in is a handful of lines), then live to the outcome; the settled exit is the final frame. Re-ask replays: a dropped lane, a re-attached seat and a settled run are one case (the bl-73e7 `Query::Follow` discipline — mirror its frame encoding). A pair with no run answers emptiness legibly, never an error.

## The run holder

Engine RAM, ONE live run per workspace × provider:
- A second `Login` on a live pair SIGTERMs and REPLACES it — the operator's own restart is the cancel; no cancel verb. Replacement must actually terminate the child: an abandoned browser-flow run holds the row's redirect port, and the next sign-in would lose the bind. The SIGTERM stays confined to src/cli_outbound/sys.rs (rule 3).
- A run older than an hour is swept (the REMOTE §5.3 mailbox bound).
- A reader thread per run drains BOTH child streams into the buffer, tagged (DESIGN §8.3 rule 3 — the authorize URL rides stderr); lanes read the buffer and never own the poll (two seats may hold lanes on one run).
- Lock home: `src/state.rs` first (rule 7). If the 100% floor breaks with phantom uncovered lines — the measured bl-4e08/bl-024b failure — move it beside `src/registry/mailbox/` and record the measurement. Decide by measuring, not by precedent.
- The `ops.jsonl` outcome row appends ENGINE-side for boundary-started runs (Origin::World, stderr derived from the same lines the lanes serve — the one-source rule src/login/mod.rs::finalize already states). No double row: the window path and the boundary path never share a run until the pane-migration ball deletes the former.
