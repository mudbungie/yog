No tool call has an implicit location.

- **Host-qualified names.** A loaded tool is a host-bound instance (host:tool). Locality rides in the very name the model chooses, so schemas stay per-host and provider-validated; there is no shared host field and no schema union across hosts. The landed load mechanism (REMOTE §5: list/get on the one client-management tool, then load, re-declared per bl-c907) is unchanged — this is a naming discipline over it, not a new surface. A wrapper meta-tool carrying an untyped payload was considered and rejected: it loses emission-time validation, forces the adjudication chokepoint to unwrap payloads, and its one virtue — discovery without server-side change — is already delivered by load.
- **Subject-locality invariant.** A tool executes where its subject lives. Workspace-relative tools follow the worktree; box tools follow the named box. "Local" is not a privileged default, only the host that happens to hold the subject.
- **Thrall-local environment.** An invocation carries its subject location (cwd); a thrall executes in its own environment. The server's composed world fold (DESIGN §16.2) is never shipped across the wire — substrate access reaches agents as thrall tools or engine acts, never as ambient inherited env.
- **No broadcast.** A hosts list is rejected from the invocation shape; if fan-out patterns become hot, that is a distinct future tool that makes sub-calls, not an overload of the invocation.
