UX testing, 2026-07-27 (the operator): hit `＋ conversation`, typed a goal, hit Enter.
Three times. The window showed nothing at all — no reply, no error, no banner.

## What actually happened

The prompt fired and the detached driver died instantly on a stale workspace
config. Three ops lines, all `exit -2` (`DETACHED_EXIT`):

    {"argv":["lernie","prompt",".../workspaces/<workspace>","...yo"],"exit":-2,...,"ts":"1785138037"}

and the §8.1 stderr sink caught the cause exactly as designed
(`~/.local/share/yog/world/state/yog/detached/1785138037-<workspace>.err`):

    lernie prompt: config: config: invalid a780d1d…:workflow.yaml at
    events.user_message[0]: action "spawn_root_agent" was retired: a user
    message resumes the agent's own branch and a new root agent is forked
    explicitly, so no binding spawns one (ARCH §2.4); remove the binding

So the capture worked. The **surfacing** did not.

## The defect

`src/opslog/detached.rs` folds the sink in at *read* time, and
`AppModel::refresh_ops` re-folds it on the 15 s full sweep — the model learns
the failure. But the composer's ichor-red banner does not read the model. It
reads a cached copy:

    src/shell/input_bar.rs:99   if let Some(failure) = &state.actions.last_failure
    src/shell/fire.rs:82        actions.last_failure = model.last_failure();

`state.actions.last_failure` is assigned **only** inside the dispatch handlers
(`fire.rs:82`, `input_bar.rs:242`, `ball_bar.rs:135`, `start_pane.rs:84/181/237`).
Every one of them runs microseconds after the spawn — before the child has died
and written its sink. `model.last_failure()` correctly returns `None` at that
instant, and nothing ever asks again. The banner is a snapshot of a moment when
the failure had not happened yet.

This defeats the whole point of the sink. `detached.rs`'s own header states the
goal: a driver that "dies right after launch … indistinguishable from a clean
launch: exit -2, nothing rendered, a prompt that visibly *does nothing*." That
is still exactly what the operator gets.

## Fix direction

Derive the banner per frame from the model rather than caching it at dispatch:
drop `ActionsState::last_failure` / `StartState::last_failure` and have the
render sites call `model.last_failure()` directly. That is the single-source-of-
truth shape (`AGENTS.md`: "don't store what you can compute") and it needs no
new signal — the fold already runs on every sweep.

## Acceptance

A drive beat: fire a prompt whose driver dies on launch, wait past one full
sweep (15 s), screenshot — the red banner carries the sink's stderr tail. Today
that beat fails.

## Not this ball

The stale `workflow.yaml` in `<workspace>` is a world-data problem, not a yog
defect — that workspace was minted 2026-07-20 against an older lernie, and
`lernie new` seeds the current template clean. Mentioned only as the repro.
