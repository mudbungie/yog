## Symptom

A provider row whose credential is **ambient** — one brazen finds outside its
own store — reads `not signed in` in `/providers`, while the same row answers
live API calls from the same wall in the same second:

```
$ yog gesture --ws <ws> '/providers'
… {"name":"<oauth-row>","fact":"auth oauth2 · not signed in","blocked":null} …

$ yog gesture --ws <ws> '/models <oauth-row>'
{"kind":"models","ok":true,"rows":["…","…", … ten ids off the live API …]}
```

The wall in that run held a `config.toml` and **no credentials directory at
all**; the row's secret is reached by an `ambient` path declared on the row.

## The authoritative column is parsed, carried, and not used for the words

`ProviderRow::credential` is documented as exactly the authority here
(`src/config_edit/brazen/providers.rs`):

> **The credential this row would actually use**, in brazen's own spelling:
> `stored` … `ambient` (one it found outside its store), `inline` … brazen
> computes it through the very `fetch_cred` a run spends, minus the network, so
> **it is the authority on "could this row answer at all"** and yog re-derives
> none of it.

`credential_words` ignores it and switches on a separate boolean instead:

```rust
fn credential_words(&self, present: bool) -> &'static str {
    match (self.auth.as_str(), present) {
        (OAUTH2, true)  => "signed in",
        (OAUTH2, false) => "not signed in",
        …
```

where `present` is `row_views`' credential-**file** existence read — a scan for
`<wall>/credentials/<name>.json`. An ambient row has no such file, so it is
`false`, so the words are `not signed in`.

## Two derivations of one fact already disagree inside this module family

`start::gate` reads the right column and says so in its own header:

> **Every other credential spelling IS ready**, including the two the ruling's
> enumeration omitted (`ambient`, `inline`) … Refusing a wall whose rows carry
> a credential a run would actually spend would block a working setup.

So the §8.1 start rung calls the wall ready and the §8.3 roster beside it calls
the row not signed in. One fact, two homes, and they already drifted.

## What it costs the operator

The sentence is the one an operator acts on: a row reading `not signed in` with
`blocked: null` invites a sign-in that is not needed and cannot be the reason
anything failed. It is also a QUALITY H2 miss in the direction that matters —
absence asserted where presence is the truth.

## Repro

    # a wall holding config.toml with an ambient-credential oauth row, no credentials dir
    yog gesture --ws <ws> '/providers'          # "auth oauth2 · not signed in"
    yog gesture --ws <ws> '/models <that row>'  # answers, off the live API

## Shape of the fix

`credential_words` switches on `credential` — the column already on the struct
— and `present` goes, along with `row_views`' second argument, if nothing else
needs it. The vocabulary then has a true word for each spelling
(`ambient`/`inline` are neither "signed in" via bz nor "not signed in"), which
is the small design question the fix has to answer rather than a mechanical
swap.
