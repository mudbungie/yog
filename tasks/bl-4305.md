Glyph-doctrine follow-up (DESIGN §11 "Glyph doctrine", filed by bl-5013), fixed
per the badge-seat pattern (§11 "The badge-seat pattern", bl-ae05).

PATHS CORRECTED: the ball was filed against `src/transcript/render.rs
(render_tool_result)`, which no longer exists — bl-9b73 (commit 14343b4) moved
the transcript to a one-line row projection, so the seat is now
`src/transcript/rows.rs` (`push_entry`, the `EntryKind::ToolResult` arm). The
second seat, `src/steps_view/render.rs` (`render_tools`), was where the ball
said it was.

The doc also contradicted itself: §11 line ~1746 already claimed the
tool-result rows "carry words beside their glyphs" (bl-9b73 added
"tool result"/"tool error" at the render site) while the §11 audit table still
scored the seat a fail. Both halves are now true and consistent.

Move 1 — the words live with the glyph. New `theme::tool_result_badge(is_error)`
returns `("✔", HYDRA, "tool result — ok")` / `("✖", ICHOR, "tool result —
error")`: one home for the glyph, the hue and the words that both seats had
each been deciding for themselves. `rows.rs` takes the glyph and the phrase from
it (keeping its headless `Tone` for the hue, since that projection names no
RGB); `steps_view` takes all three and stops restating ICHOR/HYDRA.

Move 2 — INLINE at both seats, not hover. The transcript result row is dense and
repeating, which argues hover, but (a) the row`s `prefix` is its always-visible
identity slot and is already worded for every other row class (`user:`,
`opus:`, `⚙ Read — running`), so hovering the outcome would make the tool
result the one row that will not say what it is, and (b) the width pressure
that forced the conversation list to hover (bl-9669) is the LEFT COLUMN`s — the
transcript is the centre pane, and its payload preview is clipped to one line
regardless. The Steps `tools` seat is not dense at all: `✔ <tool_id>` heads that
tool`s input/output trees on a line of its own, so it simply has room.

Tests mirror bl-ae05: `theme::tests::tool_result_badges_say_the_outcome` asserts
both phrases non-empty and distinct from each other (a shared phrase puts the
load back on the glyph), plus the lore hues; the steps render test asserts the
painted Tools tab contains both phrases, sourced from the mapping rather than
retyped.

DESIGN: §11 audit table row flipped to pass; the density paragraph updated to
the new wording; the badge-seat pattern paragraph gained the inline-branch
reasoning above; §12 theme row now names both badge mappings.
