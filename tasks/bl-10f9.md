The yog half of the containerized-build ruling (bl-223f). The pattern is
DESIGN §10.1 and two repos already landed against it — litany bl-6467 and
thrall bl-3586 — so this ball is the yog-specific decisions, not the design.

**Why it waits on bl-7942 and is not merely sequenced behind it.** The image is
the UI-free server. Containerizing today's binary would ship the eframe/egui/GL
stack into a layer nothing in a server can present — a display dependency in a
headless artifact, which is exactly the coupling the severance exists to
delete. There is no partial version of this worth building first.

Deliver the six §10.1 properties, and answer the four questions that are yog's
alone:

- **The runtime layer is what the server EXECS, and yog execs the most of any
  component.** §16.4/§16.7's self-multiplex means the world's `PATH` head is
  re-exec shims of the yog binary itself, so `bl`, `litany` and `bz` need no
  host binaries — but `git` is still forked directly (`git_env::command`), an
  `$EDITOR` still runs for §9.3's scripted config edits, and the agents the
  server drives run bash tools against whatever the box has. Enumerate it from
  the spawn boundary rather than from memory; that is the one place every child
  is built.
- **The nested world is the mount, and it is not a plain XDG root.** §16.2
  overrides `LITANY_HOME` and `XDG_STATE_HOME` under `$XDG_DATA_HOME/yog/world`
  and hands that env to every child. The image sets the outer variable; what
  mounts is the world, and the README/DESIGN section has to say so plainly
  enough that an operator does not mount the three inner roots separately and
  wonder why the world re-founds itself.
- **No wire material in a layer.** REMOTE §1.4 is that certificates arrive out
  of channel by the operator's hand. `yog wire-certs` and the engine boot mint
  is the operator's tooling on the operator's box; an image that could
  provision its own identity would be the in-channel bootstrap that must never
  exist. Mount the wire directory, ship nothing in it.
- **Ship-inert survives containerization** (bl-37fd, restated in bl-7942): zero
  enrolled thralls means no execution surface, and an image is not a reason to
  pre-enrol a local foot. A container that arrived able to execute would be an
  enrolment nobody performed.

Proof, as the other two did it: the image answers `--version`, and one
meaningful act runs against mounted directories and leaves its product on the
host side of the mount.
