The yog half of the containerized-build ruling (bl-223f). The pattern is
DESIGN §10.1 and two repos landed against it first — litany bl-6467 and thrall
bl-3586 — so this ball was the yog-specific decisions, not the design. The
tooling is thrall's copy adapted (its `ENGINE` variable, and its `case`-table
`leak-rules.sh` shape, which is yog's too); §10.1 is explicit that each repo
owns its own image tooling and that there is no shared build system.

The four answers that are yog's alone:

- **The runtime layer is `git`, `openssl`, `sh` and yog itself.** Enumerated
  from the spawn boundary (`src/git_env.rs`, the crate's one fork), not from
  memory. §16.4/§16.7's self-multiplex is what keeps the list short: the
  world's `PATH` head is re-exec shims of this binary, so `bl`, `litany`, `bz`,
  the two balls plugin seams and `tool-control` need no host binary. `openssl`
  is load-bearing rather than incidental — it is the §1.4 mint the boot
  performs when a box has none, and without it a fresh mount comes up with no
  listener at all. `lsof` is absent: §10's macOS liveness shim is not compiled
  into a Linux binary. **Nothing an agent runs is in the layer**, which is the
  ship-inert posture stated as bytes.
- **`XDG_DATA_HOME` is the ONLY root that mounts**, because it is the world's
  anchor (§16.2). `LITANY_HOME` and `XDG_STATE_HOME` are derived onto
  `<yog-data-root>/world/…`, so an operator who mounted the three separately
  would be fighting the nesting and would watch the world re-found itself. One
  directory: `/state/yog`, holding `world/`, `workspaces/` and `wire/`.
- **No wire material in a layer.** Proven rather than promised: the scan reads
  the authored filesystem, the distro floor (accounted through apk's own
  ledger) and the image config, through the same rule table the commit gate
  uses.
- **Ship-inert survives containerization.** The image pre-enrols nothing.

Proof, as the other two did it: `--version` answers, and one meaningful act
runs against mounted directories and leaves its product on the host side.
