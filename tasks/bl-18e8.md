Operator report 2026-08-21: on sending a message, an ichor banner flashes at
the top of the center pane for ~1s — the orphaned-mail alarm
(`steps_view/orphan.rs:46` "a delivered message has no driver", painted at
`src/shell/workspace.rs:149-156`; the §7.3 no-response wound at :130-137 shares
the shape). The message sends fine; the alarm is a stale-liveness rendering.

## Verified mechanism (2026-08-21)

This is bl-90bf's class, and the grace gate EXISTS — the defect is that its
window under-covers the rising edge:

- The predicate's two halves don't share a clock: the disk half (mail on tail)
  is read fresh at answer time (`steps_view/mod.rs:112-127`), the liveness
  half comes from the last published Snapshot
  (`src/boundary/answer/inspector.rs:81-83`). Delivery happens under the
  driver's own lock, so the instant `messages/NNN-user.md` lands, disk says
  "mail" while the snapshot still says quiescent.
- The grace window is `Cadence::wound_grace()` = cheap_sweep + debounce =
  2.1s default (`src/app/cadence.rs:82-89`), sized as "the catch-up bound
  itself" (DESIGN:3037). But the rising edge is NOT bounded by the cheap
  sweep: `needs_liveness_reprobe` (`src/app/derive/liveness.rs:35-39`) only
  re-probes workspaces that ALREADY hold a Live/InFlight agent — a resting
  agent coming alive is purely fs-event driven. The real chain is inotify →
  50ms bridge → 25ms worker → 100ms debounce → the WHOLE derivation pass
  (which DESIGN concedes cannot finish inside 2s on a real workspace, and
  which publishes once at the end — a full sweep in flight delays it further)
  → 500ms ASK_PERIOD. When that exceeds 2.1s, the excess is a visible red
  flash.
- Aggravator: the send act never schedules the workspace itself —
  `src/app/acts.rs:82-87` marks only the yog-state root dirty for a Message
  act (`project()` is None for it), so the deposit that CREATES the catch-up
  need never requests the catch-up.

## The change

Two complementary fixes; implementer decides the final shape, amending the doc
to match (see below). Prefer both:

1. **Make the send schedule its own catch-up:** on a conversation-origin act
   receipt, mark the act's WORKSPACE dirty (`src/app/acts.rs:82-87`), so the
   deposit that creates the mail-on-tail state also requests the re-derivation
   that will clear it. This shortens the true window instead of papering it.
2. **Size the grace against the real bound:** `Cadence::wound_grace()` must
   cover the rising edge's actual latency (derive-pass duration + ASK_PERIOD
   are named residuals `grace.rs:66-73` does not account for). Widen it from
   the cadence's own terms (e.g. include the pass/full-sweep bound), not a
   magic constant.

Do NOT reach into the pending-echo module to suppress the predicate — a
concurrent ball (bl-78d8) owns `src/app/echo*` and the coupling is worse than
either fix above.

Both banners share the gate (two Grace instances, `src/shell/ram.rs:160-170`);
fix once, both benefit. The ungated Steps-tab row (§11 Altitude 2,
`steps_view/render.rs:145`) stays ungated by design — only the banner is
graced.
