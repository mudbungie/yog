Doc rot that is now public. bl-244f deleted `docs/drive-logs/` and removed the
operator-home carve-out that existed only for it, but two documents still
instruct a reader to write there:

- `docs/QUALITY.md:188` — "6. **Record.** One log per run in `docs/drive-logs/`"
- `docs/STORIES.md:635` — "**Run logs** live in `docs/drive-logs/` — one file
  per real run, quoting the ..."

Following either instruction re-creates the directory whose contents were the
single largest source of operator-home paths in the history sweep (bl-4f96
found eight of its files among the 22 that carried them), and the leak gate's
rule table specifically records that the carve-out is gone:

    There is no per-rule path exemption and no allowlist. There was one — a SKIP
    prefix for `docs/drive-logs/`, whose files were operator-home paths by the
    hundred — and bl-244f burned those logs rather than keep the carve-out they
    justified.

So the instruction now points at a trap: the log a reader writes will be caught
by the gate, or worse, land in a commit that predates their running it.

Decide where a run log goes now — outside the repository is the obvious answer,
since that is what burning them was for — and say so in both places. If the
answer is "nowhere durable", say that instead; a step that records nothing is
better than one that names a deleted directory.
