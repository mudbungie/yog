## Contradiction

A ball-bound yog root spans two Git worlds:

- balls owns the project branch/worktree that recursive close delivers;
- yog names that path only in goal prose and process cwd;
- pinned lernie runs and commits tools in its own agent worktree.

Project edits therefore lack child inheritance, writer isolation, agent-ref provenance, bundle/replay, and lawful attempt comparison.

## Agreed model

Project execution is one recursive delivery graph. Task and subtask differ only by delivery target.

An agent operation has N >= 1 delivery attempts. Each attempt starts from an exact target commit. With N > 1, each alternative attempt is a candidate. Candidate is a policy name, not a new balls verb, task kind, status, or Git primitive.

An attempt may be reworked before delivery, rejected with its target unchanged, or accepted by ordinary source-to-target delivery. Acceptance updates the parent obligation's branch; it does not close that parent. The parent later delivers recursively through ordinary close.

Snapshot identity and mutable checkout are distinct. Attempts may share immutable Git objects and an exact commit. No two write-capable lineages may share a mutable ref, index, or worktree. A checkout may be shared only when mechanically read-only; bash/build-capable agents count as writers until capability enforcement proves otherwise.

Balls bl-a1a4 tracks the native delivery correction: the source owner must incorporate the current target before delivery; delivery gates, squashes, and CAS-advances but never reconciles. Balls bl-4eac tracks the policy-blind non-task attempt capability after this ruling.

## Deliverable

Amend docs/VISION.md and docs/DESIGN.md so one architecture defines:

1. the authoritative project source and target for roots, children, attempts, judges, synthesis, and recursive delivery;
2. a typed target binding introduced by mechanism, inherited without goal parsing, and validated after move/deletion;
3. private ref/index/worktree allocation for every write-capable attempt;
4. how project commits join agent history, project diff, transcript, bundle/replay, crash recovery, and close without duplicate project bytes;
5. one source-to-target contract: readiness, stale-target refusal, source-owned rework, gate, atomic target advance, and later parent close;
6. N >= 1 attempt creation; candidate comparison, selection, rejection, rework, loser retention/cleanup, and derived provenance, without Adopt or a stored winner field;
7. a derived science projection joining frozen inputs, model/config/skills, base/source/target OIDs, response, usage, wall time, project diff, verdict, and accepted/rejected/reworked outcome from existing authorities;
8. bare, path, and ball behavior;
9. every lower-crate implementation task and the exact release/pin sequence.

Preserve the layer law: balls owns project refs, worktree lifecycle, delivery, and safe cleanup; lernie owns agent context/transcript and attempt binding; yog owns N, variants, comparison, accept/reject/rework policy, retention decisions, and presentation. Reject goal parsing, a yog-side project index, duplicate project bytes, and a special candidate delivery path.
