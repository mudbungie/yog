Residual of bl-3d22, which gated the picker but not the failure that already happened.

bl-3d22 stopped `/model <role> <row> <id>` from writing a config whose next step dies at brazen's encoder. A config written BEFORE that gate — or by hand through the raw editors, which are the operator's own authority — still dies, and when it does the §7.3 banner offers Dismiss and nothing else.

The reason is a classifier boundary. `src/config_edit/fault.rs` fires on two markers only:

    const CONFIG_MARKERS: &[&str] = &["provider error (config)", "unknown provider"];

with the doc's own justification: "each token is a phrase brazen or lernie writes for a configuration fault and for nothing else". brazen's tool decline is not one of them. `protocol/claude_code/encode.rs` builds it through a local `reject`, and that helper stamps `ErrorKind::ParseInput`, not `ErrorKind::Config`:

    if !req.tools.is_empty() {
        return Err(reject(
            "claude_code carries no tool declarations; use the `anthropic` row for tools",
        ));
    }

So `looks_config` answers false, `config_remedy` answers None, and a failure whose only remedy IS a config file gets the affordance for a failure with no remedy at all. The same holds for the dialect's other three declines (a tool_choice, a multi-turn transcript, a non-text block) — one family, one classifier gap.

The judgement is the same fact bl-3d22 landed, so this must not become a second table: `ProviderRow::tools_blocked` in `src/config_edit/brazen/providers.rs` is the home, and what is missing is the route from a dead step to it. Attack before committing: is the right signal the failure TEXT (a marker, like the two above — cheap, and consistent with "read the row out of the failure's own words") or the row the step ran on joined against the table (authoritative, but the join is what bl-8e34 had to do and bl-dd7f then avoided)? Prefer the marker if brazen's sentence is stable enough to key on, and note that brazen bl-5053 landing a capability column changes neither answer.

Acceptance: a step that died on a request-shape decline paints the same route to the picker / §9.1 editor an `unknown provider` failure gets, in brazen's verbatim words with one added sentence; the marker set stays narrow enough that an unrelated ParseInput does not claim a config remedy; both directions covered.
