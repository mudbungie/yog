Runtime reproduction on `96d5f4e` with `yog headless` and a real scratch workspace:

1. `yog gesture --ws <workspace> /prepare dir /tmp/yog-sparrow-smoke/repo`
2. Exit 0 returns `kind: prepared` with cwd, goal preface, name, origin, and workspace.
3. `yog gesture --ws <same-workspace> /prompt Create the greeting script and tests`
4. Exit 2: `/prompt: nothing is prepared — /prepare first, then say the goal`.

The help contract presents these as the two terminal steps: `/prepare` seeds the start and `/prompt` fires what it prepared. But each `yog gesture` is a new process; `Context.prepared` is invocation-local, and argv has no way to carry the prepared reply into the next command. The only documented next step can never succeed from a terminal or headless controller.

Make the prepared result composable across invocations without inventing a second start implementation. Add an end-to-end test that runs two actual sugar invocations and observes one detached prompt.
