## Finding

REMOTE §5.7 rules that a credential living on a machine is reached through that machine's foot, and §8.3 that its sign-in is `/login <row>@<client>` from any seat. For a row whose `oauth` block declares no `device` endpoint that door does not open today. Traced, nothing run:

1. `boundary/login.rs` `start` asks the far machine's sign-in catalog; the row carries no `device` column, so `login/runs.rs` `flow_of` picks `Flow::Browser`.
2. The server spawns the `bz` arm with `--login --provider <row>@<client> --browser`; `bz_host/far.rs` posts it as an invocation of the far `bz` entry.
3. The far brazen binds its own IPv4 loopback on an ephemeral port and hands the authorize URL to a browser launcher. On a box with no browser the launcher's spawn fails and the run ends at once with brazen's *could not launch browser*; on a box with one, a browser opens where nobody sits. **The URL is never printed**, so the lane a phone or desktop seat holds shows nothing to act on, and the redirect could only land on the far box's loopback anyway.

So a far browser-only row can be signed in only by a human at that box, with a browser on it. Until then such a row keeps borrowing a sibling tool's credential through an `ambient` block, which brazen never refreshes: it lapses some hours after the owning tool last ran, and every role naming the row fails until somebody runs that tool on the box.

## What is missing

- **brazen** (brazen bl-2764): a flow that prints the authorize URL and takes the code back without a local redirect, spelled in the envelope's allowed flags.
- **here**, once that exists: `flow_of` grows nothing if the catalog can state the flow; the one new thing is how a seat hands the pasted code to the run — most likely a second `login` act carrying it, since a far run's stdin is fixed when it starts. That is a wire question (§3) and wants its own design paragraph in §8.3 before code.

## Not this ball

Keeping the borrowed credential fresh with a timer that runs the owning tool. It is a workaround on one box, not a sign-in, and it is the operator's to weigh.
