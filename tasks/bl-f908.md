The composer box has no way back to something you already said. Codex and
Claude Code both bind ↑ at the top line of the input to *prompt history* —
step back through your own past prompts, ↓ to come forward, past the newest
back to the draft you were typing. yog's box binds neither key (bare ↑/↓ are
the roster walk, and §11's suppression rule already skips them while a text
box holds the keyboard), so the gesture's plane is free.

## The ruling

**↑ on the box's top row steps back through what *you* have said in this
conversation, newest first; ↓ on the bottom row steps forward, and forward
past the newest restores the draft you were typing.**

**The history is derived, never stored.** It is the target's own operator
messages, read from the two seats the composer already reads:

1. the target's **pending** deposits (§5.1 #11, the snapshot's — the very
   rows the queue paints above the box), and
2. the **delivered** transcript's `.md` entries (§5.1 #12),

each filtered to `theme::message_role(...) == Role::User` — the one role
derivation, not a second reading of the bytes — and taken newest-first
(pending ahead of delivered, each in reverse order). No session log, no
`ui.json` key, no RAM list of "things I sent". A restart pages the same
history, because the history *is* the conversation.

A **new conversation** has no chat and therefore no history: the general
path at zero items, no flag and no special case. (Empty history ⇒ ↑ recalls
nothing ⇒ egui moves the caret, exactly as today.)

## Why the top-row gate is the whole rule

The gate is on **entry and continuation alike**, so there is no browse mode
and no mode flag. After a recall the caret lands at the end of the recalled
text:

- a one-row prompt ⇒ caret is on the top row **and** the bottom row, so ↑
  pages further back and ↓ pages forward — one key per step, as in codex;
- a multi-row prompt ⇒ ↑ walks the caret up through the recalled text and
  pages only once it is at the top, which is readline's own behaviour and
  keeps the arrows usable *inside* a recalled prompt.

"Top row" is the **visual** row (`TextEditOutput.cursor_range.primary.
rcursor.row == 0`), not the logical line, so a long wrapped draft does not
swallow the gesture.

## State: two fields, and the exit is derived

    struct Recall { stash: Option<String>, depth: usize }

`depth` 0 is the live draft; `depth` n is the nth-newest prompt. Stepping
off 0 stashes the draft; stepping back onto 0 restores it.

**Leaving the recall is a derivation, not an event.** Each frame: if
`depth > 0` and the draft is no longer the entry at that depth, the operator
edited it — reset. That one check covers every exit at once: typing over a
recalled prompt (it becomes your draft, and the stash is rightly discarded),
sending (the draft clears), switching targets (a different draft), and the
history shrinking under a landed send. No reset call at any call site.

## Placement

- `src/composer/recall.rs` (new, pure + tested): `prompts(pending,
  transcript) -> Vec<String>` and `Recall::{step, settle}`.
- `ComposerRam` gains `recall: Recall` and the last painted caret row /
  row count (a galley fact, known only at paint time, so the gesture reads
  the previous frame's — one event per frame, so it cannot be stale).
- `src/shell/inbox_queue.rs` consumes ↑/↓ **before** adding the box (so the
  widget does not also move the caret) and writes the recalled text through
  the same `Drafts` seat, then parks the caret at the end.
- The transcript comes through the existing per-snapshot memo
  (`InspectorState::tx_memo`, §7.2 `SnapMemo`) — the inspector builds it on
  every tab already since bl-1802, so the composer asking first costs one
  pointer compare, never a second `messages/` read.

## Docs

DESIGN §11 inbox-composer gains the gesture beside the Enter/Shift+Enter key
contract, and the §11 binding table's ↑/↓ row notes that the composer's box
claims them at its edges (the suppression rule is unchanged — these are the
box's own keys, like Enter, not table entries).

## Acceptance

`shell/acceptance/inbox_composer.rs` drives it: type a draft, ↑ recalls the
newest operator message, ↑ again the one before, ↓↓ returns the draft
verbatim; a wrapped draft's ↑ moves the caret instead of recalling; and an
edit mid-recall keeps the edit and forgets the stash.
