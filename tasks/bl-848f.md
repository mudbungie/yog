Filed by Alkaloid 2026-08-11 from Ingot's finding while delivering bl-a48b.

## The gap

bl-a48b made `models.yaml`'s declared `context_window` the denominator of the per-conversation context-fullness figure. That was the right call — brazen 0.0.5 carries `Model.context_window`, but only for providers that serve one on their list GET (Google does; Anthropic, OpenAI and Ollama serve none, which is brazen's own empty-set rule), so the declared value is the single authority and reading brazen's cache *as well* would be two representations of one fact.

But the **write path** does not use what it already has. The §9.4 picker writes `context_window: 200_000` as a flat default **even when the roster it just read carries the provider's real number**. So for Google models the operator gets a fabricated 200k denominator sitting next to a true figure brazen supplied in the same request, and the context percentage is wrong by whatever the real window is.

## Scope

Seed `context_window` from `Model.context_window` **at the moment the picker writes the row**, where the provider served one; keep `200_000` as the fallback where it did not.

This is a write-path change only. **Do not** make the read path consult brazen — bl-a48b's ruling stands: the declared value in `models.yaml` remains the one authority the fullness figure reads. What changes is that the declaration starts out true instead of guessed. The operator can still edit it in the §9.5 form, and an edited value must win.

## Why it matters more than the number

A fabricated default that *looks* declared is indistinguishable from a considered one. The operator has no way to tell 'nobody knew, so we guessed 200k' from 'this model really is 200k' — the same class of defect as bl-1765, where a workspace-wide total rendered identically to a per-ball figure. If seeding from the roster is impossible for some provider, the honest fallback is worth thinking about rather than defaulting silently.
