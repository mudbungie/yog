Merge 25 of 28 integration-test files (tests/*.rs) into shared test binaries
under tests/integration/, cutting cargo-tarpaulin per-binary launch overhead
(measured ~1.8s/binary) and duplicate dependency-tree linkage (~175MB/binary).

Excluded (stay standalone -- each has a documented, verified invariant: process-
global env::set_var/set_current_dir is `unsafe` in edition 2024 and sound only
with no peer thread reading it while mutated; each module doc states "one
#[test] per binary, deliberately"):
  - tests/multiplex_bl.rs   (env::set_var + set_current_dir)
  - tests/multiplex_lernie.rs (env::set_var + pgid-leadership assumption)
  - tests/git_env_scrub.rs  (env::set_var, explicitly cross-references multiplex_bl.rs)

Plan (reviewed by a fable subagent, corrections folded in):
1. Move the other 25 tests/*.rs files (+ tests/support/) into tests/integration/,
   with one root tests/integration/main.rs declaring `mod support;` once and
   `mod <file>;` per test file. (Cargo has no autotests=false / [[test]]
   override, so files must physically leave the tests/ top level or they'd
   ALSO keep compiling standalone -- #[path] alone does not stop that.)
2. Fix tests/sigterm_durability.rs's self-relaunch filter: bare
   "ui_json_gesture_then_block" --exact breaks once the test is module-
   qualified; must become "sigterm_durability::ui_json_gesture_then_block".
3. Add a SPAWN_LOCK-equivalent Mutex<()> in tests/support/mod.rs (mirrors the
   existing pub(crate) one in src/test_support.rs, which integration tests
   can't reach since they're a separate crate) and gate
   tests/support/recorder.rs's write-then-exec sites on it. Today each
   integration binary runs 1-2 tests so the ETXTBSY fork race never surfaces;
   merged, ~25 tests run thread-parallel under `cargo test`'s default, in one
   process, several forking freshly-written scripts.
4. make test and make coverage must both pass clean (100% floor unchanged;
   tarpaulin.toml forces --test-threads=1 already, so coverage runs are
   unaffected by point 3 either way -- only make test's default parallel run
   needs the lock).

Expected: 30 test binaries -> ~6. ~24 fewer tarpaulin launches (~43s off a
measured 127.6s solo coverage run), ~4GB less duplicated linkage per build
generation.
