Repro: new-conversation form, set work directory to /nonexistent/uat-dir, type a goal, Enter. The failure surfaces (good: red rows, draft survives, chip counts 1 failed) but the message reads 'failed to spawn <path-to-yog-binary>: No such file or directory (os error 2)' — ENOENT from an invalid cwd is reported against the program path by std::process, and yog forwards that misattribution. The operator typed a bad directory and is told their binary is missing. Fix twofold: (1) validate the work-directory field at the form — it is a text field like the workspace name; a path that is not a directory flags red before Enter fires anything; (2) at spawn, when the requested cwd does not exist, say so: 'work directory does not exist: <path>'. Also check placement: the red failure rows currently render inside the balls section fold, which was not the originating surface (the composer was). Acceptance: bad dir → pre-flight red flag on the field; forced spawn failure with a bad cwd → error names the directory, not the binary.
