Found while driving bl-e349's acceptance beats.

## Observed

With a §8.2 entry's workspace focused — a roster row present, a tab painted and
selected, the name resolving over the union — the window's centre paints the
**first-launch bootstrap pane**. Verbatim, off the paint layer:

    new
    cobalt
    Workspaces:
    ...
    no workspace yet — say the word
    ...
    yog
    the key and the gate
    will be named CourtyardRooftop
    start a conversation:
    say what you want done

The tab bar says `cobalt` is there and selected. The centre says there is no
workspace at all.

## The mechanism — bl-e349's conflation, one layer down

`shell::workspace::center` hands over to `shell::bootstrap` exactly when
`AppModel::focused_workspace()` is `None`. REMOTE §8.2 rules that answer for a
workspace held at an entry on purpose: *"A remote name still has no local PATH,
on purpose. `Snapshot::ws_path` resolves the painted enumeration, whose members
are directories on this box; a workspace hosted elsewhere has none, so
`focused_workspace` answers `None` for one."*

So `None` means two different things and the centre reads them as one:

- **nothing is focused** — the empty world, where the bootstrap pane is right;
- **the focus is not on this box** — where it is a lie, and the pane it paints
  invites the operator to start a conversation in a world it has just told them
  does not exist.

That is precisely the conflation bl-e349 closed for the start's *address*
(`start_workspace` now reads the focused NAME, and `AppModel::start_path`
answers `None` only where a path genuinely does not exist here). The paint side
was left standing because bl-e349's subject was the act.

## What correct looks like

The predicate the centre wants is **"is anything focused"**, which is
`focused_ws_name().is_some()` — a name, not a path. A focused workspace whose
content is a name-addressed wire read (conversations, transcript, marks, balls)
already works over the union unchanged (§8.2), so the ordinary centre should
render for an entry's workspace like any other; what should be withheld is only
the surfaces whose subject is a file on THIS box (config editing, the ball
store, a spawn's working directory) — §8.2's own list, and withholding those is
correct rather than pending.

Sequenced beside bl-f29c (an unreachable entry paints on its own rows, never the
shell) — same surface, different fact: that one is about a channel that cannot
be dialled, this one about one that answers fine.

Acceptance: with an entry's workspace focused, the centre paints that
workspace's conversation view; the string `no workspace yet` appears nowhere.
The fixture that reaches this state exists — `World::attach_entry` plus
`fixture/entry.rs`, landed with bl-e349, and `acceptance::remote_start` is the
drive that found it.
