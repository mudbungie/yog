From the 2026-07-27 UX-testing session (the operator):

> the prompt, "message the selected conversation" should be "message <session name>"

## Today

`src/shell/input_bar.rs:77-80` — the hint text inside the box:

    .hint_text(match target {
        Some(_) => "message the selected conversation",
        None => "start a conversation",
    })

and `input_bar.rs:55-56`, the target line above it:

    if let Some(agent) = target.as_deref() {
        ui.weak(format!("→ message {agent}"));

So the box says a generic phrase, and the line above it says the raw agent id —
`→ message <agent-id>`. Neither tells the operator which
conversation they are about to speak into in terms they can recognise.

## Blocked on bl-68d9

Deliberately gated. the operator said "session name", and yog has no such thing: a
conversation is identified by its root agent id (a timestamp-hash) and rendered
in the §11 list by `ConvRow::preview`, its first line. bl-68d9 is the DESIGN
task deciding whether a conversation gets a name of its own and what it is.
Implementing an interim here would be work thrown away when that lands, and
~/AGENTS.md says build less.

## When unblocked

Use whatever bl-68d9 decided as the conversation's display identity, in both
places — the hint text AND the `→ message <x>` target line, which are two
spellings of the same fact and must not disagree. Check `ConvRow` (`src/nav/convs`)
for the field; the §11 conversation list already faces the same "what do I call
this row" problem and falls back to `row.root_id` when the preview is empty
(`src/shell/navigator.rs:223-227`) — whatever the answer is, that fallback and
this label should come from one function, not two.
