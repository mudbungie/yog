From the 2026-07-27 UX-testing session (the operator):

> the prompt, "message the selected conversation" should be "message <session name>"

## Today

`src/shell/input_bar.rs:77-80` — the hint text inside the box:

    .hint_text(match target {
        Some(_) => "message the selected conversation",
        None => "start a conversation",
    })

and `input_bar.rs:55-56`, the target line above it:

    if let Some(agent) = target.as_deref() {
        ui.weak(format!("→ message {agent}"));

So the box says a generic phrase, and the line above it says the raw agent id —
`→ message <agent-id>`. Neither tells the operator which
conversation they are about to speak into in terms they can recognise.

## The bl-68d9 answer (RESOLVED — DESIGN §3.3/§11 as amended)

A conversation gets NO minted name. Its display name is derived: the first
payload line of its goal (harness workspace line stripped), root id fallback —
one function, built by bl-1b5a (this ball now needs it). DESIGN §11:

> **The composer names its message target by the conversation's display
> name** (bl-2f30): the `→ message <display name>` target line and the box's
> hint are two spellings of one fact, both from the §3.3 one function — never
> the raw agent id alone (the id survives weak in the center header).

## When unblocked (bl-1b5a delivered)

Use bl-1b5a's display-name function in both places — the `→ message <x>`
target line AND the hint text (e.g. `message <display name>`). Note the
selection can be a CHILD agent (`selected_branch` is the selected member, not
the root): resolve the conversation via `nav::convs::root_of` and display
*its* name; the message still targets the selected agent. Acceptance: with a
conversation selected whose goal payload starts "fix the parser", the target
line reads `→ message fix the parser` (id nowhere in the composer), and the
hint matches; with none selected the hint stays "start a conversation".
