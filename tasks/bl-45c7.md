Filed by Alkaloid 2026-08-11 from Ferrule's bl-3aa1 finding. **This is a repeat, and the repeat is the point.**

## The invariant and its hole

An acceptance scan asserts *"no seat formats an agent id as a display name."* It works by enumerating **field names** — it knew `agent_id` and `root_id`.

An inbox deposit carries the very same fact under `sender`. The scan was **silent**, and the defect shipped: bl-3aa1's witness 2 was a seat painting a raw agent id, sitting in plain sight under an invariant that existed precisely to forbid it.

## Why this ball exists rather than just the patch

bl-63a1 already recorded this exact lesson, verbatim:

> the first scan forbade only `agent_id`, so a seat painting the same fact under its other name would have passed

**The lesson was written down and it still recurred.** That is the evidence that documenting the gap is not a fix. A scan whose strength is a hand-maintained vocabulary decays every time anyone names the same fact differently, and nothing fails when it does — the scan simply goes quiet. It is [[vacuous]] by omission rather than by construction, which is the hardest shape to see: it *is* passing, on the subset it happens to know.

Ferrule patched the instance (added `sender`, and **verified the scan now bites** by planting `ui.label(deposit.sender)` and watching it fail). That is correct and sufficient for bl-3aa1. This ball is the structural question that patch does not answer.

## The ask

**Make the scan derive from the fact, not from a list of names.** An agent id has a shape; a seat painting a string of that shape as a display name is the defect, whatever the field is called. Deriving from the value removes the maintenance burden and closes the class instead of the instance — single source of truth applied to an invariant rather than to data.

Investigate:

1. Can the scan detect an id-shaped value regardless of field name? (Prefer this.)
2. If value-shape detection is genuinely infeasible, can the field list be *generated* from the boundary types that carry an agent id, so adding a field to a type extends the scan automatically?
3. Failing both, state plainly why the vocabulary must stay hand-maintained, and put the enumeration and the types beside each other so a reviewer can see them diverge.

**Whatever lands must be proved to bite** by planting a violation under a field name the author did not think of.

## Scope note

Audit for sibling scans with the same shape — any acceptance check keyed on a hand-listed set of names has this failure mode. Related: bl-36c3 (paint-layer vacuity), bl-f16e (drive-beat vacuity). Verify all cited symbols at HEAD; ball bodies drift.
