**Filed as ONE ball on purpose.** These are five claims about one surface — the
§11 Altitude-2 transcript's fold/tone/wrap semantics — and every one of them
lands in `src/transcript/render.rs` or `src/transcript/rows/project/build.rs`.
Split into five they would collide on every merge.

## The ruling to build to

**Anything hidden is hidden behind a triangle.** Nothing on this surface may be
cut, capped, clipped or elided without a disclosure control that reveals it.
That is the invariant; the five findings below are its current violations.

---

## Finding 1 — content is hidden with no affordance, two ways

**(a) The 160-char cap.** `src/transcript/rows/project/build.rs`:

    const PREVIEW_CAP: usize = 160;
    …
    fn split(payload: &str) -> (String, String) {
        let first = payload.lines().next().unwrap_or_default();
        let clipped = first.chars().count() > PREVIEW_CAP;
        let preview = if clipped {
            let head: String = first.chars().take(PREVIEW_CAP).collect();
            format!("{head}…")

This one at least sets `body`, so a toggle exists. It is the *lesser* half.

**(b) The silent clip, which has no affordance at all.** The transcript sets no
wrap mode, and `src/shell/row.rs` states what that means, verbatim:

    /// It was written into the side panel's own body and read as if it were a
    /// window rule; it is not, and egui's default everywhere else is `Extend`.
    /// So the top bar, the centre and the activity accessory laid every
    /// horizontal label at its natural width and the panel's clip rect sliced
    /// it mid-glyph — with **no ellipsis**, because a galley that was never
    /// asked to truncate has nothing to mark.

bl-5410 fixed the top bar, the centre chrome and the activity accessory. **The
transcript was not reached** — `grep wrap_mode src/transcript/` returns nothing.
So both `ui.weak(&row.preview)` and the expanded `ui.label(&row.body)` lay at
natural width and get sliced mid-glyph by the pane's clip rect, with no mark.

This is the same class as the standing lesson that a paint probe reading
`Galley::text()` sees the INPUT string and can never observe elision — a test
that asserts the row's text is not evidence the operator can read it.

## Finding 2 — the expanded body is not shown in full

Same root cause as 1(b). `render_row`:

    if !inline {
        ui.label(&row.body);
    }

In an `Extend` centre a long line runs past the pane edge and is clipped. So
opening the fold does not deliver what the fold promised. **This is the finding
that makes the whole affordance a lie**, and it should be fixed first: a
triangle that reveals a still-cut payload is worse than no triangle.

## Finding 3 — the fade is inverted

`render_row`, verbatim:

        if inline && !row.preview.is_empty() {
            ui.weak(&row.preview);
        }

`ui.weak` is unconditional. A row with **nothing to fold** — a short payload
shown whole, which is the complete content — paints exactly as faded as a
one-line preview standing in for hidden text. The operator's reading is right:
faded reads as "there is more behind this", so the surface says the opposite of
the truth precisely where it is telling the whole truth.

Invert it: **complete content reads as complete; an abridged preview is what
looks abridged.** Note the row already knows which it is with no new field —
`row.body.is_empty()` *is* the fact (`split`'s doc: *"the empty body is the
fact"*), and `render_row` already computes `inline` from it.

Do not mint a parallel palette. `theme::tone_solidity` exists (bl-915e) for
exactly "display-only, not yet a statement" and `Tone` is the vocabulary; decide
whether this is a tone or a solidity and say which.

## Finding 4 — model output should not arrive folded

`AutoExpand::default()` already reads:

    responses: true,
    others: false,

so on the face of it model text *is* expanded by default, and the operator is
seeing something else. **Find out what before changing the knob.** Two leads,
neither confirmed:

- The turn rollup. `rows/turns.rs::group`/`push_turn` rolls a
  boundary-delimited segment into an aggregate row whose `Fold::Steps` reveals
  the step rows after it. If the model's answer is inside a rollup governed by
  `auto.others` (false), it arrives shut regardless of the `responses` knob.
- A persisted knob. The §4.1 knobs are durable; a stored `responses: false`
  would outrank the default. Check what is actually on disk before blaming code.

Whatever the cause, the delivered behaviour is the ruling: **direct model output
arrives open.** If the fix is that the rollup must not swallow the answer, say
so in DESIGN rather than flipping a default that was already right.

## Finding 5 — the pre-commit render is unverified

The operator: *"I'm not sure the same display semantics are working in the
pre-commit render."* The live tail is now two rows (`thinking:` then `live:`)
projected per frame by `Transcript::with_live(&Stream)` (bl-54f7, `0ef853e`),
each keeping its committed counterpart's `RowClass` *specifically* so the §11
fold knobs mean one thing on either side of the commit.

That intent is stated; it is not asserted. **Verify it and make it a test**: for
the same payload, the live rows and the committed rows must agree on fold
availability, expansion state, tone/fade and wrap. A payload that reads one way
while streaming and another way one frame after it commits is the defect,
whichever way each one is.

## Constraints

- `Tone::Live` auto-expands the streaming rows (`in_flight` in
  `rows.rs::expanded_for`). Whatever you change must keep that true — the live
  answer is the show.
- The fold vocabulary has one home (jsonview's `GLYPH_COLLAPSED` /
  `GLYPH_EXPANDED`, and `NO_FOLD_MARK` for the leaf). Do not mint a second.
- §11 glyph doctrine: a glyph is never a fact's only carrier. The existing
  toggle hover states what the fold holds; keep that discipline for anything new.
- The row is a pure projection with nothing stored (`with_size`'s doc: *"no
  field, no cache, nothing stored"*). Keep it derived.
- Wrapping a prose block in the centre is explicitly allowed — `src/shell/row.rs`
  says *"a seat that must not truncate (a wrapped prose block) can still say so
  locally"*. That is the licence for the transcript to set `Wrap` on itself; take
  it deliberately and record it, do not set an ambient default.

## Acceptance

The standing hazard on this surface is a test that reads the input string and
therefore cannot see elision. Assert against the **laid galley** — what the
operator can actually read — not `Row::preview`/`Row::body`.

At minimum, and at more than one window size (this surface has broken at
420x320 and 800x500 twice):

1. A long single-line model payload, expanded: every character is reachable —
   nothing is clipped by the pane edge.
2. A payload with no body: not faded.
3. A payload with a body, contracted: faded, and a triangle present.
4. No row anywhere paints text the operator cannot reach, with no toggle beside
   it.
5. The same payload live and committed produce the same fold/expansion/tone.

Prove each bites — neuter the fix and show it red, as the last five workers did.
