Top-level help advertises `yog bz --login` as the sign-in path, and DESIGN §8.5 says login already has that headless spelling. DESIGN §16.2 simultaneously says a bare shell or `yog env`/`yog exec` has only the world, never a workspace wall.

Runtime confirms the contradiction on `96d5f4e`: `yog bz --login ...`, `yog bz --version`, and `yog bz --help` outside an agent all exit 64 with `no workspace in this environment`. There is no bz `--workspace` flag, hatch that exports `YOG_WALL`, or boundary Login action. The GUI failure fallback also paints `bz --login --provider <row> --browser` as a command to run by hand, but that command fails in an ordinary shell for the same reason.

Provide one supported workspace-bound sign-in spelling and make the GUI call and fallback derive from it. Preserve the no-wall refusal so credentials never fall back ambiently. Add a real CLI test proving credentials land only in the named wall.
