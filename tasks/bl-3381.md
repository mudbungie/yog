## Clock design (updated 2026-08-01)

1. **DECIDED — cadence lives in yog** (operator: *"yeah, I'd do it in yog"*), not in the workspace's governing config commit. yog stores per-role cadences in its own persisted settings and runs the timers; lernie is untouched. Consequence accepted with the decision: the schedule is a property of the yog install, so a second machine or fresh install starts from cadence defaults. Cadence settings surface in the overhauled config pane (bl-a1c2) as real controls, not file text.
2. **Open, recommendation standing — watchdog vs reactor per role.** Cron fires blind at ≥2 model calls per cycle even when idle. Recommendation: per-role choice, declared alongside the cadence — sensor reactive (deposit only when its watched channel changed since last wake; yog already observes the filesystem), shepherd unconditional (a watchdog must be able to notice absence).
3. **Open, recommendation standing — overdue surfacing.** The fleet ticks only while yog runs. Recommendation: accept that as the operating model AND render it — on launch/attach, compute per-watcher 'N cycles overdue' from last-wake vs cadence. No second clock outside yog; two clocks over one fleet re-creates the drift problem this decision removed.
4. **Rendering** last-wake/next-wake is native yog state — no cross-harness derivation.
