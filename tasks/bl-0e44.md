Found by the 2026-08-07 re-baseline drive (bl-c63e), docs/drive-logs/2026-08-07-ladder-rebaseline.md. Reproduced on two runs of `scripts/drive/stories.sh run-s7` against release `aafa438`, on a box at load average 4-15.

**This is the only red in that drive that is load-shaped.** It is a harness robustness defect, not a yog defect — yog did the right thing five times.

Beat: `S4-T4 uncoloured id: stamped conversation started`, `scripts/drive/beats_s6.sh:101`.

    until_landed phantom agents_are $((before + 1))

    S4-T4 uncoloured id: stamped conversation started FAIL — no new agent
    S4-T4 uncoloured id: goal.md carries the unknown stamp PASS   <-- same evidence, opposite verdict

## The mechanism

`until_landed` fires the gesture, waits ~8s for the predicate, and **re-fires up to five times**. `phantom` starts a WHOLE NEW CONVERSATION each time. Under load the detached `lernie prompt` took longer than the 8s window to materialize its agent dir, so the loop fired again — and once two conversations are in flight the count steps `before+2`, skipping the `before+1` the predicate is pinned to. The predicate can then never be true again, so all five retries burn and the beat reports `no new agent` about a gesture that worked every time.

## On-disk proof

The world holds SEVEN agent dirs where the beat wanted three — one root, its laid forensic child, and FIVE phantoms, ~11s apart:

    <agent-id>
    <agent-id>-<agent-id>
    <agent-id>
    <agent-id>
    <agent-id>
    <agent-id>
    <agent-id>

and FIVE `goal.md` files carrying the `bl-9999` stamp. The very next beat, `S4-T4 uncoloured id: goal.md carries the unknown stamp`, PASSED on that same evidence. Only the counting was wrong.

## The general defect

`agents_are` is the harness s ONE equality predicate:

    agents_are() { [ "$(agent_count)" = "$1" ]; }

Every other `until_landed` predicate is monotone — `verb_ge` (a `>=`) or a set-membership test — and a monotone predicate survives a retry by construction. Pairing an equality with a retry loop that ADDS to the quantity being counted is self-defeating: the retry destroys the very condition it is waiting for.

Note `until_landed` s own comment already states the invariant this breaks: "Every gesture passed here is a no-op when it misses, and the predicate is re-read before each retry, so a landed gesture never re-fires." `phantom` is NOT a no-op when it misses — it starts a conversation — so it violates the contract `until_landed` documents for its argument.

## Repair, and the wider sweep

Make the predicate monotone (`agent_count >= before+1`), which is what the beat actually means: at least one new conversation started. Then audit every `until_landed` call site for a gesture that is not a no-op on a miss — `run()` in stories.sh uses `until_landed prompt_existing agents_are $((agents_before + 1))` for S1 prompt-existing, which is the same equality with the same non-idempotent gesture and passed here only because the box was quieter at that moment. It is the same latent bug.
