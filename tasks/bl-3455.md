REMOTE §5.2's clients tool has three ops — list, get, load — and the loaded set is a durable per-agent document the injection re-declares at every assembly. There is no subtraction: an agent that loads a host's tools, finishes with that box, and moves on carries those definitions in its prefix for the rest of the conversation. Loading is already selective (load {client, tools}), so the accumulation is not a loading-model defect — it is the missing symmetric act. Add a fourth op, unload {client, tools} (tools optional: absent means the client's whole loaded set), removing entries from the same document; the next assembly re-declares without them, one paid prefix rebuild at a moment the agent chose, exactly as load's own settlement (bl-c907) reads. Refusals in band as the other ops: an unload naming a tool the document does not hold refuses whole, mirroring load's whole-or-not-at-all rule, so the model's belief about its own surface never desyncs in either direction. Amend §5.2's op enum and the document semantics in the same change.
