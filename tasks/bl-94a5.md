Round 2, lane comparator. Steal-list item 3 of 3: the APPROVAL PROMPT.

## What the suite has

`/answer pass | hold | refuse`, and it is already better than every comparator in one respect — the help states why:

    The answer is scoped to the exact call that is held, which is read from
    the conversation's own hold mark, so nothing is typed and nothing can be
    spent by a different call.

Verified live this round: with the floor standing, a `bash` call parked, and

    yog gesture --ws w --agent A '/answer refuse'
      {"advanced":true,"kind":"answered","ok":true,"tool":"bash",
       "tool_use":"call_Lqep…","verdict":"refuse"}

The verdict names the call it settled. That is the part to keep.

## What is missing: the SCOPE of the trust

Every comparator's approval prompt offers a scope and the suite offers none, so an operator holding a conversation answers the same question for every call of a kind they already decided about.

hermes-agent 0.15.2, `cli.py:11345-11350`, under the title `"⚠️  Dangerous Command"`:

    "once":    "Allow once"
    "session": "Allow for this session"
    "always":  "Add to permanent allowlist"
    "deny":    "Deny"
    "view":    "Show full command"

with two refinements worth as much as the list: `view` appears only when the command exceeds 70 characters, and `always` is **withheld entirely** when the security scanner raised a content-level finding (`tools/approval.py:1377`) — the permanent option is suppressed exactly where permanence is inappropriate.

codex says the same thing in prose, and its strings name the mechanism:

    Allow Codex to run `…`
    codex to always run commands that start with
    every time this session
    persisted Codex network access to

— i.e. the grant is BY PREFIX and the prompt says so.

## And: the denial is written TO THE MODEL

hermes, `tools/approval.py:1402-1410`, the text a denied call returns as its result:

    BLOCKED: User denied this command. The user has NOT consented to this
    action. Do NOT retry this command, do NOT rephrase it, and do NOT attempt
    the same outcome via a different command. Stop the current workflow and
    wait for the user to respond before taking any further destructive or
    irreversible action.

Three loopholes closed in one paragraph — retry, rephrase, and reach the same outcome another way. What the suite returns for a `refuse` today is not stated in the gesture's help at all, so the model's next act after a refusal is undefined by the surface.

## Proposal

1. **`/answer` takes a scope**, and only the scopes the boundary can actually enforce. `once` is today's behaviour and stays the default. `session` is the conversation. Anything permanent belongs in the control's own rules and not in an answer — so the third rung is not "always" but a named remedy the reply prints, pointing at the rule table.
2. **The scope is refused where permanence is wrong**, on the same principle: a call the control classified as loss or secret takes `once` only. That is the existing floor answering a new question, not a new floor.
3. **A refusal's tool result is stated**, in the gesture's help and in the bytes the model receives, with the three loopholes named.

## Proposed rendering for lernie

`lernie answer <workspace> <agent> <verdict>` today takes a bare word. Held work reaches the seat as `held: bash (call_x) — <reason>` (`src/render/walls.rs::parked`). The prompt around it:

    holding  bash   in <workspace> · <conversation>
      $ rm -rf ./build && make clean
      classified: loss — the control holds anything that destroys work

      lernie answer <ws> <agent> pass            run this call
      lernie answer <ws> <agent> pass --session  and every bash like it, this conversation
      lernie answer <ws> <agent> refuse          decline it; the model is told not to retry
      lernie answer <ws> <agent> hold            leave it parked

- The command is shown whole, wrapped, before any option — hermes' `view` rung dissolves into always printing it.
- Each option's line says what it TRUSTS, not what it types.
- `--session` is absent from the list when the classification forbids it, with one line saying why, rather than offered and then refused.
